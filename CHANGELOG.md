# Changelog

All notable changes to Fenolite are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/) (pre-1.0: minor versions may break).

## [Unreleased]

### Added

- `fenolite check` marks every DRC type whose count reached the limit of KiCad's report (499 entries of `clearance` and `unconnected_items`, 199 of any other type): `summary.limits` of the stage `drc.kicad` and one `check.report-limit` warning per type; such a count is a lower bound. Status and exit code do not change (c0141). A reply of a board under every limit gains `"limits": []`; `null` says that nothing is known. The limits are measured on an authored bench with `kicad-cli` 10.0.6; the 9.0.9 counts of 2026-10-05 wait for their recorded probes.
- **Footprints from the built-in catalog and from `dsl.Footprint` now carry `Reference` and `Value` on the board and in the project library, so a catalog-only board passes `check`. Projects built before gain the two properties on their next build: this is the first change of KiCad bytes since 0.2.0, and only for these footprints.** Altium projects do not change. (c0077) The two fields are generated 1 mm above (`Reference`, `F.SilkS`) and below (`Value`, `F.Fab`) the footprint's extent box, and `Part.field` moves or hides them. **A library footprint that lacks one of the two now gets it on the board too, with the new info `build.field-added`: a `Part.field` request for such a field, which ended in `FEN-3004`, now builds.** **`fenolite build --target altium` of a design that names catalog symbols or footprints and declares script copper no longer stops with `FEN-3001`**: the KiCad build that resolves the copper takes the catalog's definitions too. Verified on `kicad-cli` 10.0.6 (`H-K-FP-FIELDS`); the 9.0.9 run is left to CI.
- **New command `fenolite fetch freerouting`** (c0078): downloads the pinned Freerouting jar from its publisher after `--confirm`, checks its size and SHA-256 and installs it in the user's tools folder, where `route --router freerouting` finds it; no other command downloads anything (ADR-0007). `--dry-run` shows the file, its size, its digest, its address and its licence (GPL-3.0) and makes no request; `--from FILE` installs a copy you already have, with the same check; `--dir DIR` chooses another folder. The tools folder is `FENOLITE_TOOLS_DIR`, else the cache folder of the platform (`~/Library/Caches/fenolite/tools`, `%LOCALAPPDATA%\fenolite\tools`, `~/.cache/fenolite/tools`). The command installs no Java: Freerouting still needs Java 25 or newer. **Changed messages:** without a jar, `fenolite route --router freerouting` still exits 6 with `FEN-6001`, and its message and hint now name `fenolite fetch freerouting --confirm`; the `freerouting` entry of `doctor`'s `result.routers` gains `source` (`argument`, `env`, `fetched` or `null`). Two new error codes: `FEN-6003` (exit 6, retryable: the download failed) and `FEN-3006` (exit 3: the bytes do not have the pinned size or SHA-256; nothing is written). `--router-path` and `FENOLITE_FREEROUTING_JAR` work as before and win over the tools folder.
- `design.board(copper=…)` takes 6 and 8 copper layers (c0100): zones, planes and script copper on every inner layer, the KiCad layer table KiCad itself writes, proved through fill, DRC and export on KiCad 10 (the KiCad 9 half of the proof runs on two committed filled boards and waits for the CI run); `Design.copper_layers`; a rebuild names the board's count when it differs, and `layout.copper-mismatch` hints at `copper=<the board's count>` and `--discard-layout`; the hint of `build.plane-not-lowered` names the `design.zone(…)` call instead of a step in KiCad; `--target altium` writes the six- and eight-layer document with the stack of c0085. `fenolite.dsl.design.INNER_LAYERS` and `layers.INNER_ROWS` are replaced by `inner_layers(copper)` and `inner_rows(copper)`.
- `fenolite route` selects the nets that still have open connections, so a second run and script copper can share a net; `routed` and `unrouted` now come from the board after the merge, copper of nets left open is kept, and `--require-complete` exits 5 and writes nothing when a selected net stays open (c0108). Tracks, arcs and vias carry `locked`, read from and written to KiCad boards; `--rip` keeps locked and script copper; `Design.track`, `via` and `stitch` take `locked=`. `fenolite net` gives `islands` and `open` per net. `routing.select.unrouted` takes `open_nets`. An Altium build writes the lock of a locked track, arc or via, or warns with `altium.not-lowered`; the Altium import reads it. **Releases 0.2.x and 0.3.x cannot read a model document that carries the key `locked` on a track, an arc or a via.**
- **`fenolite export` writes IPC-2581, ODB++, STEP, board PDF and DXF per layer, and the schematic PDF** (c0116; `--ipc2581`, `--odb`, `--step`, `--pdf`, `--dxf`, `--sch-pdf`); `--all` still selects the four fabrication kinds, and a preset changes no document kind. A STEP gets the 3D models that Fenolite locates, reported with their source and SHA-256 in `result.models`; a missing model is a warning. A schematic whose hierarchy names a sheet that cannot be given to the run is refused (`export.sheet-missing`), and a board that does not fit its page gives the warning `export.page-too-small`. `result.repeat` says which hashes compare between exports. New command `fenolite models` lists the models of a board and copies them into `3dmodels/` with `--vendor`; `tools/kicad_libs_fetch.py --models` fetches single files of the official 3D library (no fetch was run yet). `LibraryResolver.missing_models` now also finds a model in the project's `3dmodels/` folder, in the install and in a fetched cache, so it can report fewer warnings than before. The document kinds and `fenolite models` carry `INFERRED`: their probes are recorded for `kicad-cli` 10.0.6 and not yet for 9.0.9.
- Board stack-ups (c0101): `read_board` fills `Board.stackup` from a KiCad stack-up that KiCad uses, created boards whose model holds a stack-up get the complete node and a matching board thickness, and scripts declare one with `design.stackup()` and `fenolite.dsl.stack` (the board's stack-up wins over an unlocked script one). `analyze` takes its thicknesses from it, `export` notes a job file that will state KiCad's default, and `inspect` shows it. New warnings name a stack-up that KiCad ignores and a board thickness that differs from its layers. An Altium build writes a stated core or prepreg, passes masks over and names what the document does not hold. A design without a stack-up builds the files it built before. **Changed: a board whose model holds a stack-up and that is created for KiCad (for example a model imported from Altium) now gets the `stackup` node in `setup`, and is refused with `kicad.board.stackup-invalid` when its copper entries are not the board's copper layers.** **Changed: `export --gerbers` of a board without a stack-up reports one info, `export.stackup-default`; an info does not stop the writes of `export`: only an error does (a warning does not either, since c0116).** **Release 0.2.x cannot read a model document that carries the new keys** (`dielectric_kind`, `color`, `impedance_controlled`). Stack-ups are written for 2, 4, 6 and 8 copper layers; the presets from fabricator pages are not in this part.
- `fenolite analyze` gains power paths (`[[path]]`, `--path`, `--kinds power`): the copper on the path, its narrowest sections and via groups, capacities judged where the whole current flows, and a bounded resistance and drop from a resistivity you give; insulation between layers (`--kinds insulation`, `insulation_nm`); creepage that bridges grooves narrower than your groove width (`groove_nm`, `--groove-width`). Creepage and clearance now cross copper of other nets, or of none, at no length and name it, so they can be shorter than before; a judged creepage that passes a groove without a groove width now warns. The capacities and the drop are estimates against your limits, not a simulation, and Fenolite ships no resistivity, groove width or insulation distance. **A reply without the new kinds changes too:** each measure holds `over`, `result.inputs` holds `paths`, `resistivity_pohm_m` and `groove_nm`, the evidence names `H-G-AN-OVER`, and a board with a graphic on a copper layer now gets a warning in the distance analysis. **Not yet usable on a real board:** the insulation between layers and the resistance of a via group need the depths of the stack-up, which the model gets with change c0101; until then the reply says that the stack-up is missing. A requirements file that holds a `[[path]]` row, `insulation_nm` or `groove_nm` is refused by 0.2.x and 0.3.0 (c0115).
- Via protection (c0112): `protect()` and `protection=` on `Design.via`, `via_step` and `Design.stitch`, and `Design.via_protection()` for the board default. KiCad boards read and write tenting, covering, plugging, capping and filling per via and in `setup`; target 9 holds tenting only and refuses the others (exit 7). `inspect` reports `via_protection`. **Changed:** a KiCad 9 board with via tenting, rebuilt for target 10, now keeps the mask that 9.0.9 plots, and a protection set in KiCad on a script via is reported when the build replaces it. Altium: the build writes a via's tenting where the design states it, the import reads the tenting flags into the model (**every imported via gains explicit tenting**), and the four other features are named and not written. A design that states no protection builds the files it built before, for KiCad and for Altium. 0.2.x and 0.3.0 cannot read a `board.json` that carries `protection` or `via_protection`.
- **The agent guide ships in the package** (c0079): `fenolite guide` prints it, `fenolite skill install` copies it to an agent's skill folder or adds a pointer to `AGENTS.md`, and `fenolite init` writes a starter project that builds with the built-in catalog and that the built-in router closes; `capabilities --brief` and `capabilities --command NAME` give a small first reply (6.0 kB for 35 commands, against 21.9 kB) and a command's arguments as data. **`agent/SKILL.md` moved into `src/fenolite/agent/skill/`**, and its loop block now starts from an empty folder: `capabilities --brief`, `init blink`, `build`, `place`, `route --router direct`, `fill`, `check`, `export`, `render`. `inspect` left the block for the page's section on small questions. A command can print a text of its own in text mode (`Result.text`), which is how `fenolite guide start --text` prints a page; the JSON output of every existing command is unchanged, and the default result of `capabilities` gains only the entries of the three new commands. `skill install --agent claude-code` writes to `.claude/skills/fenolite`, and `--dir DIR` serves every other agent. The block is proved on KiCad 10.0.6 for projects of both majors; the run on KiCad 9.0.9 is owed.
- A yardstick example of about 370 parts (`examples/yardstick`), taken through the loop every night by `tools/yardstick.py` with time and memory budgets per step, and a record of its runs in `docs/evidence/yardstick.md` (c0119). The board is an invented controller of eight identical 48 V buck channels with an isolated high-voltage sense section, on KiCad's official libraries and four copper layers; it is at stage 1 of five and grows as the changes of v0.4 are archived. `make yardstick` runs it locally. The job `yardstick` of `nightly.yml` is not a merge gate, and has not run yet: the budgets of `tools/yardstick_budgets.toml` are provisional, from one local run.
- **`fenolite route --timeout` now bounds the whole routing step for every router** (c0109): it bounded each net for KiCadRoutingTools, and 600 stood for the default. `route` keeps the copper of every router run that finished in time and reports the rest with `route.budget-exhausted` (a warning, exit 0; it was `route.tool-failed`, exit 5, and no copper); run `route` again to continue with the nets still open. KiCadRoutingTools routes groups of nets of equal sizes in one process, with `--escalation off` and without `--clearance` (`--router-option group-nets=N` splits a group); a net that does not fit at the requested sizes now stays open instead of being routed narrower. Freerouting is given only the nets of the job (a net outside the job whose class clearance is larger than the default rule stays declared, `route.net-declared`) and runs without its optimizer unless `--router-option optimize=on` (`route.optimizer-cut`), so its routes may hold more vias and detours than before. New `--order GLOB` routes the matching nets first, in tiers; new result keys `budget`, `runs` and `not_attempted`. For plugin authors: `RoutingJob.budget`, `JobNet.tier`, `RouterRun`, `RoutingResult.runs` and `not_attempted`, `routing.budget.Budget`; the constructors of both plugins take `budget` where they took `timeout`, and `write_dsn` takes `others`. No model or schema change.
- The layer-table benches of c0100 write the created test board without its stack-up, so they judge the layer table alone; a stack-up whose copper entries are not the board's copper layers is refused by the board writer on a created and on a read board alike (`kicad.board.stackup-invalid`), which the requirement of c0101 now states and a test pins. No behaviour of the library changes (c0101).
- `tools/agent_eval`: five authored tasks, a judge that uses `fenolite check` and the expected nets, a log of every `fenolite` call, and a runner that starts a fresh agent on one task in a clean environment. Reference solutions are replayed by the test suites; runs with a real agent are started by hand and recorded in `docs/evidence/agent-eval.md` (c0081). Nothing of it is in the package and no command changes. `make agent-eval TASK=<name> RUNNER=replay` plays a task's solution without any agent. A real agent costs money: the runner refuses one while `CI` is set, and without `--yes` it prints the budget and starts nothing; the first row for a real agent is written from its public documentation and stays `unconfigured` until the maintainer has checked it. No run with a real agent is recorded yet. Writing the tasks found one defect that no change addresses yet: a design that names the built-in catalog and a `Power(...)` interface does not build (`build.vendor-unsafe-name`, the libraries `Fenolite` and `fenolite` differ only in letter case), so a catalog part with a power input pin cannot pass KiCad's ERC from a connector supply; the task `regulator-zone` uses a Zener shunt regulator for that reason.
- The README of the agent evaluation tasks says in one sentence which licence covers what: the task scripts carry the `Apache-2.0` header that the SPDX guard demands of every `.py` file, the task texts are `CC0-1.0` (c0081).
- The RT-A2 test of the examples (`tests/unit/lens/test_altium_rta2.py`) classifies `examples/yardstick`, which c0119 added and which made three of its tests fail: no Altium build of the yardstick writes anything, so it is listed as refused with the measured reason. Without the official KiCad libraries its symbols do not resolve (exit 3); with them the build is refused in the binary and in the ASCII form (exit 5) by one `altium.text-unwritable`, the description of `Isolator_Analog:AMC1200BDWV` holding `±`. A test holds the entry to that reason where the libraries are installed. No behaviour of the library changes (c0119).
- `route` joins the SMD pads of plane nets to their planes with fan-out vias before the router runs, and never traces a plane net (c0107); `--no-plane-fanout` skips the step, and `result.plane_layers` and `result.plane_fanout` report it. Copper layers of type `power` are plane layers, and **`board(planes=…)` now sets that type on KiCad boards: the board of a script that declares planes changes in those rows, also on a rebuild; a script without planes builds the bytes it built before.** A plane without a zone of its net gives `build.plane-zone-missing`. The Specctra file declares plane layers and planes, keeps classes to their layers, and carries class clearances, class-to-class clearance and per-layer widths; the rules it cannot carry, the edge clearance among them, are reported (`specctra.rule-not-sent`). `route` now reads the project's rules file. New rule kind `no_tracks` (`disallow track` in KiCad, for target 10 until its probe is recorded on 9.0), which an Altium build reports as not lowered. **Releases 0.2.x and 0.3.x cannot read a model document that holds a `no_tracks` rule.** `build.plane-not-lowered` is no longer given.
- The probes that the v0.4 changes registered for KiCad 9 have their 9.0.9 outcomes, measured in the pinned image (57 rows of `docs/evidence/kicad/probes/9.0.9.json`). **A rule of the kind `no_tracks` is now written for target 9 too** (`dru-kind-no_tracks` is `present` on 9.0.9); it gave `rules.kind-unchecked` there before. Three outcomes differ from their tests on 9.0.9 and are recorded as measured: `drc-limit-hole_clearance` and `drc-limit-keys` (`different`), and `route-fanout-t9` (`inconclusive` in a container without `kicad-cli` 10).
- **Net ties, waivers and check severities** (c0114). Net-tie pad groups are read, written and authored (`Footprint.net_tie`), and the copper check no longer reports two pads of one group: a board whose tied pads touch, or sit closer than the clearance, loses those `copper.short` and `copper.clearance` findings in `check` and in the build's copper guard. `design.waive()` accepts one `copper.*` or `kicad.drc.*` finding with a reason, which `check` and the build's copper guard then list as `info`, and `check` reports waivers and KiCad exclusions that no longer match (`check.waiver-unmatched`, `check.exclusion-stale`); `design.rules.severity()` sets the severity of a KiCad DRC check in the project file. Waivers also apply to `check` on a built Altium project and to the copper guard of the Altium build; the Altium build reports net-tie groups and severities instead of writing them. **Output changes:** the result of `check` gains `waivers`, `result.copper_check` of `build` gains `waivers`, the summary of `copper.clearance` gains `net_tie_pairs` and that of `drc.kicad` gains `exclusions`, and the issue of a DRC entry that the KiCad project excludes now ends with ` (excluded in the project: <comment>)`. The model gains three keys, each omitted when unused, so a design that uses none of them builds the same bytes: `net_ties` (`board.json`, `library.json`), `waivers` (`findings.json`) and `severities` (`rules.json`); 0.2.x cannot read a document that carries one of them. KiCad's verdicts are proved on `kicad-cli` 10.0.6; the 9.0.9 runs are owed.
- Script copper can be given in a part's frame (c0111): `part.at(dx, dy)` and `part.pad(n).at(dx, dy)` stand wherever a point is taken, and the build resolves them after placement, so vias, waypoints and stitches follow a moved part at the next build. `design.stitch(region=part.pad(n))` makes a thermal via array inside a pad. `part_frame` gives the same points to the Python API. `via_step` and `Design.via` also take their point as one argument, an anchor or an `(x, y)` pair; the two-length forms work as before, and a script without anchors builds the same bytes. No model, schema, CLI or issue-code change: an anchor that cannot be resolved and a pad that cannot hold an array use five existing `kicad.copper.*` codes (`docs/copper.md`). A via of another net anchored inside a pad passes KiCad's DRC, which gives it the pad's net; the copper guard of `build` refuses it. Measured on `kicad-cli` 10.0.6; the same probes on 9.0.9 are pending, so `H-G-FRAME-ANCHOR` and `H-K-VIA-IN-PAD` are `INFERRED`.

## [0.3.0] - 2026-10-08

### Added

- v0.3, the write part of the second backend: `fenolite build --target altium` writes a complete Altium project (PCB document, schematic documents, both libraries, project file, output job and drawing sheet), a model with a board is written back as Altium documents with the round-trip level RT-A3, `fenolite check` judges copper and parity on Altium input without a tool, `equivalent` compares routing at level 5, and `fenolite kit` builds, checks and records the Altium verification kit. **Every Altium write stays experimental in 0.3.0**: by the rule of change c0092 no write kind has the evidence to leave it, and no kit run is recorded. What is proved, the verdict per write kind and what is not in this release are in `docs/release/v0.3.md`.
- A pin may be bonded to several pads (c0123): `pad_map={"3": ("3", "EP")}` in a script, and the pads that a footprint model lists for one pin in an Altium import. Every pad takes the pin's net on the board; the generated KiCad schematic holds one hidden pin per further pad, so KiCad's netlist, ERC and parity test see them; `netlist.assignment_compare` and level 2 of `equivalent` name every pad. `Component.pin_pad_map` holds such a pin in several pairs, and `Component.pads_of(pin)` reads it. A design whose pins have one pad each is written byte for byte as before. **The model version stays `"0"`, at a cost: Fenolite 0.2.x and earlier read a document that holds a pin of several pads without an error and apply one pad per pin.** New finding `model.pin-pad-map` (error) for a pad that two pins name; a build of a script with such a pad keeps its own error beside it (`altium.pin-pad-map-invalid`, `build.pin-pad-map-invalid`).
- An Altium build bonds a pin to every pad its `pad_map` lists (c0123). The release 0.2.1 fixed the build for a map of one pad per pin; now each pad of a pin carries the pin's net in the PCB document, script copper and `--copper-from` are checked against every pad, and the map record of the pin in the schematic and its library lists all its pads. RT-A2 compares the map. `fenolite check`, the parity test and `equivalent` know the map of a built Altium project from 0.3.0: they report nothing for the mapped pins, where 0.2.1 reports `netlist.assignment-differs`. A map that names a missing pin or pad, or that leaves one pad to two pins, is refused with `altium.pin-pad-map-invalid`, as in 0.2.1. **The files of an Altium build change only for a script whose `pad_map` gives a pin several pads.**
- The Altium import names the components of a sheet that several sheet symbols name per channel: by the project's PCB document, else by the project's designator format (`D9_1` … `D9_12` instead of `D9` twelve times). On the public project with such a sheet, the schematic and the board now share 694 pad assignments instead of 508. The import instantiates repeated sheets: a sheet symbol `Repeat(NAME, first, last)` gives one channel per index, each with its own components, nets and designators (`$ChannelIndex` and `$ChannelAlpha` are resolved; a sheet entry `Repeat(NAME)` takes one member of the parent's bus per channel; a net inside a channel is named per channel); `altium.import.repeated-sheet` is now only the statement that cannot be instantiated. Imported components carry the pin-to-pad map of their footprint model (`pin_pad_map`), which `check` and level 2 of `equivalent` apply; `altium.import.pin-map` (info) counts the map records that one pad per pin cannot say. The `Repeat` part rests on Altium's documentation and authored sheets (no public file holds one), and a board links to such channels by designator only; the annotation file is still not read (c0083).
- The Altium PCB document holds stacks of up to 16 signal layers, blind and buried vias, board texts, graphics, keep-outs and non-plated holes; polygons are written unpoured and repoured in Altium. `result.pcb` of an Altium build counts every model item as written or not lowered, and an item without a record is named by `altium.not-lowered` (`where` = `<kind>/<id>`). Changed: a blind or buried via is written instead of refused; `altium.via-unsupported` is a warning for micro vias only, and the build goes on without them; a board's keep-outs, texts, graphics and holes are written instead of reported per kind; a copper count that is odd or above 32 gives the stack of the two outer layers and `altium.not-lowered` (`stackup`) instead of `altium.copper-stack`. A keep-out holds its restrictions in the key Altium saves and in the key KiCad's importer reads, so a KiCad import carries them. Component bodies are not written yet (reported one by one), and the model's board holes have no slots (c0085).
- `equivalent --level 5` compares routing per net: which pads the copper joins, the vias per layer pair and the routed length per layer. Differences are located at the net (`equiv.route-missing`, `equiv.route-connectivity`, `equiv.route-vias`, `equiv.route-length`); copper that reaches no pad and nets that depend on a zone without a fill are reported and fail nothing (`equiv.route-stub`, `equiv.route-unjudged`, under `result.notices`). `--tolerance-ppm` and a profile's `tolerance_ppm` set a relative tolerance for routed lengths. **Behaviour change:** without `--level`, `equivalent` now runs level 5 when both sides hold a track, an arc or a via, so two routed boards that differ only in their routing exit 5 where they exited 0; pass `--level 4` for the earlier result. The triangle holds at level 5 on `kicad-cli` 10.0.6 for the routed sample and the seven public PCB documents (c0089).
- An Altium build writes an output job set up from the export preset and draws the script's drawing sheet on its schematics; `template build --target altium` writes a `.SchDot` from a sheet specification. The job (`<name>.OutJob`, on by default beside a PCB document, `--altium-outjob off` to leave it out) holds Gerber, NC drill, pick-and-place, bill-of-materials, schematic-print and PCB-print outputs with their source documents and two containers, and no output setting: the options of `--altium-outjob-preset` are listed in `result.outjob.defaults` to be set in Altium. The drawing sheet of `design.sheet(drawing_sheet=…)` is drawn on every Altium schematic as lines and texts on a custom sheet of the paper's size, with the title block as sheet parameters; a logo and a text that mixes a token with other text are losses that need `--allow-lossy`. Both files are proved by Fenolite's own readers only and stay `INFERRED` until Altium has opened them (c0087).
- An Altium build writes the script's rules by kind and scope, names every rule it cannot lower with its reason, and `export --altium-rul` writes them as a rule file. Seven Altium rule kinds carry the neutral ones (Clearance, Width, Routing Via Style, Hole Size, Board Outline Clearance, Hole To Hole Clearance, Minimum Annular Ring), scoped to all objects, a net, a net class or their conjunction; a rule is written exactly or not at all. **Changed:** the single `altium.not-lowered` info with `where` `design-rules` is gone; each rule that is not written gives one `altium.not-lowered` warning with `where` `design-rules/<kind>`, and `result.rules` lists what was written and what was not. The import maps Board Outline Clearance, Hole To Hole Clearance and Minimum Annular Ring (c0084; that Altium applies the rules is not yet confirmed).
- `fenolite kit` builds the Altium verification kit, checks the files a run leaves and records the run: the base of the label `ALTIUM-VERIFIED(kit)`. `kit build` writes five sample projects from the scripts under `examples/kit/`, a checklist (`STEPS.md`), a result form and a script that a user may start inside Altium for the compile steps; the kit is the same byte for byte on every machine. `kit verify` reads the documents that Altium saved with Fenolite's readers, compares them with the kit's own at the levels of `equivalent`, checks the typed values and lists strings that look like a home folder or a login name. `kit record` writes the archive of the results and a run record without any path or user name; `kit status` lists the runs and the rows whose run is stale. No run was made yet, so no row carries the label; the copper check of a re-saved board waits for c0088 and is reported as pending (`docs/altium-kit.md`, c0091).
- A model with a board can be written as Altium documents; RT-A2 compares footprints and copper, and the new level RT-A3 measures an import, write and re-import over the public corpus. `AltiumBackend().write(design)` (and `fenolite.lens.altium.write_model` for a design read from a KiCad board, whose rounded pads need KiCad's corner ratio) writes the PCB document from the model alone and a schematic generated from the circuit; what the writers do not carry is counted per kind and reported as `altium.not-lowered`, and a loss of copper, pads or footprints is refused (`FEN-7001`) without `allow_lossy`. New: the opt-in check stage `roundtrip.rta3` with the codes `check.rta3-failed` and `check.rta3-unwritten`, and `fenolite roundtrip PATH --level rta0|rta1|rta2|rta3` for Altium input. On the seven public PCB documents that are not heavy the two imports are equal inside the written scope and KiCad's importer reads each rewrite as Fenolite does; a rewrite is not a copy: footprint graphics, bodies, shapes on copper and poured fills are not in it, and `docs/evidence/altium-roundtrip.md` gives the counts (c0090).

### Changed

- **The default output of an Altium build changes** (c0086): the Altium schematic draws each symbol's own graphics, follows the module tree at any depth, and carries port directions, buses, parameters and text outside ASCII. `--altium-symbols generic` gives the former output (one rectangle per part), byte for byte; `graphics` is the default by the maintainer's decision of 2026-10-06. New options `--altium-symbols generic|graphics` and `--altium-directions on|off`, new `result.schematic`, new info `altium.bus-flattened`. With `--altium-sheets modules` a nested module now gets its own sheet `<name>_<module path with ".">.SchDoc` instead of being drawn on the sheet of its top-level module; `flat` stays the default. Symbols and footprints from the catalog, and symbols the script authored, now build for `--target altium`. The properties of a part become hidden parameters. In the binary form a comment or a parameter value may hold Windows-1252 characters. The committed samples `blink`, `kicad_example`, `no_connect` and `routed` were regenerated; their earlier bytes, which the author reports covered, are kept under `tests/data/altium/generic/`. Nothing of this has been opened in Altium yet (Part Y of `docs/evidence/altium-schematic.md`); KiCad's importer reads the written library graphics as the model holds them.
- **`fenolite check` on Altium input runs two more stages by default, and can exit 5 where it exited 0** (c0088): `copper.clearance` (shorts, clearance and zone overlaps of the PCB document, with the Clearance rules the document holds) and `parity` (the PCB document against its schematic documents: references, values, footprints and nets), both without any tool. `--stages` selects the former set. The stage says what it could not judge and then carries `UNVERIFIED`: unpoured polygons, internal planes, Clearance rules outside the rule table, and filled zones that no clearance applies to (a pour is never judged against a default the document does not hold). `fenolite parity` takes an Altium project, project folder or PCB document. `fenolite build --target altium` judges the copper of the PCB document it is about to write and refuses a board with a short (exit 5, nothing written); `--copper-check warn` writes it, and the option is no usage error with that target any more. The result of an Altium build gains `copper_check`. The copper check judges no board-edge clearance on either backend. For Altium input only, each clearance rule is judged 5 nm lower, because a distance of an Altium document can read up to 4 nm closer after the unit conversion; KiCad boards are judged exactly as in 0.2.0.
- **`fenolite check` on an Altium PCB document can judge clearance where it judged shorts only, and exit 5 where it exited 0** (c0125): the Altium rule table reads more forms of a Clearance record. A blank object matrix and one whose every entry equals the rule's value are one clearance; the records of a clearance matrix between all net classes (`ISMATRIX` and the cell keys) are read; `ExistsOnLayer` of every copper layer of the board on both scopes gives a clearance rule with `layers`, and `OnMid` on a board without an internal signal layer applies to nothing (new reason `no-layer`, which is no unread rule). A matrix of differing clearances stays unmapped and its reason now counts the differing entries instead of quoting the matrix; the option that ignores the pads of one footprint, a layer condition for some of the copper layers and every other scope function stay unmapped too. The forms are read, never written. **On the public corpus this lifts ONE of the three PCB documents that had no clearance in force**, to the level `INFERRED`: the one whose records are a clearance matrix on a two-layer board, the only forms a neutral rule says exactly. The two others stay `UNVERIFIED` (`docs/evidence/altium-roundtrip.md`, "Light DRC over the corpus"). `map_rules`, `rulemap.lift` and `import_rules` take the board's copper layers (`layers=`); KiCad boards and every written file are unchanged.
- **The Altium import reads a Clearance matrix cell by cell, and the stage summary of a document check has one more key** (c0130): a Clearance record whose object matrix holds differing clearances gives its generic rule and one more clearance rule per cell (`<rule>/<kind>-<kind>`, with `item_kind` selectors for `track`, `pad`, `via` and `zone`), when the matrix is exact in those kinds; a matrix that tells an arc from a track or a through-hole pad from a surface pad stays unmapped and its reason names the pairs. Cells for fills, regions, text and holes are kept in the rule's bag. `summary.clearance_cells` (`judged`, `unjudged`) counts them, from the new `DesignRules.clearance_cells`. **On the public corpus this lifts one record, on the heavy document, which stays `UNVERIFIED`; the two other documents with such a matrix are not moved** (their matrices are not exact, and they carry the option that ignores the pads of one footprint). The measurement of that heavy document also found 28 false shorts of the import (vias without a pad on inner layers), listed on `docs/evidence/altium-roundtrip.md`. Read only; KiCad boards and every written file are unchanged.
- **The canonical model of an imported Altium project changes when a footprint model lists several pads for a pin** (c0123): the pads are pairs of `pin_pad_map`, no longer `pin_pads` entries of the extension bag, and `altium.import.pin-map` counts only a record without a pad and a pad that another pin holds. On the public project with such records the assignment comparison covers four more elements.
- **The output job that `fenolite build --target altium` writes now holds the Gerber settings, and every written `.OutJob` differs from the one an earlier build wrote** (c0138). No release wrote an output job (0.2.x writes none; the job is unreleased v0.3 work), so this concerns folders built from the development branch. **A rebuild into such a folder replaces the job and keeps the old one as `<name>.OutJob.bak`**, as it does for every other file the build wrote; it is refused instead (exit 7, `FEN-7001`, nothing written) only when the job was edited since that build or when the folder's `.fenolite/` record is gone, and then `--discard-layout` replaces it, again with the backup. **A rebuild of a folder built by 0.2.x adds the output job to the project file, keeping `<name>.PrjPcb.bak`**: a project file that is still as a build wrote it and does not list the job is written again with the job listed, so that Altium's Projects panel shows it; a project file that was changed since (Altium saved it, or you edited it), or that the folder's `.fenolite/` record does not know, is kept as before, whatever `--discard-layout`, with the info `altium.outjob-not-listed` and how to list the job. Why: run in Altium Designer 26, the job as written before produced drill, pick-and-place, bill-of-materials and print files and no Gerber layer file, because a Gerber output without a settings record plots nothing. The Gerber output now carries the complete record of 44 fields that the public saved jobs hold: millimetres, the decimals of the export preset's `gerbers.precision` (4 without a preset), and as plotted layers the layers of the board (silkscreen, paste, solder mask, the copper layers from top to bottom with a plane at its place, Mechanical 13 to 16). Every output, of every kind, gains the key `OutputDefault<i>=0`; no other output kind gains a settings record. **No board outline is plotted yet: the Gerber set of the written job holds no outline file**, because the PCB document holds the outline as the board shape and on no layer; `result.outjob.gerber.outline` says so, and you turn the outline on in the Gerber setup in Altium. `result.outjob` gains `gerber` (`unit`, `decimals`, `layers`, `outline`) and `result.outjob.defaults` no longer lists `gerbers.precision`. `outjob.from_preset` takes the board's copper stack (`copper=`), `write_outjob` refuses a Gerber output without the whole record, and `read_outjob` gives the settings of an output (`JobOutput.settings`, `record_fields`). Altium has not opened such a job yet: every row is `INFERRED` until Part O of the second Altium session is reported; the committed sample `tests/data/altium/outjob/blink.OutJob` changes (eight more lines).
- **The notes about a kept Altium project file name only what the file lacks** (c0138). A project file that exists in `--out` and is kept is now read with Fenolite's own project reader: `altium.pcb-not-in-project`, `altium.schlib-not-in-project`, `altium.sheets-not-in-project` and `altium.outjob-not-listed` are given only for documents the kept file really does not list, and each names those documents alone. Before, the first three were given on every rebuild into a folder with a project file, even one that listed everything. A kept file that cannot be read gets them as before, with a hint that says so.
- **`.fenolite/build.json` of an Altium build keeps a kept project file that is still as a build wrote it** (c0138). A rebuild that keeps `<name>.PrjPcb` (nothing has to change in it, or the output job is off) records the file again when its bytes are the ones the folder's record held, so that a later build still knows it as built and can add the output job to it. The record's file list is no list of what a run wrote: `result.files` and the receipt are, and they do not name a kept file.
- **An Altium board with internal planes is imported with fewer tracks.** A plane layer is stored in negative, so a line, an arc, a fill, a region or a text drawn on it cuts the plane and is no copper; the import made a track without a net of each such line. It now makes no entity of them, with or without a net: `altium.import.unmapped` counts them as `plane-cuts`, and the layer of the plane holds the count in its `altium` bag (`plane_cuts`). The ids of the other imported items do not change. The copper check on Altium input no longer filters those lines out of its view and reports the planes as before (`copper.item-unsupported` at `plane`); `equivalent --level 5` no longer counts them as copper on no net, and a rewrite of such a board (RT-A3) no longer writes them as tracks. On the two public documents with planes the import holds 74 and 43 tracks fewer, the number KiCad's own import of them holds (c0124).

A zone fill of an imported document is one ring that holds the outline and its holes, the form of a KiCad filled polygon (new `geometry.keyhole_ring`), so the copper check no longer reports tracks and vias in a hole as shorts and `equivalent --level 5` finds the islands of a pour. - The font table of an Altium schematic holds each distinct font once (c0146). ### Fixed

- Windows: `kicad-cli.exe` is found on `PATH` and in KiCad's default install folders, which KiCad's installer does not put on `PATH`; files Fenolite writes keep LF line ends; a board on another drive than the working folder can be routed; a drawing-sheet path starting with `/` counts as absolute.
- `fenolite route` reads the net classes from the project file beside the board. Before, every net was routed with the default track width, clearance and via size, whatever its class said: a KiCad board holds no net class.
- `fenolite route --router freerouting` lists a net under `unrouted` when Freerouting reports that it left one of its connections open. Before, a net with any copper counted as routed, so a partly routed net was reported as done; KiCad's DRC in `fenolite check` still found it.
- A board whose rotated pad or rotated footprint carries a slotted hole is read and written again, and its footprints can be written as library files: the writer refused them (`KiCad writer cannot represent this slot rotation`, `KiCad oval drills can encode only horizontal or vertical slot axes`). `Padstack.hole_rotation` is now the slot's axis in the pad's own frame everywhere; on a board it used to include the pad's angle.
- Geometry: the documented and tested bound of two successive `Transform.apply` calls is `(1 + |cos θ| + |sin θ|)/2` nm per axis, at most `(1 + √2)/2 ≈ 1.2071` nm, not 1 nm; `test_composition_rounds_once` no longer fails at random, and a test reaches the bound exactly. No code changes (c0050).
- Script copper in the Altium build (change c0053): `fenolite build --target altium` now writes the tracks, vias and stitching vias that the design script declares (`Design.track`, `Design.via`, `Design.stitch`) into the experimental `<name>.PcbDoc`; before, they were left out without an issue. An intent that does not resolve refuses the build, an intent that creates nothing is reported, and with `--copper-from` the board wins with one `altium.not-lowered` info.
- `fenolite check` no longer reports `kicad.drc.rules-not-loaded` for rules that were loaded on a board with 499 or more clearance violations: `kicad-cli` stops reporting clearance violations near 499 per run and can leave the canary's own out, so such a run is now `inconclusive` with the reason `clearance-limit` (`kicad.drc.rules-unchecked`). The two-run canary test compares two DRC runs against what was measured to repeat, and the contract says which part of `check`'s output repeats between runs (c0051).
- Altium PCB document in the form Altium saves: `<name>.PcbDoc` now holds the whole `Board6` record (board keys, the outline as a polygon, sheet, sub-stack, drill pair, routing keys and snap grid, written by rule in `docboard.py` on top of `libboard.py`), net and component records with the common keys and unique ids, `UniqueIDPrimitiveInformation`, the option storages (`Advanced Placer Options6`, `Pin Swap Options6`, `Design Rule Checker Options6`, `PadViaLibrary`, `PadViaLibraryCache`, `LayerKindMapping`, `ConstraintManager`, `SignalClasses`) and 13 more empty storages; `write_pcbdoc` takes the file name. The first form gave a "catastrophic" error in Altium Designer 26.5 (maintainer's report, c0035); the new one opens there and its change order from the schematic reports no difference (author report of 2026-10-03). Texts, pads, tracks and arcs keep their short records.
- Altium PCB library opens in Altium Designer's form: `<name>.PcbLib` now holds the 53-byte `FileHeader` (version and library id), the whole board record in `Library/Data` (layer stack, grid, layer sets and view keys, written by rule in `libboard.py`) and the `Library` side streams (`EmbeddedFonts`, `ModelsNoEmbed`, `Textures`, `ComponentParamsTOC`, `PadViaLibrary`); `FileHeaderSix` of `<name>.PcbDoc` carries its id. The first form gave a "catastrophic" error in Altium Designer (maintainer's report, c0035); the new one opens in Altium Designer 26.5 (author report of 2026-10-03).
