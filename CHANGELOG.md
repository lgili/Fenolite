# Changelog

All notable changes to Fenolite are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/) (pre-1.0: minor versions may break).

## [Unreleased]
- **Changed: an Altium board with internal planes is imported with fewer tracks.** A plane layer is stored in negative, so a line, an arc, a fill, a region or a text drawn on it cuts the plane and is no copper; the import made a track without a net of each such line. It now makes no entity of them, with or without a net: `altium.import.unmapped` counts them as `plane-cuts`, and the layer of the plane holds the count in its `altium` bag (`plane_cuts`). The ids of the other imported items do not change. The copper check on Altium input no longer filters those lines out of its view and reports the planes as before (`copper.item-unsupported` at `plane`); `equivalent --level 5` no longer counts them as copper on no net, and a rewrite of such a board (RT-A3) no longer writes them as tracks. On the two public documents with planes the import holds 74 and 43 tracks fewer, the number KiCad's own import of them holds (c0124).
- Proposed the ten v0.4 OpenSpec changes c0083–c0092 for the write side of the second backend: repeated sheets in the import, rule lowering, the complete PCB document and schematic, the output job and the sheet template, a copper and parity check on Altium input, equivalence level 5, the round trip of a written model, the verification kit, and the rule by which a write leaves `experimental`.
- The Altium import names the components of a sheet that several sheet symbols name per channel: by the project's PCB document, else by the project's designator format (`D9_1` … `D9_12` instead of `D9` twelve times). On the public project with such a sheet, the schematic and the board now share 694 pad assignments instead of 508. The import instantiates repeated sheets: a sheet symbol `Repeat(NAME, first, last)` gives one channel per index, each with its own components, nets and designators (`$ChannelIndex` and `$ChannelAlpha` are resolved; a sheet entry `Repeat(NAME)` takes one member of the parent's bus per channel; a net inside a channel is named per channel); `altium.import.repeated-sheet` is now only the statement that cannot be instantiated. Imported components carry the pin-to-pad map of their footprint model (`pin_pad_map`), which `check` and level 2 of `equivalent` apply; `altium.import.pin-map` (info) counts the map records that one pad per pin cannot say. The `Repeat` part rests on Altium's documentation and authored sheets (no public file holds one), and a board links to such channels by designator only; the annotation file is still not read (c0083).
- The Altium PCB document holds stacks of up to 16 signal layers, blind and buried vias, board texts, graphics, keep-outs and non-plated holes; polygons are written unpoured and repoured in Altium. `result.pcb` of an Altium build counts every model item as written or not lowered, and an item without a record is named by `altium.not-lowered` (`where` = `<kind>/<id>`). Changed: a blind or buried via is written instead of refused; `altium.via-unsupported` is a warning for micro vias only, and the build goes on without them; a board's keep-outs, texts, graphics and holes are written instead of reported per kind; a copper count that is odd or above 32 gives the stack of the two outer layers and `altium.not-lowered` (`stackup`) instead of `altium.copper-stack`. A keep-out holds its restrictions in the key Altium saves and in the key KiCad's importer reads, so a KiCad import carries them. Component bodies are not written yet (reported one by one), and the model's board holes have no slots (c0085).
- `equivalent --level 5` compares routing per net: which pads the copper joins, the vias per layer pair and the routed length per layer. Differences are located at the net (`equiv.route-missing`, `equiv.route-connectivity`, `equiv.route-vias`, `equiv.route-length`); copper that reaches no pad and nets that depend on a zone without a fill are reported and fail nothing (`equiv.route-stub`, `equiv.route-unjudged`, under `result.notices`). `--tolerance-ppm` and a profile's `tolerance_ppm` set a relative tolerance for routed lengths. **Behaviour change:** without `--level`, `equivalent` now runs level 5 when both sides hold a track, an arc or a via, so two routed boards that differ only in their routing exit 5 where they exited 0; pass `--level 4` for the earlier result. The triangle holds at level 5 on `kicad-cli` 10.0.6 for the routed sample and the seven public PCB documents (c0089).
- An Altium build writes an output job set up from the export preset and draws the script's drawing sheet on its schematics; `template build --target altium` writes a `.SchDot` from a sheet specification. The job (`<name>.OutJob`, on by default beside a PCB document, `--altium-outjob off` to leave it out) holds Gerber, NC drill, pick-and-place, bill-of-materials, schematic-print and PCB-print outputs with their source documents and two containers, and no output setting: the options of `--altium-outjob-preset` are listed in `result.outjob.defaults` to be set in Altium. The drawing sheet of `design.sheet(drawing_sheet=…)` is drawn on every Altium schematic as lines and texts on a custom sheet of the paper's size, with the title block as sheet parameters; a logo and a text that mixes a token with other text are losses that need `--allow-lossy`. Both files are proved by Fenolite's own readers only and stay `INFERRED` until Altium has opened them (c0087).
- An Altium build writes the script's rules by kind and scope, names every rule it cannot lower with its reason, and `export --altium-rul` writes them as a rule file. Seven Altium rule kinds carry the neutral ones (Clearance, Width, Routing Via Style, Hole Size, Board Outline Clearance, Hole To Hole Clearance, Minimum Annular Ring), scoped to all objects, a net, a net class or their conjunction; a rule is written exactly or not at all. **Changed:** the single `altium.not-lowered` info with `where` `design-rules` is gone; each rule that is not written gives one `altium.not-lowered` warning with `where` `design-rules/<kind>`, and `result.rules` lists what was written and what was not. A `clearance` or `edge_clearance` minimum of the script now reaches the PCB document and precedes the class rules; a width, via or hole-size minimum is reported, because Altium's record also holds a maximum. The import maps Board Outline Clearance, Hole To Hole Clearance and Minimum Annular Ring (c0084; that Altium applies the rules is not yet confirmed).
- **The default output of an Altium build changes** (c0086): the Altium schematic draws each symbol's own graphics, follows the module tree at any depth, and carries port directions, buses, parameters and text outside ASCII. `--altium-symbols generic` gives the former output (one rectangle per part), byte for byte; `graphics` is the default by the maintainer's decision of 2026-10-06. New options `--altium-symbols generic|graphics` and `--altium-directions on|off`, new `result.schematic`, new info `altium.bus-flattened`. With `--altium-sheets modules` a nested module now gets its own sheet `<name>_<module path with ".">.SchDoc` instead of being drawn on the sheet of its top-level module; `flat` stays the default. Symbols and footprints from the catalog, and symbols the script authored, now build for `--target altium`. The properties of a part become hidden parameters. In the binary form a comment or a parameter value may hold Windows-1252 characters. The committed samples `blink`, `kicad_example`, `no_connect` and `routed` were regenerated; their earlier bytes, which the author reports covered, are kept under `tests/data/altium/generic/`. Nothing of this has been opened in Altium yet (Part Y of `docs/evidence/altium-schematic.md`); KiCad's importer reads the written library graphics as the model holds them.
- The Altium import keeps the holes of a poured region: copper inside a hole of a pour is no longer joined to it. A zone fill of an imported document is one ring that holds the outline and its holes, the form of a KiCad filled polygon (new `geometry.keyhole_ring`), so the copper check no longer reports tracks and vias in a hole as shorts and `equivalent --level 5` finds the islands of a pour. A hole outside its outline is dropped and reported by the new warning `altium.import.zone-hole-outside`. Imported boards whose pours have holes get other fill polygons than before; boards without holes are unchanged (c0122).
- **`fenolite check` on Altium input runs two more stages by default, and can exit 5 where it exited 0** (c0088): `copper.clearance` (shorts, clearance and zone overlaps of the PCB document, with the Clearance rules the document holds) and `parity` (the PCB document against its schematic documents: references, values, footprints and nets), both without any tool. `--stages` selects the former set. The stage says what it could not judge and then carries `UNVERIFIED`: unpoured polygons, internal planes, Clearance rules outside the rule table, and filled zones that no clearance applies to (a pour is never judged against a default the document does not hold). `fenolite parity` takes an Altium project, project folder or PCB document. `fenolite build --target altium` judges the copper of the PCB document it is about to write and refuses a board with a short (exit 5, nothing written); `--copper-check warn` writes it, and the option is no usage error with that target any more. The result of an Altium build gains `copper_check`. The copper check judges no board-edge clearance on either backend. For Altium input only, each clearance rule is judged 5 nm lower, because a distance of an Altium document can read up to 4 nm closer after the unit conversion; KiCad boards are judged exactly as in 0.2.0.
- `fenolite kit` builds the Altium verification kit, checks the files a run leaves and records the run: the base of the label `ALTIUM-VERIFIED(kit)`. `kit build` writes five sample projects from the scripts under `examples/kit/`, a checklist (`STEPS.md`), a result form and a script that a user may start inside Altium for the compile steps; the kit is the same byte for byte on every machine. `kit verify` reads the documents that Altium saved with Fenolite's readers, compares them with the kit's own at the levels of `equivalent`, checks the typed values and lists strings that look like a home folder or a login name. `kit record` writes the archive of the results and a run record without any path or user name; `kit status` lists the runs and the rows whose run is stale. No run was made yet, so no row carries the label; the copper check of a re-saved board waits for c0088 and is reported as pending (`docs/altium-kit.md`, c0091).
- A model with a board can be written as Altium documents; RT-A2 compares footprints and copper, and the new level RT-A3 measures an import, write and re-import over the public corpus. `AltiumBackend().write(design)` (and `fenolite.lens.altium.write_model` for a design read from a KiCad board, whose rounded pads need KiCad's corner ratio) writes the PCB document from the model alone and a schematic generated from the circuit; what the writers do not carry is counted per kind and reported as `altium.not-lowered`, and a loss of copper, pads or footprints is refused (`FEN-7001`) without `allow_lossy`. The write is experimental and is not in the capability report. An Altium build now stores the board it wrote in `.fenolite/board.json` (footprints with their pads, tracks, arcs, vias, zones), so `roundtrip.rta2` compares every kind of the written scope and no longer has `summary.not_in_model`; a project built earlier is skipped with `model-predates-board` until it is built again. No project file of a build changes. New: the opt-in check stage `roundtrip.rta3` with the codes `check.rta3-failed` and `check.rta3-unwritten`, and `fenolite roundtrip PATH --level rta0|rta1|rta2|rta3` for Altium input. On the seven public PCB documents that are not heavy the two imports are equal inside the written scope and KiCad's importer reads each rewrite as Fenolite does; a rewrite is not a copy: footprint graphics, bodies, shapes on copper and poured fills are not in it, and `docs/evidence/altium-roundtrip.md` gives the counts (c0090).
- **`fenolite check` on an Altium PCB document can judge clearance where it judged shorts only, and exit 5 where it exited 0** (c0125): the Altium rule table reads more forms of a Clearance record. A blank object matrix and one whose every entry equals the rule's value are one clearance; the records of a clearance matrix between all net classes (`ISMATRIX` and the cell keys) are read; `ExistsOnLayer` of every copper layer of the board on both scopes gives a clearance rule with `layers`, and `OnMid` on a board without an internal signal layer applies to nothing (new reason `no-layer`, which is no unread rule). A matrix of differing clearances stays unmapped and its reason now counts the differing entries instead of quoting the matrix; the option that ignores the pads of one footprint, a layer condition for some of the copper layers and every other scope function stay unmapped too. The forms are read, never written. **On the public corpus this lifts ONE of the three PCB documents that had no clearance in force**, to the level `INFERRED`: the one whose records are a clearance matrix on a two-layer board, the only forms a neutral rule says exactly. The two others stay `UNVERIFIED` (`docs/evidence/altium-roundtrip.md`, "Light DRC over the corpus"). `map_rules`, `rulemap.lift` and `import_rules` take the board's copper layers (`layers=`); KiCad boards and every written file are unchanged.
- **The Altium import reads a Clearance matrix cell by cell, and the stage summary of a document check has one more key** (c0130): a Clearance record whose object matrix holds differing clearances gives its generic rule and one more clearance rule per cell (`<rule>/<kind>-<kind>`, with `item_kind` selectors for `track`, `pad`, `via` and `zone`), when the matrix is exact in those kinds; a matrix that tells an arc from a track or a through-hole pad from a surface pad stays unmapped and its reason names the pairs. Cells for fills, regions, text and holes are kept in the rule's bag. `summary.clearance_cells` (`judged`, `unjudged`) counts them, from the new `DesignRules.clearance_cells`. **On the public corpus this lifts one record, on the heavy document, which stays `UNVERIFIED`; the two other documents with such a matrix are not moved** (their matrices are not exact, and they carry the option that ignores the pads of one footprint). The measurement of that heavy document also found 28 false shorts of the import (vias without a pad on inner layers), listed on `docs/evidence/altium-roundtrip.md`. Read only; KiCad boards and every written file are unchanged.

## [0.2.0] - 2026-10-06

### Added

- v0.2 acceptance: the schematic of a built project judged by KiCad's own ERC, netlist and parity test on 9.0 and 10.0, round trips of the demo schematics, the BOM and placement tables, the project manifest, the inspection commands, the complete layout lens, six more rule kinds and Fenolite's own parity check; the release record `docs/release/v0.2.md` names the test behind each item, its limits and what else is in the package (c0093).
- `fenolite build` writes a schematic (`<name>.kicad_sch`, symbol libraries and `sym-lib-table`) that KiCad's ERC and parity test accept on 9.0 and 10.0; pads of unconnected pins and net names with a slash are written as KiCad stores them; `--schematic skip` keeps the previous output (c0061). A sheet holds every unit of every part, a global label per connected pin, a no-connect flag per `no_connect` mark and a power flag per supply net that nothing drives; `schematic-placements.toml` beside the script fixes symbol positions, and an edited schematic is replaced with a warning and a backup (`docs/schematic.md`). New `build` issue codes are listed in `docs/cli-contract.md`.
- The schematic gets one sheet per module and puts 2-pin parts beside the IC pins they connect to, joined by a wire; `--schematic-layout grid` writes one flat sheet. Each module with a part is written to `sheets/<module path>.kicad_sch` and named by a box without pins on the sheet above it; nets cross sheets by their global labels, so net names stay those of the script, and a footprint of a part in a module carries the path of its sheets. `fenolite netlist --source fenolite` and the build's netlist guard read the sheet tree and the wires, so a sheet that KiCad would drop in silence stops the build. `fenolite parity` and the `parity` stage of `check` read the sheet tree with Fenolite's own netlist, so a project with module sheets needs no tool there either (c0070). The Reference and the Value of a turned or mirrored symbol are written level and centred, clear of the labels at its pins.
- KiCad schematics are read into a typed sheet (symbols, labels, no-connect flags, sheet references, embedded symbols) with every other child kept in place: `fenolite.backends.kicad.sch.read_schematic`, `rebuild_schematic`, `roundtrip_schematic`, `sheet_files`, `components` and `hierarchy_components`, and the model `fenolite.model.schematic.SchematicSheet` with schema `fenolite.schematic.v0`. Round trips are proved over the demo schematics: RT0 and RT1 pass on the 125 readable demo rows and on two third-party schematics re-saved by KiCad 10 (`H-K-SCH-READ`, `H-K-SCH-RT1`), and the components read from 34 demo projects on 10.0.6 and 31 on 9.0.9 equal those of `kicad-cli sch export netlist` (`H-K-SCH-COMPONENTS-2`). The token fuzz has load checks for schematics and symbol libraries, and the token inventory covers schematic and symbol-library tokens: 49 rows and one form row of kinds `kicad_sch` and `kicad_sym`, each proved by the fuzz on 9.0.9 and 10.0.6 (`H-K-SCH-TOKENS`); a symbol-library row also matches inside a schematic. (c0060).
- `fenolite check` runs KiCad's ERC (`erc.kicad`) on the project's schematic and reports schematic parity findings of the DRC run (c0062). ERC violations are `kicad.erc.<type>` issues located as `REF-PIN`, `REF` or a label text; parity entries are `kicad.drc.<type>` issues, and `kicad.drc.parity-unchecked` says when KiCad could not compare the board with its schematic. The copy of a project that `kicad-cli` sees now holds the schematic, its sheet files, `sym-lib-table` and the project's symbol libraries. In a manifest, a sheet, a symbol library and the symbol table reach `native-verified` through that stage.
- `fenolite netlist`: components and nets of a KiCad project as JSON, from `kicad-cli` or from Fenolite's own reading of a generated schematic; `build` refuses a schematic whose netlist differs from the circuit; `check` compares the schematic's netlist with the model and the board (c0063). The own reading equals the export of `kicad-cli` 9.0.9 and 10.0.6 on the examples and on 25 generated designs.
- New command `parity` and `check` stage `parity`: schematic against board and symbol pins against footprint pads, without KiCad for generated projects, cross-checked with KiCad's parity test when it runs. Its counts per type equal KiCad's on the public demos of 9.0.9 and 10.0.6 (c0072).
- `fenolite bom` and `fenolite pnp`: the bill of materials and the placement table of a project as neutral tables, rendered to CSV through a user-written column template (names, order, grouping, units, origin, side names, rotation rules); no template of any assembly service ships. The bill has two sources: the model (`--source model`) and `kicad`, the default, whose parts come from `kicad-cli sch export bom` on a copy of the project's schematic, one row per reference, and Fenolite groups them under the user's column template. Options `--kicad-cli` and `--timeout`; code `bom.field-unsupported`; `counts.left_out` is `null` for this source. Measured on KiCad 9.0.9 and 10.0.6: the export's rows (`H-K-BOM-CSV`), the parts of a built model equal to KiCad's (`H-K-BOM-MODEL`) and the placement rows (`H-K-POS-ROWS`) are `KICAD-VERIFIED` (c0064; guide `docs/assembly.md`).
- `fenolite manifest`: a project manifest with the SHA-256 and a state (`generated`, `checked`, `roundtrip-ok`, `native-verified`) for every design file and artefact, and `--verify` to compare it with the files on disk; `--manifest` on `export`, `render`, `bom` and `pnp` now merges into the folder's manifest instead of replacing it. Each entry says in `held` what its next state is missing. A state is read from the stages of `check` and never says more than they do: a board is `native-verified` when KiCad's DRC reports no error, a file made from it stops at `checked`, and a schematic, its symbol libraries and their table are `native-verified` when KiCad's ERC reports no error. Manifests written by v0.1 are still read (c0065; guide `docs/exports.md`).
- New commands `diff`, `roundtrip`, `fmt`, `explain`, `restore`, `net`, `region` and `neighbors`; `--limit` and `--cursor` page a command's main list, `--format concise` keeps one issue per code; receipts carry an `id` and the `undo` command (c0066). `diff` lists the exact differences between two boards, libraries or built models (a moved footprint is one change) and has a tree view of two KiCad files; `roundtrip` says whether a file survives RT0, RT1 and, through `kicad-cli`, RT2; `fmt` writes Fenolite's canonical print, a fixed point over the corpus; `explain` knows every error and issue code; `restore` puts back the backups of a confirmed write and deletes nothing. `diff` compares two schematics in its model view (`diff_sheets`: symbols by reference and unit, sheet references and embedded symbols by name, labels and no-connect flags by content), and `roundtrip` reaches RT1 on a schematic through the schematic reader's rebuild. The fixed point of `fmt` is measured over the 132 schematic rows of the corpus as well. `roundtrip --level rt2` also judges the schematic of a project (`result.rt2.schematic`): KiCad's ERC on the project and on Fenolite's re-dump of its sheets must give the same kinds of violations, the sheet, type, severity and exclusion of each (`ErcReport.kinds()`), and `exact` says whether the items agreed too. The item KiCad names for one violation can differ between two runs on one unchanged project, on 9.0.9 and on 10.0.6, so the items are not compared; a project on which the kinds do not repeat is not judged.
- `capabilities` lists `result.matrix`: for each backend and file kind, the evidence level of `detect`, `read`, `write`, `roundtrip_exact` and `roundtrip_modified`, the hypotheses behind it and the operations that are experimental. Every backend module now declares its evidence, and `docs/evidence/matrix.md` is generated from the declarations (`tools/gen_evidence_matrix.py`, with `--check`). A backend module without a declaration fails `tests/unit/backends/test_evidence_declared.py`, whose message says what to add, and every declared level is held to `docs/hypotheses.md`. The KiCad backend lists the write kind `kicad_lib_table`, and the Altium schematic reader's evidence no longer names the refuted `H-A-RD-SCH-TEXT` (c0067).
- `moved()` takes module paths and `moved_net()` renames nets without losing their routing; a footprint renamed through an alias keeps its KiCad edits (its uuids and its group memberships follow the new path); `fenolite sync --to-source` writes `placements.toml`, which `build` reads beside the script, for both targets and with `--discard-layout` too; `sync --check` fails when the committed file is stale, and `sync` reports what the next build would drop (`sync.orphan`, `sync.net-dropped`, `sync.value-differs`). `sync` also writes `schematic-placements.toml` from the symbols moved in KiCad's schematic editor, and reports a symbol it cannot hold with `sync.symbol-off-grid` (c0069).
- Six more rule kinds (hole to hole, hole clearance, annular width, courtyard, silkscreen, creepage) in the model, the `.kicad_dru` writer and reader, and `design.rules.rule()` with selectors from `fenolite.dsl.select`. Each kind is written only for the KiCad majors that enforce it: creepage rules are written for KiCad 10 only, and a build for KiCad 9 refuses them unless `--allow-lossy` drops them. A hand-written rule of one of these kinds is now read into the model instead of being kept opaque (c0071).
- Exact `Quantity` values in the DSL (`ohm("4k7")`, `farad("100n")`), typed `I2C`, `SPI`, `UART` and `USB2` interfaces with `attach` by role, and build warnings for differential-pair names KiCad does not pair (`build.diff-pair-name`) and for I2C lines without a pull-up (`build.i2c-pullup-missing`). A `Part` value given as a quantity is stored as its canonical text (`4.7kΩ`). KiCad 9.0.9 and 10.0.6 pair two net names that are equal except for a last `P`/`N` or `+`/`-` (c0073).
- `design.sheet()` and `design.title_block()` put the user's drawing sheet and title block on the board, and on the schematic when a build writes one: the build writes `<name>.kicad_wks` from a `.kicad_wks` or `*.sheet.toml` beside the script; `fenolite export --preset` applies the user's fab options from a TOML file; board outlines join endpoints closer than 10 µm and include footprint edge items, so all 21 demo boards close; stitching avoids rule areas that forbid vias and the board edge. KiCad 9.0.9 and 10.0.6 close an outline across a gap below 10 µm (c0074).
- New in the DSL: `Part.zone_connection`, `arc_to`, and `kind=` for vias; `build` reports `result.copper.arcs` and `result.preserved.pad_zones`. New command `pads` (c0068).
- DSL symbol authoring: design-attached `Symbol` definitions resolve custom component pins and are written as project-local KiCad symbol libraries with a `sym-lib-table` (c0058).
- Footprint DSL: `Footprint.pad(..., shared=True)` can author additional physical pads with the same number as an earlier pad, with stable unique IDs; accidental duplicates still fail.
- An offline catalog authored for Fenolite: 49 generic schematic symbols (passives, semiconductors, protection, power and control parts, electromechanical parts) and 100 footprint variants (chip and MELF parts, small-outline diodes and transistors, SOIC, TSSOP, MSOP and SSOP, QFN and DFN, QFP, DIP, 2.54 mm headers, connectors, buttons, radial and axial parts, mounting holes, a test point), with discovery through the API and `fenolite catalog`, resolution at build without a fetch, and project overrides. Every entry cites its public source; a symbol states a function and not a pinout, and a footprint is assigned in the script, never guessed. Land patterns are `INFERRED` starting points that need a review per part and process. Body outlines are on `F.Fab`, so silkscreen does not cross copper (c0075, c0076).
- Symbol definitions and DSL-authored symbols now carry ordered vector body graphics, which the KiCad symbol reader and writer preserve; the writer also keeps hidden pin-name and pin-number settings on a round trip (c0075, c0076).
- The `altium` backend reads `.PrjPcb`, `.SchDoc`, `.SchLib`, `.PcbDoc` and `.PcbLib` into the neutral model (nets from wires, labels, ports, power ports, buses and harnesses); a project read links footprints to schematic components by unique-id path and PCB nets by name. On four public Altium-saved projects from four repositories the schematic netlist equals the pad netlist of the PCB document, and the board import agrees with `kicad-cli pcb import` 10.0 (c0043).
- Model: `Circuit.buses` (`Bus`, `BusMember`), `PadstackLayer.offset`, and `ComponentBody` on footprint instances and definitions, with the findings `model.duplicate-bus-index` and `model.body-height`; all additive, the schemas are regenerated (c0043).
- `fenolite.backends.altium.read.bodies` decodes the component-body records of PCB documents and libraries byte for byte (c0043).
- Altium schematic reader: `fenolite.backends.altium.read.sch.read_schematic` reads `.SchDoc` and `.SchDot` files (binary and ASCII), and `read.schlib.read_schlib` reads `.SchLib` files into typed records with an owner tree. Unknown keys, records, streams and trailing bytes are preserved; streams rebuild byte for byte. Nine schematic and nine library rows join the corpus, and `tools/altium_census.py` reports their census (c0040).
- Altium PCB reader: lossless typed readers for Altium `.PcbDoc` and `.PcbLib` files preserve record bytes and keys, accept long and short record forms, and report located issues with strict mode available. Checked against eleven public files and KiCad CLI import/upgrade (c0041).
- Altium verification: `fenolite check` and `fenolite inspect` accept Altium documents and projects, read-only and without external tools; the round-trip levels RT-A0 (container copy), RT-A1 (records per stream) and RT-A2 (model → Altium → model on built projects, for what the built model holds: the circuit and the net classes); `fenolite diff A B` reads Altium inputs in its model view and gains a records view (`--view records`) for two Altium files of one kind; results over the public corpus in `docs/evidence/altium-roundtrip.md` (c0044).
- Design equivalence: `fenolite equivalent A [B] --level N` compares two designs at levels 1 to 4 (components, netlist as `REF-PIN` sets, footprints and pads, placement) with located differences, integer tolerances (`--tolerance-nm`, `--tolerance-udeg`), `--frame relative` and exclusion profiles; `--against kicad-import` compares Fenolite's read of a PCB document with `kicad-cli pcb import` (10.0 only) under a per-version exclusion list; results per corpus row in `docs/evidence/equivalence-triangle.md` (c0045).
- Altium sheet templates: `fenolite template import SRC --target kicad --out OUT` imports a `.SchDot` (or the template graphics of a `.SchDoc`) into the neutral drawing sheet and writes a `.kicad_wks`; size, lines, rectangles, texts, special strings and embedded PNG images are imported, everything else is reported, and a loss needs `--allow-lossy`. Writing a `.SchDot` is not included (c0046).

### Changed

- Built projects change once. The next build of a v0.1 project adds the schematic files, with new files under `sheets/` and new footprint paths for parts in modules, and renames, in the board file only, the nets of unconnected pads (`unconnected-(U1-PA1-Pad2)`) and of nets with a slash (`mod{slash}LED_A`). Layouts, positions, tracks and zone fills are kept, and no other net is renamed (c0061, c0070).
- `fenolite check`: the `erc.lite` stage is removed from KiCad checks (`--stages erc.lite` is now a usage error), and the hermetic stage list is `--stages model.validate,roundtrip` (c0062). `fenolite check` now treats a pad on no net as a block of its own, reads the `N/C` label of the IPC-D-356 export as no net, and names a model pin by its pad when the part has a `pad_map`.
- `check` and the copper guard of `build` now apply a zone's own clearance between a fill and other copper, as KiCad's DRC does, and place the copper of a pad with an offset drill where KiCad places it: boards may gain `copper.clearance` findings of source `zone` and lose false ones on such pads (`--copper-check warn` writes anyway). `BoardPad.hole` of such a pad is back at the pad's position. The facts are measured on KiCad 9.0.9 and 10.0.6 (c0068).
- `fenolite capabilities` lists two backends, `altium` before `kicad`: select a backend by its `name`, not by its position (c0043).
- A component whose value is empty in the script is stored in the built model of an Altium build with the value its documents hold, the symbol's name (c0044).
- Examples: `examples/blink_2layer` marks its 29 unused pins with `no_connect` and `examples/blink_routed` marks its unused pins, so their schematics pass KiCad's ERC; the boards are unchanged, and the blink gets its resistor beside the controller pin on the sheet. `examples/blink_official` connects the analog supply pins of its microcontroller and marks its unused pins: KiCad's ERC reports nothing on it (it reported 29 errors and one warning). An authored symbol library for KiCad 9 now carries the 9.0 header version (`20241209`, was `20231120`).
- Development: Archived the completed specs of c0040 to c0046, c0060 to c0069, c0071 to c0076 and c0082, and cited their CI runs in the hypothesis register. A nightly job, `macos-app`, runs the KiCad tests on the `kicad-cli` of the 10.0.6 macOS disk image. The worksheet version oracle runs on fresh copies with its own configuration folders (c0082); the oracles of the Altium readers share one table of the corpus rows on which the Linux build of `kicad-cli` 10.0.6 fails in its own importer; a cost test of the Altium schematic reader counts calls instead of comparing times; cross-platform path assertions were repaired. None of this changes what the command line or the library does.

### Fixed

- `route` no longer hands a router the one-pad `unconnected-(…)` nets that a build gives unused pins since the schematic writer: with them Freerouting left one connection of the 40-part example open.
- A component read from an Altium PCB document takes the designator text the board shows as its reference, and its source designator only without one, so the components of a repeated sheet no longer share a reference in a board read on its own; the fault was found by the equivalence triangle (c0045).
- `fenolite bom` no longer puts a part marked "do not populate" (DNP) on the line of fitted parts of the same value: with `exclude_dnp = false` in the column template, a line is all DNP or all fitted, whether or not `group_by` names `dnp`, for both sources, so no quantity counts a part that is not fitted. A DNP line stands where its first reference puts it, like every line. With `--against`, the `key` of a DNP line ends with `DNP` (c0094; guide `docs/assembly.md`).

### Fixed

- Windows: `kicad-cli.exe` is found on `PATH` and in KiCad's default install folders, which KiCad's installer does not put on `PATH`; files Fenolite writes keep LF line ends; a board on another drive than the working folder can be routed; a drawing-sheet path starting with `/` counts as absolute.
- `fenolite route` reads the net classes from the project file beside the board. Before, every net was routed with the default track width, clearance and via size, whatever its class said: a KiCad board holds no net class.
- `fenolite route --router freerouting` lists a net under `unrouted` when Freerouting reports that it left one of its connections open. Before, a net with any copper counted as routed, so a partly routed net was reported as done; KiCad's DRC in `fenolite check` still found it.
- A board whose rotated pad or rotated footprint carries a slotted hole is read and written again, and its footprints can be written as library files: the writer refused them (`KiCad writer cannot represent this slot rotation`, `KiCad oval drills can encode only horizontal or vertical slot axes`). `Padstack.hole_rotation` is now the slot's axis in the pad's own frame everywhere; on a board it used to include the pad's angle.
- Geometry: the documented and tested bound of two successive `Transform.apply` calls is `(1 + |cos θ| + |sin θ|)/2` nm per axis, at most `(1 + √2)/2 ≈ 1.2071` nm, not 1 nm; `test_composition_rounds_once` no longer fails at random, and a test reaches the bound exactly. No code changes (c0050).
- Script copper in the Altium build (change c0053): `fenolite build --target altium` now writes the tracks, vias and stitching vias that the design script declares (`Design.track`, `Design.via`, `Design.stitch`) into the experimental `<name>.PcbDoc`; before, they were left out without an issue. An intent that does not resolve refuses the build, an intent that creates nothing is reported, and with `--copper-from` the board wins with one `altium.not-lowered` info.
- `fenolite check` no longer reports `kicad.drc.rules-not-loaded` for rules that were loaded on a board with 499 or more clearance violations: `kicad-cli` stops reporting clearance violations near 499 per run and can leave the canary's own out, so such a run is now `inconclusive` with the reason `clearance-limit` (`kicad.drc.rules-unchecked`). The two-run canary test compares two DRC runs against what was measured to repeat, and the contract says which part of `check`'s output repeats between runs (c0051).
- Altium PCB document in the form Altium saves: `<name>.PcbDoc` now holds the whole `Board6` record (board keys, the outline as a polygon, sheet, sub-stack, drill pair, routing keys and snap grid, written by rule in `docboard.py` on top of `libboard.py`), net and component records with the common keys and unique ids, `UniqueIDPrimitiveInformation`, the option storages (`Advanced Placer Options6`, `Pin Swap Options6`, `Design Rule Checker Options6`, `PadViaLibrary`, `PadViaLibraryCache`, `LayerKindMapping`, `ConstraintManager`, `SignalClasses`) and 13 more empty storages; `write_pcbdoc` takes the file name. The first form gave a "catastrophic" error in Altium Designer 26.5 (maintainer's report, c0035); the new one opens there and its change order from the schematic reports no difference (author report of 2026-10-03). Texts, pads, tracks and arcs keep their short records.
- Altium PCB library opens in Altium Designer's form: `<name>.PcbLib` now holds the 53-byte `FileHeader` (version and library id), the whole board record in `Library/Data` (layer stack, grid, layer sets and view keys, written by rule in `libboard.py`) and the `Library` side streams (`EmbeddedFonts`, `ModelsNoEmbed`, `Textures`, `ComponentParamsTOC`, `PadViaLibrary`); `FileHeaderSix` of `<name>.PcbDoc` carries its id. The first form gave a "catastrophic" error in Altium Designer (maintainer's report, c0035); the new one opens in Altium Designer 26.5 (author report of 2026-10-03).
