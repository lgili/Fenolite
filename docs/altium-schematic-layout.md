# Native Altium schematic layout

Generate a project with Fenolite, organise its sheets in Altium Designer, save them, and synchronise
the native presentation into the source folder. Later builds replay the saved sheets byte for byte.

```bash
fenolite build design.py --out build/altium --target altium --confirm --json
# Open the project in Altium, adjust the sheets, and save every document.
fenolite sync design.py --out build/altium --target altium --to-source --dry-run --json
fenolite sync design.py --out build/altium --target altium --to-source --confirm --plan PLAN_ID --json
fenolite build design.py --out build/altium --target altium --dry-run --json
fenolite build design.py --out build/altium --target altium --confirm --plan BUILD_PLAN_ID --json
```

Use the plan IDs returned by each dry-run. For module sheets, pass the same `--altium-sheets modules`
to each build; keep the same `--altium-format` and other generation options.

## What is saved

`altium-schematic-layout.json` beside the design script holds the exact bytes of every edited generated
sheet, base64 encoded, with its checksum and the checksum of its original generated baseline. Keep this
file with the source. It works when building into a new output folder as well.
If saving changes a document from ASCII to binary, replay retains its saved form. Planned write kinds
reflect the actual document bytes, and `result.schematic_layout.formats` lists the native forms per sheet.
`result.schematic_format` remains the format used to generate the baselines.

Saving complete native documents retains component and unit positions, rotations and mirrors, reference
and value text positions and appearance, wires, junctions, labels, ports, drawing-sheet presentation,
embedded assets and other streams. It preserves what the edited `.SchDoc` already contains: it cannot
restore an omitted logo until that logo is applied in Altium and the sheet is saved.
Externally linked assets retain their references and must remain available; the snapshot embeds only
data already present in the native documents. Font files and the `.PrjPcb` are not copied into it.

This snapshot contains the project's native data and assets. It belongs with that project's source;
private snapshots must never be committed to the Fenolite repository.

The generated originals remain under `DIR/.fenolite/altium-generated/`, tracked by the build receipt.
Do not edit those baselines. Builds made before this feature have no baseline: create a fresh build in
another folder, then reproduce and save the layout edits on that generated project before synchronising.
The command cannot certify unrelated older documents as edits of its baseline.

## Electrical verification

Before saving, sync reads the complete generated and edited sheet sets and compares their component
unit IDs, symbol and footprint assignments, pin-to-pad maps, pin identities/types, parameters, net memberships,
no-connects, buses and harnesses. Component IDs must stay intact. Reannotation, changed values, changed
symbols and changed wiring are circuit conflicts, rather than presentation edits. The Python script
remains the source of the circuit. Unknown schematic records and reader or netlist warnings refuse
capture because their electrical meaning cannot be verified. Unknown container streams are preserved.

The project must list exactly the generated sheet set and retain the generated netlist options. The
`.PrjPcb`, PCB layout, libraries and output jobs are outside this capture. Extra schematic documents are
refused rather than silently omitted. The saved snapshot is checked again before replay.

Evidence is `INFERRED`: these checks use Fenolite's own reader, not native Altium compilation or ERC.
Synthetic tests establish capture/replay behaviour, not native-tool acceptance.

## Conflicts and recovery

| Finding | Meaning | Action |
|---|---|---|
| `sync.altium-connectivity-changed` | The saved document changes a component, symbol, parameter or circuit connection | Resolve the difference between the native file and the Python source before syncing |
| `sync.altium-unverified` | A baseline is absent or modified, a sheet is missing, IDs are ambiguous, project options differ, or input cannot be verified | Restore the complete generated project and resolve the reported finding |
| `build.altium-layout-conflict` | The fresh generated bytes of a saved sheet changed, or that sheet was removed | Keep the snapshot and resolve the source change; no output is written |
| `sync.would-change` | `sync --check` finds the snapshot absent or stale | Review and confirm a new sync |

Any conflict refuses the whole write transaction. Adding a component to a saved sheet also changes its
baseline and is refused. A new sheet without a saved entry is generated normally when all saved sheets
still generate their exact original baselines; introducing a module often changes its parent too and
therefore conflicts. Incremental merging of changed sheets is outside this version.

To intentionally regenerate a conflicting project, archive or move `altium-schematic-layout.json`
outside the script's folder, build into a new output directory, and transfer the desired presentation in
Altium before synchronising again. Keep the old project and snapshot until the new layout is reviewed.
`--discard-layout` does not override a source snapshot.

`sync --check` writes nothing and exits 5 if a capture would change or cannot be verified. Sync and build
use the ordinary review/confirm/receipt protocol; editing an input after reviewing its plan gives
`FEN-4002`, exit 4. A reviewed build binds the snapshot even when it did not exist during review.
