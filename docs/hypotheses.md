# Hypothesis register

Every claim that is not yet verified is a hypothesis with a test or an acceptance-kit request that
settles it.

- Ids keep three prefixes: `H-A-` (second backend), `H-G-` (general and model) and `H-K-` (KiCad).
- Rows about a tool that acts on KiCad files use `H-K-`, and routing rows are `H-K-KRT-*`. Specctra
  DSN/SES rows are `H-G-DSN-*`, with backend `specctra`.
- A refuted row keeps its id. Its level is the level of the run that refuted the claim, and its result
  starts with `refuted; superseded by <successor id>`. A refuted row never counts as release support.
  A result that starts with other text, such as `partly refuted`, is not a refutation.
- An author-report row (level `ALTIUM-VERIFIED(author-report; …)`) never raises an operation to
  verified.
- `tests/unit/test_hypotheses_register.py` checks this register and every hypothesis id cited in the
  repository's live text; `fenolite.verify` reads it.

Reserved families: ids that no row extends yet but that later changes will register.
