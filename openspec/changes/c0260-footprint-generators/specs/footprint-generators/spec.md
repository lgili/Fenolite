## ADDED Requirements

### Requirement: Public per-family footprint generators
`fenolite.catalog.footprints.generate(package, *, density="nominal") -> Generated` SHALL draw a footprint from one `fenolite.package.v0` record (c0259) by its `family`: `chip`, `molded`, `gullwing`, `nolead`, `grid`, `to`, `dip`, `header` or `connector`. It MUST be pure (no file, clock or environment). `Generated` holds `footprint` (`None` on an error finding), `land`, `stamp` and sorted `issues`.

#### Scenario: A gull-wing record is drawn
- **GIVEN** the authored record `tests/data/packages/soic8.toml` of family `gullwing`, 8 pins, pitch 1.27 mm, `drawing = 1`, `lands = 1`
- **WHEN** `uv run pytest tests/unit/catalog/footprints/test_generate.py -k gullwing` calls `generate` on it twice
- **THEN** both results are equal, the footprint has pads `1` to `8` and no issue of severity error

#### Scenario: Unknown family
- **WHEN** a record with `family = "spiral"` is read
- **THEN** `FormatError` with code `FEN-3004` is raised naming `family`

### Requirement: Family parameter keys
Each family SHALL accept exactly the keys listed for it in `docs/footprint-generators.md` (design decision 2), plus `[generate]` (`lands`, `drawing`, `density`) and an optional `[land]`. A missing required key, an unknown key or a wrong type MUST raise `FEN-3004` naming the file and the key. `drawing` MUST always be given; `lands` MUST be given when the calculator is used.

#### Scenario: Missing pitch
- **WHEN** a `gullwing` record without `pitch` is read
- **THEN** `FEN-3004` is raised naming `pitch`

#### Scenario: Calculator without a table version
- **WHEN** a record with no `[land]` and no `lands` key is generated
- **THEN** `FEN-3004` is raised naming `lands`

### Requirement: Exact length ranges
`fenolite.core.quantities.LengthRange(min, nom, max)` SHALL hold integer nm bounds, each optional. The spellings `"1.27mm"`, `"a..b"`, `"x max"`, `"x min"` and a `{min, nom, max}` table with units `mm`, `um`, `mil` and `in` MUST be parsed exactly; a value that is not whole nm, or bounds out of order, MUST raise `FEN-3004`. The nominal is `nom`, else `(min + max) // 2`.

#### Scenario: Range spellings
- **WHEN** `uv run pytest tests/unit/core/test_length_range.py` parses `"4.80mm..5.00mm"`, `"1.75mm max"` and `"50mil"`
- **THEN** it gets `(4800000, None, 5000000)` with nominal `4900000`, `(None, None, 1750000)` and `(1270000, 1270000, 1270000)`

#### Scenario: Sub-nanometre value
- **WHEN** `"0.0000005mm"` is parsed
- **THEN** `FEN-3004` is raised naming the value

### Requirement: Worst-case land calculation
For facing land rows the calculator SHALL compute, in integer nm, `Z = L.max + 2·Jt`, `G = L.min − 2·T.max − 2·Jh` and `X = W.max + 2·Js`, round Z up, G down and X up to the table's grid, and place pads of length `(Z − G)/2` at row distance `(Z + G)/2`. A needed bound that is missing MUST give the error `package.missing-bound`. No float and no square root of a sum of squares of tolerances is used.

#### Scenario: Calculated SOIC land
- **GIVEN** `soic8.toml` without `[land]` and a test table with `Jt = 300 µm`, `Jh = 100 µm`, `Js = 50 µm`, grid 10 µm
- **WHEN** `uv run pytest tests/unit/catalog/footprints/test_lands.py -k soic` generates it
- **THEN** `land.z == 6800000`, `land.g == 3060000`, `land.x == 610000`, and the pads are 1870000 nm long at row distance 4930000 nm

#### Scenario: Missing bound
- **WHEN** a record whose `span` is `"6.20mm max"` is generated by the calculator
- **THEN** the result has no footprint and one error `package.missing-bound` naming `span` and `min`

### Requirement: Fenolite-authored land constants
The goals, `pad_gap`, `grid`, `courtyard`, `hole_clearance`, `annular_ring`, `ball_ratio` and paste values SHALL be Fenolite-authored, held per version in `fenolite.catalog.footprints.lands.LANDS` and published with their derivation in `docs/formats/library/lands.md` labelled `INFERRED`. A released version MUST NOT change. No value MAY be taken from IPC-7351 tables or calculator.

#### Scenario: Published table equals the code
- **WHEN** `uv run pytest tests/unit/catalog/footprints/test_lands.py -k published` reads `docs/formats/library/lands.md`
- **THEN** every constant of `LANDS[1]` appears there with its value, its label `INFERRED` and its derivation

### Requirement: Calibration of land goals
`tools/calibrate_lands.py` SHALL derive each land class's goals from the package records that give both toleranced dimensions and a cited manufacturer `[land]`: back-solve each goal, take the lower median, round to 10 µm. `--check` MUST fail when the table differs. A class with fewer than three such records MUST have no goals, and generating it without `[land]` MUST give the error `package.no-goals`.

#### Scenario: Calibration is reproducible
- **WHEN** `uv run python tools/calibrate_lands.py --check` runs
- **THEN** it exits 0 and lists, per class, the records it used

#### Scenario: Uncalibrated class
- **GIVEN** a land class with two calibration records
- **WHEN** a record of that class without `[land]` is generated
- **THEN** there is no footprint and one error `package.no-goals`

### Requirement: Nominal density only
`density` SHALL default to `nominal`, the only value shipped. `compact` and `robust` MUST raise `FEN-3004` with a message that names them as reserved; any other value MUST raise `FEN-3004`.

#### Scenario: Reserved density
- **WHEN** `generate(package, density="compact")` is called
- **THEN** `FEN-3004` is raised and the message says `compact` is reserved

### Requirement: Pad gap is kept
When two neighbouring lands of different numbers would be closer than `pad_gap`, the generator SHALL narrow or shorten the land, floored to the grid, and give the warning `package.pads-clipped` naming the pads and the lost goal. When a land would have no positive size or gap, it MUST give the error `package.land-impossible`.

#### Scenario: Fine pitch is clipped
- **GIVEN** a 0.5 mm pitch record whose calculated land width leaves less than `pad_gap`
- **WHEN** it is generated
- **THEN** each land is `500000 − pad_gap` nm wide and one warning `package.pads-clipped` is given

### Requirement: Manufacturer land override
A `[land]` table with a `source` SHALL win over the calculator: its numbers are used unchanged and the conventions draw the rest. The description MUST end with `land: manufacturer <source>` (else `land: calculated lands/<n> nominal (INFERRED)`). When the class has goals, `land.deltas` MUST hold the difference per number and an info `package.land-override` MUST name the largest.

#### Scenario: Override recorded
- **GIVEN** `soic8.toml` with `[land]` giving pad 1.52 × 0.60 mm at row spacing 5.50 mm, source `S-0855 soldering footprint` (the onsemi 751-07 footprint)
- **WHEN** it is generated
- **THEN** pads are 1520000 × 600000 nm at x = ±2750000, `land.source == "manufacturer"`, the description ends with `land: manufacturer S-0855 soldering footprint`, and one info `package.land-override` is given

### Requirement: Evidence of generated lands
A calculated land SHALL be labelled `INFERRED` whatever the record's label. A manufacturer land MUST keep the record's evidence label. No generation MAY raise a label.

#### Scenario: Calculated land stays inferred
- **WHEN** a record labelled `CORPUS-VERIFIED` without `[land]` is generated
- **THEN** the land evidence is `INFERRED`

### Requirement: Exposed pad and paste grid
A `nolead` exposed pad SHALL be one land of the `ep` nominal size, numbered `ep_number` (default `EP`), on `F.Cu` and `F.Mask`. Signal lands closer than `pad_gap` MUST be shortened from their inner end. Paste MUST be an `n × m` grid on `F.Paste`, `n = max(2, ceil(side / paste_cell))`, each window 4/5 of its cell per axis, unless `[land].paste` gives the grid.

#### Scenario: QFN exposed pad
- **GIVEN** a `nolead` QFN record with `ep` 1.70 × 1.70 mm, `drawing = 1` and a test table whose `paste_cell` is 3 mm
- **WHEN** it is generated
- **THEN** pad `EP` is 1700000 nm square without `F.Paste`, and four filled `F.Paste` windows of 680000 nm are centred at ±425000 nm

### Requirement: Grid array lands
A `grid` record SHALL give one round land per ball, of diameter ball nominal × `ball_ratio[pad]` rounded to the grid. Rows MUST be lettered from `A` skipping `I`, `O`, `Q`, `S`, `X`, `Z`, then `AA`; columns numbered from 1; `A1` top left. Depopulated names or a `center` block MUST be left out; one outside the grid MUST give `package.dimensions-inconsistent`.

#### Scenario: Depopulated centre
- **GIVEN** a 10 × 10 grid record with `depopulated = { center = "4x4" }`
- **WHEN** it is generated
- **THEN** it has 84 lands, no land `E5`, and the row after `H` is `J`

### Requirement: Through-hole lands
For `dip`, THT `to`, `header` and `connector` the drill SHALL be the lead diagonal (the integer square root of `w.max² + t.max²` rounded up, or `w.max` for a round lead) plus `hole_clearance`, rounded up to the grid, and the pad diameter drill plus twice `annular_ring`. A pad wider than `pitch − pad_gap` MUST become an oval of that width with `package.pads-clipped`. Under `drawing/1` pad 1 MUST be square.

#### Scenario: DIP drill
- **GIVEN** a `dip` record with lead width max 0.56 mm and thickness max 0.38 mm and a test table with `hole_clearance = 230 µm`
- **WHEN** it is generated
- **THEN** every drill is 910000 nm (676 757 nm diagonal plus clearance, rounded up to 10 µm)

### Requirement: Pad numbering and orientation
Under `drawing >= 1`, dual rows SHALL be numbered from the top of the left row (pin 1 at the most negative y of the library frame, X to the right and Y down) counter-clockwise in the top view, and quad rows likewise from the upper left. Under `drawing/0` the rows MUST keep the placement of the 0.6 helpers `_row_pads` and `_quad_pads` (pin 1 at the most positive y), so that the migrated catalog keeps its bytes. `sides` records MUST place each side's `numbers` at its `positions` on the pitch grid, position 0 at the top. Pads on perpendicular sides MUST have perpendicular long axes. Polarized two-terminals put the cathode on pad 1.

#### Scenario: Dual-row top view
- **WHEN** `soic8.toml` (`drawing = 1`) is generated
- **THEN** pad 1 lies on the left at y = −1905000, pad 4 on the left at y = +1905000, pad 5 on the right at y = +1905000 and pad 8 on the right at y = −1905000

#### Scenario: SOT-23 sides
- **GIVEN** a `gullwing` record with `arrangement = "sides"`, left numbers `["1", "2"]` at positions `[0, 2]` and right `["3"]` at `[1]`
- **WHEN** it is generated
- **THEN** pads 1 and 2 lie on the left at y = −pitch and +pitch and pad 3 on the right at y = 0

### Requirement: Generated courtyard
The courtyard SHALL be one `F.CrtYd` rectangle: the bounding box of the nominal body and every pad plus the table's `courtyard` excess, rounded outward to the grid under `drawing >= 1`. It MUST contain every pad and the body outline.

#### Scenario: Courtyard contains everything
- **WHEN** `uv run pytest tests/unit/catalog/footprints/test_courtyard.py` generates every test record
- **THEN** each courtyard contains every pad and body vertex with at least the `courtyard` excess

### Requirement: Versioned drawing conventions
`drawing/0` SHALL reproduce the 0.6 catalog drawing (fabrication rectangle, courtyard, pin-1 line, cathode line, rectangular pads, no silkscreen, no model). `drawing/1` MUST add a chamfered fabrication outline, silkscreen, a pin-1 mark, polarity bars, rounded SMD pads and a STEP model path, with constants in `lands.md`. A released convention MUST NOT change.

#### Scenario: Drawing 1 pin-1 marks
- **WHEN** a `drawing = 1` gull-wing record is generated
- **THEN** the `F.Fab` outline has a chamfer at the pin-1 corner and one `F.SilkS` circle lies outside the body beyond pad 1

### Requirement: Silkscreen keeps clear of copper
Under `drawing >= 1` no silkscreen graphic SHALL come within the convention's silk-to-copper gap of any pad, and no silkscreen piece shorter than the convention's minimum MUST remain.

#### Scenario: No silk on copper
- **WHEN** every `drawing = 1` test record is generated
- **THEN** the distance from every `F.SilkS` stroke edge to every pad is at least the gap of `lands.md`

### Requirement: Generated bodies
A generated footprint whose record gives a body height SHALL hold `ComponentBody(kind="extruded")` entries with signed bounds: `body` (nominal outline, `z_min` the standoff min or 0, `z_max` the height max or nominal), one per lead or pin (`lead:<n>:foot`, `lead:<n>:shoulder`, `pin:<n>`, `tab`), through-hole pins below the board with negative `z_min`. Round outlines MUST be 32-gons from an integer table.

#### Scenario: SOIC bodies
- **WHEN** `soic8.toml` is generated
- **THEN** its `body` has `z_min == 100000`, `z_max == 1750000` and a 4900000 × 3900000 nm outline, and 16 lead bodies follow

### Requirement: Fenolite STEP writer
`fenolite.backends.step.write_bodies(name, bodies, *, timestamp)` SHALL write an ISO 10303-21 file in schema `AUTOMOTIVE_DESIGN` with one product `name` and one closed planar B-rep solid per extruded body, in mm with exact decimals printed from nm, colours by body name, stdlib only. Equal arguments MUST give equal bytes. Its facts MUST be recorded in `docs/formats/step/part21.md`.

#### Scenario: Deterministic and closed
- **WHEN** `uv run pytest tests/unit/backends/test_step.py` writes the bodies of `soic8.toml` twice and reads them with the test reader
- **THEN** the bytes are equal, every reference resolves, every solid has V − E + F = 2, and no number has an exponent

#### Scenario: KiCad reads the models
- **GIVEN** a built board whose parts use three `drawing = 1` generated footprints
- **WHEN** `uv run pytest tests/kicad/export/test_generated_models.py -rA` runs `fenolite export step` on KiCad 9 and 10
- **THEN** the STEP holds three `NEXT_ASSEMBLY_USAGE_OCCURRENCE` and no line says `Could not add 3D model`

### Requirement: Generated STEP models in a build
A `drawing >= 1` footprint SHALL name `${KIPRJMOD}/lib/<library>.3dshapes/<name>.step` in `models`, and `fenolite build` MUST plan that file from the footprint's bodies with `write_bodies`. A footprint without such a path MUST NOT get a model, so builds that use only `drawing/0` footprints keep their bytes.

#### Scenario: Model written beside the library
- **WHEN** a design using `Local:SOIC8_B4.9x3.9_P1.27` from `Footprint.from_package` is built with `--dry-run --json`
- **THEN** the plan holds `lib/Local.pretty/SOIC8_B4.9x3.9_P1.27.kicad_mod` and `lib/Local.3dshapes/SOIC8_B4.9x3.9_P1.27.step`

### Requirement: Naming of Fenolite-authored packages
A generic package SHALL be named `<FAMILY><pins>_B<L>x<W>[x<H>]_P<pitch>[_EP<x>x<y>][_<variant>]` with nominal mm values without trailing zeros, and a package from a manufacturer's own drawing `<FAMILY><pins>_<Maker>_<drawing>`, as `docs/formats/library/naming.md` defines. A generic name that disagrees with its record MUST give the error `package.name-mismatch`.

#### Scenario: Name checked against numbers
- **WHEN** a record named `SOIC8_B4.9x3.9_P1.27` gives pitch 0.65 mm
- **THEN** there is no footprint and one error `package.name-mismatch` naming `P1.27`

### Requirement: Generator stamp and determinism
`Generated.stamp` SHALL name the family generator version, the land source with its table version and density, and the drawing version, and the description MUST carry it. Equal record bytes MUST give equal `FootprintDef`, `.kicad_mod` and `.step` bytes; graphic and body ids MUST derive from the lib id and a role name.

#### Scenario: Stamp in the description
- **WHEN** `soic8.toml` without `[land]` is generated
- **THEN** the stamp and the description contain `gullwing/1 lands/1 drawing/1 nominal`

### Requirement: Dimension consistency findings
Before drawing, the generator SHALL give the error `package.dimensions-inconsistent` for a span not larger than the body width, a pin row longer than the body, a terminal longer than half the body, an exposed pad larger than the body or a depopulated ball outside the grid, and `package.pin-count` when `pins` disagrees with the arrangement. Codes MUST be registered in `explain.toml`.

#### Scenario: Span inside the body
- **WHEN** a gull-wing record with span max 3.5 mm and body width min 3.8 mm is generated
- **THEN** there is no footprint and one error `package.dimensions-inconsistent` naming `span`

### Requirement: Library generate command
`fenolite library generate PACKAGE... --out DIR [--library NICK] [--positions N] [--no-step]` SHALL plan `DIR/<NICK>.pretty/<name>.kicad_mod` and `DIR/<NICK>.3dshapes/<name>.step` per package, writing through `--dry-run` and `--confirm --plan`, all files or none, with a receipt. An error finding MUST give exit 5 and write nothing. `NICK` defaults to `Local`.

#### Scenario: Plan and confirm
- **WHEN** `fenolite library generate tests/data/packages/soic8.toml --out lib --dry-run --json` runs, then the same with `--confirm --plan <plan_id>`
- **THEN** the plan lists the two files, the second run writes them, and the receipt lists both with their SHA-256

### Requirement: Generated footprints in an Altium PCB library
`fenolite library generate` SHALL also plan `DIR/<NICK>.PcbLib`, one Altium PCB library holding every generated footprint, written by the existing Altium library writer (`fenolite.backends.altium.pcblib.write_pcblib`) with the same plan, confirmation and receipt as the KiCad files; `--no-pcblib` MUST leave it out. A generated footprint MUST pass the writer's footprint check (`check_footprint`) without a refusal: rounded-rectangle pads give their corner ratio (`Pad.corner_ratio`), the conventions draw no polygon and no filled shape outside `F.Paste`, and the only items the writer leaves out are the paste windows of an exposed pad and that pad's missing paste opening (Altium holds paste as a pad expansion), which it reports.

#### Scenario: PcbLib read back with equal pads
- **GIVEN** one generated footprint of each family from the records of `tests/data/packages/`
- **WHEN** `uv run pytest tests/unit/catalog/footprints/test_pcblib.py` writes them (with the calibration records and the first two positions of the connector series) into one PCB library and reads it with `fenolite.backends.altium.read.pcblib.read_pcblib`
- **THEN** the library names every footprint, the reader reports no error finding, and each footprint has the generated pads: equal numbers, positions, sizes, shapes and drills, within the writer's documented unit conversion

### Requirement: Library verb dispatch
`fenolite library` SHALL treat a first argument that is a registered verb (`generate`, and the verbs later changes register) as that verb, and any other first argument as the board path of c0223, whose behaviour MUST NOT change.

#### Scenario: Board form unchanged
- **WHEN** `fenolite library examples/blink --out lib/Blink.pretty --dry-run --json` runs
- **THEN** its result equals the 0.6 result for the same input

### Requirement: Library generate result
The result of `library generate` SHALL hold `packages[]` with `name`, `family`, `id`, `stamp`, `land` (`source`, `z`, `g`, `x`, pad sizes, `deltas`), `courtyard`, `bodies` (count and top) and `files`, and `issues` with the `package.*` findings, in record order then position order.

#### Scenario: Result of a connector series
- **WHEN** a `connector` record with `positions = "2..4"` is generated with `--dry-run --json`
- **THEN** `result.packages` holds three entries in position order 2, 3, 4, each with its own name and id
