## Context

- Report of 2026-10-03, Altium Designer 26.5 (trial licence on the maintainer's own PC): "Design »
  Update PCB Document" on the built `examples/altium_hier_board`, after the document-order fix of c0037.
  Components and nets match. The change order proposes: remove the net class `PWR`; add the component
  classes `driver` and `led`; add a room per module sheet; add two "Supply Nets" rules.
- On the flat blink project the earlier report (step D3 of `docs/evidence/altium-pcb.md`) gave "no
  difference". That board held no net class then (c0038 added it later).
- What the board holds today: one `KIND=0` class per net class (c0038). What the schematic holds: no
  class at all. What the project file holds: `[Design]`, `Version=1.0` and one `DocumentPath` per
  document.
- Facts read for this change, all from permitted sources:
  - **Net class directive.** Altium's documentation: a net joins a class through a Parameter Set
    directive that touches its wire, bus or harness and holds the parameter `ClassName`; one directive
    serves the whole net; the option "Generate Net Classes" of the tab "Class Generation" must be on;
    with the Constraint Manager flow the directives are not used (S-0310, S-0311).
  - **The records.** A public Altium-saved sheet (S-0187) holds three such directives: a record 43 at a
    point inside a wire, `Color=255`, `Orientation=1`, `Name=Parameter Set`, a unique id; and one owned
    record 41 with `Name=ClassName`, `Text=<class>`, `IsHidden=T`, `Color=8388608`, `FontID=1`.
  - **The project keys.** Two public saved projects (S-0187, S-0188) hold `[PrjClassGen]` with seven
    keys, `NetClassManualEnabled=1` among them, and three class keys in every document section. The
    maintainer's saved project of the board example (S-0313) holds the same keys with
    `NetClassManualEnabled=0` and `ClassGenCCAutoRoomEnabled=0`.
  - **Component classes.** Four public Altium-saved boards (S-0172, S-0175, S-0199, S-0200) hold one
    `KIND=1` class per sheet: `SUPERCLASS=FALSE`, no `AUTOGENERATEDCLASS` key, the designators as
    members. Its name is the sheet symbol's name (S-0310).
  - **Rooms.** A room is a "Room Definition" rule scoped `InComponentClass('<name>')`; the option
    "Generate Rooms" of the same tab creates one per sheet (S-0310). None of the six boards read holds
    such a rule, so its record is not known.
  - **Supply Nets.** Altium suggests the rule for each net with a power port when the advanced setting
    `Schematic.AutoGenerateSupplyNetsRule` is on (S-0185, S-0312). No board read holds the rule.

- **Report of Part E, 2026-10-04 (AD 26.5), on the first build of this change.**
  - Board example with module sheets: the change order lists only "Add Rules (2): Supply Nets". No net
    class removal, no component class, no room.
  - Flat routed sample: no net class removal, but "Add Component Classes (1): `routed`", "Add Rooms (1):
    Room `routed`" scoped by that class, and the two "Supply Nets" rules. That build held no class key in
    its project file and no component class in its document (Decisions 5 and 8 as first written).
  - So in a flat project Altium derives one component class named after the single sheet, with every
    component, and a room for it.

## Goals / Non-Goals

**Goals.** The change order of a Fenolite build proposes no class change and no room: a flat build
and a per-module build. What stays is listed, with its reason.

**Non-Goals.** Room records, "Supply Nets" rules, comparator options, blankets, differential-pair
directives, component `ClassName` parameters, reading Altium classes.

## Decisions

1. **A Parameter Set directive per net and sheet, not a blanket and not a sheet-level net class.**
   - It is the construct the documentation names first, and a public saved sheet shows its records.
   - One directive per sheet where the net has a stub. One per project would do by the documentation,
     but a net on a module sheet is a separate net until the hierarchy joins it; a directive per sheet
     does not depend on that.
   - *Rejected: a blanket.* Its records are in no file read, and Fenolite's stubs are spread over the sheet.
   - *Rejected: `ClassGenNCAutoScope`.* It makes one class per sheet, named after the sheet; it cannot
     express `PWR`.
   - *Rejected: removing the class from the board.* The class and its rules are verified (step C4),
     and the user wants them.
2. **The directive sits inside the stub, pointing away from the label.** 200 mil from the stub's start
   on a stub of 300 mil or more, 100 mil otherwise: never a wire end, never the label's hotspot (100 mil
   from the start on right and up stubs). `ORIENTATION=3` (downwards) on a horizontal stub, where the
   label text lies above the wire; no `ORIENTATION` on a vertical stub. The saved directives lie inside
   wires too.
   - *Rejected: the wire's end.* On a port stub the end holds the power port.
3. **Upper-case keys, as every record Fenolite writes.** The saved sheet uses mixed case; Altium
   Designer 26.5 accepts Fenolite's upper-case records (author reports of c0033 and c0037).
4. **`[PrjClassGen]` with the seven keys of the saved projects, only when the design holds a net
   class.** Six values are those of all three saved files; `NetClassManualEnabled=1` is the option.
   - A flat design without a net class keeps the verified minimal bytes.
   - *Rejected: one key alone.* No file read holds a partial section, and the defaults of missing
     keys are not known: the maintainer's file saved from the minimal project holds `0` for this one.
5. **Three class keys per schematic document, with module sheets or a PCB document.**
   `ClassGenCCAutoEnabled=1`, `ClassGenCCAutoRoomEnabled=0`, `ClassGenNCAutoScope=None`.
   - First written for module sheets only, because the flat blink project had reported "no difference"
     (step D3). The report of Part E refutes that reading: a flat project is offered a room. The keys now
     go to every schematic section of a project with module sheets or a PCB document.
   - A project without module sheets and without a PCB document keeps the verified minimal bytes.
   - Only schematic documents: the options belong to sheets (S-0310).
   - **Why the flat sample got a room and the board example did not.** They differed in two ways: the
     key in the project file, and the component class in the document. The documentation makes the room
     a product of the sheet's option "Generate Rooms", scoped by the sheet's component class (S-0310), so
     the key is the likelier cause. Whether the class alone would also remove the room offer is not
     known: Altium may add a room for a class that exists. Writing the class is not expected to remove
     the room by itself; both are written now, and step E4 repeats the case (`H-A-ECO-SHEETCLASS`). If a
     room is still listed, the report of the tick "Generate Rooms" separates the two.
   - *Rejected: the keys in every project file.* A schematic-only project has no board to compare.
6. **Rooms are turned off, not written.** Justification: the room rule's record is in no permitted
   source, and a guessed rule could be refused or be proposed for removal. The documented option does
   the same for the change order. If step E3 still shows rooms, they stay a documented difference:
   they are additions.
   - *Rejected: writing a `Rules6` record of an unseen kind.*
7. **Component classes are written into the board, derived from `PlacedComponent.sheet`.** No new
   field in `PcbDocSpec` and no lens change: the module of a component is already there (c0037).
   - Name of a module sheet's class: the module name, which is the sheet symbol's name on the top sheet
     (S-0310). Confirmed by the report of Part E.
   - *Rejected: `ClassGenCCAutoEnabled=0`.* It would also empty the change order, but the classes are
     useful in the board, and the record form is known.
8. **A class for every sheet with a part: the top sheet and the single sheet too.** Their class is
   named after the sheet, which is the stem the PCB document shares with it.
   - First decided the other way, on the "no difference" of step D3. The report of Part E shows the
     offer `routed` for `routed.SchDoc`, and one saved board holds such a class for its top sheet
     (S-0199).
   - One rule for both modes: a sheet's class carries the name Altium shows for the sheet. A sheet
     under a sheet symbol shows the symbol's name; a sheet under none shows its own.
   - The top sheet of a build with modules is treated like the single sheet. No report covers it yet
     (the board example's top sheet holds no part); it follows from the same rule and from S-0199.
   - A module named as the design shares the top sheet's class; no error.
   - Cost: every PCB document changes, so the blink and routed golden documents are rebuilt.
9. **"Supply Nets" rules stay a documented difference.** The record is in no permitted source; the
   proposal is governed by an application setting, not by the project; and executing it only adds
   rules with a voltage of 0. The user may leave the group unticked or turn the setting off.
10. **`altium.not-lowered` changes its message, not its code.** Without a PCB document the members
    of a net class are now in the schematic; only the rule values are kept in the model.

## Risks / Trade-offs

- **The keys may undo the hierarchy fix.** Variant n of step H7 worked with `DocumentPath` alone and
  variant h with Altium's full file; a section with three more keys is between the two. Step E1 checks
  it first. Fallback: drop the per-document keys and accept rooms as a difference.
- **The room of a flat build** (Decision 5): expected to go with the key; step E4 repeats it.
  Fallback: documented difference.
- **Rebuilt golden files.** The author reports of `blink` and `routed` were made on the old schematic
  bytes. The records that those reports verified are unchanged; the new records are appended last.
- **Looks.** A directive may overlap a neighbour stub's label by a few mil on dense symbols. It is a
  drawing matter; connectivity is by the hotspot.
- **A net of a class without any pin** gets no directive, so Altium would propose removing it from the
  board's class. Such a net has no copper either.
- **An existing project file is kept**, so a project built before this change needs its `.PrjPcb`
  deleted, or the two options set by hand in Altium.
