## ADDED Requirements

### Requirement: Atoms keep their spelling
`fenolite.backends.kicad.sexpr` SHALL represent every atom as an immutable `Atom(text, kind)`. `text` MUST be the exact characters of the source, including the quotes of a quoted string. `kind` MUST be `string` for a quoted atom. It MUST be `number` for an unquoted atom that fully matches `-?(\d+\.?\d*|\.\d+)([eE][-+]?\d+)?`. It MUST be `symbol` otherwise. Classification MUST depend only on the lexical form.

#### Scenario: Trailing zeros survive
- **GIVEN** the text `(ratio 12.000000)`
- **WHEN** it is parsed
- **THEN** the child atom has `text == "12.000000"` and `kind == AtomKind.NUMBER`

#### Scenario: Leading plus is not a number
- **GIVEN** the text `(x +0.8 0x10 1.6mm)`
- **WHEN** it is parsed
- **THEN** the three atoms have kind `symbol`

#### Scenario: Quoted digits are a string
- **GIVEN** the text `(pad "1" smd rect)`
- **WHEN** it is parsed
- **THEN** the first atom has `text == "\"1\""`, `kind == AtomKind.STRING` and `value == "1"`

### Requirement: Invalid atoms cannot be built
Constructing an `Atom` MUST raise `ValueError` when `text` is not exactly one lexical atom (empty text, whitespace, `(`, `)`, a raw CR or LF, or a malformed quoted string) or when `kind` differs from the lexical classification of `text`. `Atom.symbol(name)` MUST raise `ValueError` for a name that would read as a number or a string.

#### Scenario: Atom with whitespace
- **WHEN** `Atom("a b", AtomKind.SYMBOL)` is constructed
- **THEN** a `ValueError` is raised

#### Scenario: Kind disagrees with the text
- **WHEN** `Atom("a", AtomKind.NUMBER)` or `Atom.symbol("12")` is called
- **THEN** a `ValueError` is raised

#### Scenario: Symbol that reads as a string
- **WHEN** `Atom.symbol("\"x\"")` is called
- **THEN** a `ValueError` is raised

### Requirement: Nodes are ordered and headed by an atom
A list SHALL be parsed into an immutable `Node(head, children, offset, comments)`:
- `head` MUST be the first atom of the list, of any kind.
- `children` MUST keep source order and MAY mix `Node` and `Atom`.
- `offset` MUST be the byte offset of the opening parenthesis in the UTF-8 encoding of the input, for `parse`, `parse_bytes` and `load` alike, and MUST NOT take part in equality.
- `comments` MUST be empty on every node except the root.

#### Scenario: Numeric head
- **GIVEN** the text `(layers (0 "F.Cu" signal) (2 "B.Cu" signal))`
- **WHEN** it is parsed
- **THEN** the root has two child nodes whose heads are number atoms `0` and `2`

#### Scenario: Offsets ignored by equality
- **GIVEN** `(a (b 1))` and `(a\n\t(b 1)\n)`
- **WHEN** both are parsed
- **THEN** the two nodes compare equal although their child offsets differ

#### Scenario: Offsets count bytes
- **GIVEN** the text `(a "é" (b))`
- **WHEN** it is parsed with `parse` and, encoded as UTF-8, with `parse_bytes`
- **THEN** the offset of the `(b)` node is 8 in both results

### Requirement: Accepted lexical forms
The parser SHALL accept all of the following:
- space, TAB, CR and LF as separators
- unquoted atoms made of any characters except whitespace, `(`, `)` and a leading `"`
- double-quoted strings that contain any character except CR, LF and an unescaped `"`, including parentheses, TAB, other control characters, non-ASCII UTF-8 characters and backslash escapes
- lines whose first non-blank character is `#` before the root list

Those comment lines MUST be kept in the root's `comments`.

#### Scenario: CRLF file
- **GIVEN** a board text with CRLF line endings
- **WHEN** it is parsed
- **THEN** the tree equals the tree of the same text with LF endings

#### Scenario: Parentheses inside strings
- **GIVEN** `(descr "Resistor (THT)")`
- **WHEN** it is parsed
- **THEN** the node has exactly one child atom with `value == "Resistor (THT)"`

#### Scenario: Raw control character inside a string
- **GIVEN** `(t "a` + a raw VT byte + `b")`
- **WHEN** it is parsed
- **THEN** it succeeds and the atom's `value` contains the VT character

#### Scenario: Comment before the root is preserved
- **GIVEN** a text whose first line is `# generated by hand` followed by `(kicad_pcb (version 20260206))`
- **WHEN** it is parsed and serialised with `dumps`
- **THEN** the root's `comments` is `("# generated by hand",)` and the output starts with that line

#### Scenario: Legacy unquoted atoms
- **GIVEN** `(module Resistors_SMD:R_0603 (layer F.Cu) (net 1 /VCC))`
- **WHEN** it is parsed
- **THEN** `Resistors_SMD:R_0603`, `F.Cu` and `/VCC` are symbol atoms with that exact text

### Requirement: Rejected input raises a located FormatError
`parse`, `parse_bytes` and `load` MUST raise `fenolite.core.errors.FormatError` in each of the cases below. The first group mirrors observed KiCad load failures. The second group is Fenolite-only strictness, and no agreement with KiCad is claimed for it.
- mirrored: empty input or input with only comments; unbalanced parentheses; a byte-order mark or any other character before the root; a raw LF inside a quoted string; an atom directly after a closing quote
- Fenolite-only: non-whitespace content after the root list; a `(` directly followed by `)` or by `(`; a raw CR inside a quoted string; an unterminated string; nesting deeper than `MAX_DEPTH`; invalid UTF-8 (only in `parse_bytes` and `load`)

The error MUST carry `file`, `offset` and the locator of the innermost open list. `offset` MUST be a byte offset in the UTF-8 encoding of the input, for every entry point. The message MUST name the rule that was broken.

#### Scenario: Raw newline in a string
- **GIVEN** `(kicad_pcb (title "a` + LF + `b"))`
- **WHEN** `parse(text, file="x.kicad_pcb")` runs
- **THEN** a `FormatError` is raised with `file == "x.kicad_pcb"`, the offset of the newline, locator `/kicad_pcb/title[0]` and a message containing `newline inside string`

#### Scenario: Byte-order mark
- **GIVEN** bytes `EF BB BF` followed by `(kicad_pcb (version 20260206))`
- **WHEN** `parse_bytes` runs
- **THEN** a `FormatError` with offset 0 and a message containing `byte-order mark` is raised

#### Scenario: Trailing content is not dropped silently
- **GIVEN** `(kicad_pcb (version 20260206)) (extra)`
- **WHEN** it is parsed
- **THEN** a `FormatError` naming `content after the root list` is raised at the offset of `(extra)`

#### Scenario: Atom glued to a string, after a multi-byte character
- **GIVEN** `(a "é" "x"y)`
- **WHEN** it is parsed with `parse`, and with `parse_bytes` on its UTF-8 encoding
- **THEN** both raise a `FormatError` with offset 11, the byte offset of `y`

#### Scenario: Unbalanced input
- **GIVEN** `(kicad_pcb (version 20260206)`
- **WHEN** it is parsed
- **THEN** a `FormatError` naming `unbalanced` and locator `/kicad_pcb` is raised

#### Scenario: Depth bomb
- **GIVEN** a text of 10 000 nested lists `(a (a (a …)))`
- **WHEN** it is parsed
- **THEN** a `FormatError` naming `MAX_DEPTH` is raised and no `RecursionError` occurs

### Requirement: Fragment codec
`dumps(atom)` SHALL return `atom.text` in both styles. `parse_fragment(text, *, file="")` SHALL return a `Node` when `text` holds exactly one list and an `Atom` when it holds exactly one atom, with optional surrounding whitespace. It MUST raise `FormatError` for empty text, for more than one element, for a comment line, and for every rejection rule of `parse`. For every `x` that is a `Node` without comments or an `Atom`, `parse_fragment(dumps(x, style="compact"))` MUST be tree-equal (for an atom: equal) to `x`.

#### Scenario: Bare symbol fragment
- **WHEN** `parse_fragment("locked")` is called
- **THEN** it returns `Atom("locked", AtomKind.SYMBOL)`

#### Scenario: String fragment
- **WHEN** `parse_fragment('"a b"')` is called
- **THEN** it returns a string atom whose `value` is `a b`

#### Scenario: Two elements
- **WHEN** `parse_fragment("a b")` is called
- **THEN** a `FormatError` naming `more than one element` is raised

### Requirement: String decoding and encoding
`Atom.value` SHALL decode a string atom as follows:
- `\"`, `\\`, `\n`, `\r`, `\t` and `\v` become their characters.
- Octal `\ooo` (1–3 digits) and hex `\xHH` become the character they encode.
- Any other backslash sequence MUST be kept literally.

`Atom.string(value)` SHALL encode the value as follows:
- It MUST escape `"`, `\`, LF and CR as `\"`, `\\`, `\n` and `\r`.
- It MUST keep TAB and every character that is not a C0 control raw.
- It MUST write every other C0 control character, VT included, as a 3-digit octal escape.
- It MUST raise `ValueError` for NUL.
- It MUST never produce a raw newline.

#### Scenario: Decode table
- **GIVEN** the string atom `"q\"b\\n\nt\101\x42\e"`
- **WHEN** `value` is read
- **THEN** it equals `q"b\n` + LF + `tAB\e`

#### Scenario: Encode then decode is identity
- **GIVEN** any string without NUL (hypothesis strategy `kicad_strings()`)
- **WHEN** `Atom.string(s).value` is computed
- **THEN** it equals `s`, and `Atom.string(s).text` contains no byte below 0x20 other than TAB

#### Scenario: Control characters
- **WHEN** `Atom.string("a\x0bb")` and `Atom.string("a\x00b")` are called
- **THEN** the first returns the text `"a\013b"` and the second raises `ValueError`

### Requirement: Numbers in integer nanometres
`Atom.to_nm(exact=True)` SHALL convert a number atom written in millimetres to integer nanometres using integer arithmetic only. It MUST accept exponent, leading-dot and trailing-dot spellings. When `exact` is true, it MUST raise `ValueError` for a value that is not a whole number of nanometres or for a non-number atom. When `exact` is false, it MUST round half to even.

`Atom.from_nm(nm)` SHALL produce the shortest decimal-millimetre spelling:
- at most 6 decimals
- no exponent
- no trailing zeros
- no trailing dot
- `0` for zero

#### Scenario: Exact conversions
- **WHEN** `to_nm` is called on atoms `0.25`, `1e-3`, `.8`, `1.` and `-0`
- **THEN** the results are `250000`, `1000`, `800000`, `1000000` and `0`

#### Scenario: Inexact value
- **GIVEN** the atom `1.60000000000001`
- **WHEN** `to_nm()` is called
- **THEN** a `ValueError` is raised, and `to_nm(exact=False)` returns `1600000`

#### Scenario: Writing
- **WHEN** `Atom.from_nm(n).text` is computed for `n` = `2000000`, `123457`, `-500`, `0`
- **THEN** the texts are `2`, `0.123457`, `-0.0005`, `0`

#### Scenario: Symbol is not a length
- **WHEN** `Atom.symbol("signal").to_nm()` is called
- **THEN** a `ValueError` is raised

### Requirement: KiCad-style serialisation
`dumps(node)` SHALL write UTF-8 text with LF line endings. The output ends with `)` and one LF. The layout rules are:
- Root comments come first, one per line.
- There is one TAB per depth.
- Atoms that precede the first child list stay on the head line, separated by single spaces.
- A list whose children are all atoms is written on one line.
- Each child list, and each atom that follows a child list, starts a new line one depth deeper.
- The closing parenthesis of a list with child lists stands alone at the list's depth.
- Inside `pts`, the next `xy` list is appended to the current line after one space if and only if that line is shorter than 99 columns, with a TAB counted as one column. Otherwise it starts a new line.

Atom text MUST be written unchanged. `dumps` MUST raise `ValueError` for a tree in which a node other than the root has comments. For every other tree, `dumps(parse(dumps(n)))` MUST equal `dumps(n)` byte for byte.

#### Scenario: Layout of a pad
- **GIVEN** the tree of `(pad "1" smd rect (at 1 2) (layers "F.Cu"))` at depth 0
- **WHEN** `dumps` runs
- **THEN** the output is `(pad "1" smd rect` LF TAB `(at 1 2)` LF TAB `(layers "F.Cu")` LF `)` LF

#### Scenario: xy appended at 98 columns
- **GIVEN** a `pts` node at depth 3 whose children are `(xy 0 0)`, `(xy 1000.123456 -1000.123456)` twice, `(xy 10.123456 -10.123456)` and `(xy 0 0)`
- **WHEN** `dumps` runs
- **THEN** all five `xy` lists are on one line at depth 4, because the line holding the first four is exactly 98 columns long

#### Scenario: xy wrapped at 99 columns
- **GIVEN** the same node with the fourth child replaced by `(xy 10.123456 -100.123456)`
- **WHEN** `dumps` runs
- **THEN** the first four `xy` lists fill a line of exactly 99 columns and the fifth starts a new line at depth 4

#### Scenario: Idempotence
- **GIVEN** any tree produced by the hypothesis strategy `sexpr_trees()`, which puts comments on the root only
- **WHEN** `dumps(parse(dumps(t)))` is computed
- **THEN** it equals `dumps(t)` and `parse(dumps(t))` is tree-equal to `t`

#### Scenario: Comments on a nested node
- **GIVEN** a root whose child node has `comments == ("# x",)`
- **WHEN** `dumps` runs in either style
- **THEN** a `ValueError` is raised

### Requirement: Compact serialisation
`dumps(node, style="compact")` SHALL write the node on one line. Elements MUST be separated by exactly one space. The output MUST have no newline, and atom text MUST be written unchanged. Root comments MUST be omitted. `parse` of the result MUST be tree-equal to `dataclasses.replace(node, comments=())`.

#### Scenario: Compact fragment
- **GIVEN** the node of `(stroke\n\t(width 0.1)\n\t(type solid)\n)`
- **WHEN** it is serialised compactly
- **THEN** the result is `(stroke (width 0.1) (type solid))`

#### Scenario: Compact output drops root comments
- **GIVEN** the root parsed from `# note` LF `(a 1)`
- **WHEN** it is serialised compactly
- **THEN** the result is `(a 1)`

#### Scenario: Unknown style
- **WHEN** `dumps(node, style="pretty")` is called
- **THEN** a `ValueError` is raised

### Requirement: Tree equality and locators
`tree_equal(a, b)` SHALL return true exactly when all of the following are equal: heads, atom texts and kinds, child counts, child order, and root comments. Whitespace and offsets MUST be ignored. `first_difference(a, b)` SHALL return `None` for equal trees, and otherwise the locator of the first differing node. Locators use the form `/head/child[index]`, where `index` counts earlier siblings with the same head, starting at 0. `walk(node)` SHALL yield `(locator, node)` for every node in document order.

#### Scenario: Spelling matters
- **GIVEN** `(a (w 12))` and `(a (w 12.0))`
- **WHEN** `tree_equal` and `first_difference` are called
- **THEN** they return `False` and `/a/w[0]`

#### Scenario: Locator of the second footprint
- **GIVEN** a board with three `footprint` children
- **WHEN** `walk` reaches the second
- **THEN** its locator is `/kicad_pcb/footprint[1]`

### Requirement: RT0 over the public corpus
For every cached corpus item whose `uses` contains `rt0` and that is not `heavy`, `parse` MUST succeed, `parse(dumps(parse(t)))` MUST be tree-equal to `parse(t)`, and the sequence of tokens of `t` MUST equal the sequence of tokens of `dumps(parse(t))`. Tokens are parentheses and atom texts, and they MUST be computed by a tokenizer in the test that is independent of `sexpr.py`. `heavy` items MUST be included only when `FENOLITE_HEAVY=1`. Each item's origin MUST be read from its `origin:` value in `uses`. The parser MUST NOT be labelled `CORPUS-VERIFIED` unless items from at least two origins passed.

#### Scenario: Demo and third-party boards round-trip
- **GIVEN** the corpus fetched with `uv run python tools/corpus_fetch.py --uses rt0 --exclude-uses heavy`
- **WHEN** `uv run pytest tests/corpus/test_rt0.py` runs
- **THEN** every item passes and the summary lists the origins `kicad-demos` and `third-party` with their item counts

#### Scenario: Heavy items need opt-in
- **GIVEN** a cached `heavy` item and `FENOLITE_HEAVY` unset
- **WHEN** the RT0 test runs
- **THEN** that item is skipped with a message naming `FENOLITE_HEAVY=1`

#### Scenario: Corpus absent
- **GIVEN** an empty corpus cache and no `FENOLITE_REQUIRE`
- **WHEN** the test runs
- **THEN** it is skipped with the fetch hint

### Requirement: kicad-cli loads what dumps writes
For every non-heavy corpus board whose original loads in `kicad-cli` 10.0.x, the file written by `dumps(parse(original))` MUST also load. Loading means `kicad-cli pcb export svg -l Edge.Cuts --mode-single -o <svg>` exits 0 and the SVG exists. All runs MUST take place in a temporary directory.

#### Scenario: Re-dumped board loads
- **GIVEN** a fetched demo board and `kicad-cli` 10.0.6
- **WHEN** `uv run pytest tests/kicad/test_rt0_oracle.py::test_redump_loads` runs
- **THEN** the command exits 0 for the re-dumped file and the SVG exists

### Requirement: Fixture outcomes match recorded expectations
Every fixture under `tests/data/kicad/sexpr/` SHALL have a row in `tests/data/kicad/sexpr/EXPECT.toml` with `file`, `class` (`mirror`, `unmirrored` or `semantic`), `expect_parse` (`accept` or the rule name of the expected `FormatError`), `expect_kicad_10` (exit code of the load command), an optional `expect_kicad_9`, and a hypothesis id. The observed parse outcome MUST equal `expect_parse`. When `kicad-cli` runs, its observed exit code MUST equal the expectation for its major; a fixture without one is skipped with a message. Only for class `mirror` MUST `expect_parse` be a rejection exactly when the KiCad expectation is 3. Class `unmirrored` holds the Fenolite-only rejections, and class `semantic` holds number spellings that parse but that KiCad may refuse.

#### Scenario: Mirrored rejection agrees with KiCad
- **GIVEN** the `mirror` fixture with a raw newline inside a string
- **WHEN** `uv run pytest tests/kicad/test_sexpr_oracle.py::test_fixture_outcomes` runs with `kicad-cli` 10.0.6
- **THEN** `parse` raises `FormatError` naming `newline inside string` and `kicad-cli` exits 3

#### Scenario: Stricter than KiCad
- **GIVEN** the `unmirrored` fixture with trailing content after the root list, recorded with `expect_kicad_10 = 0`
- **WHEN** the same test runs
- **THEN** `parse` raises `FormatError` naming `content after the root list` and `kicad-cli` exits 0

#### Scenario: Semantic number rejection
- **GIVEN** the `semantic` fixture whose line width is written `+0.8`
- **WHEN** the same test runs
- **THEN** `parse` succeeds and `kicad-cli` exits 3

#### Scenario: Inconsistent mirror row
- **GIVEN** a `mirror` row with `expect_parse = "accept"` and `expect_kicad_10 = 3`
- **WHEN** `uv run pytest tests/unit/backends/kicad/test_sexpr_fixtures.py` runs
- **THEN** the test fails naming the fixture

### Requirement: Strings written by Fenolite read back in KiCad
For a board whose `gr_text` strings are produced by `Atom.string` from values containing a quote, a backslash, LF, CR, TAB, VT, another C0 control character and non-ASCII characters, the values decoded from the file that `kicad-cli pcb upgrade --force` writes MUST equal the original values.

#### Scenario: Encoder round trip through KiCad
- **GIVEN** such a board written in `tmp_path` and `kicad-cli` 10.0.6
- **WHEN** `uv run pytest tests/kicad/test_sexpr_oracle.py::test_encoder_after_upgrade` runs
- **THEN** each re-read `gr_text` value equals the value given to `Atom.string`

### Requirement: Format facts are documented with sources and labels
`docs/formats/kicad/sexpr.md` SHALL state, in Fenolite's own words, each fact the parser and printer rely on (lexical forms, rejections, escapes, number spelling, layout rules) as a row of a table with the header `| fact | source | label | hypothesis |`. Each row MUST cite at least one source id from `docs/evidence/sources.md`, and its label MUST be a value of `fenolite.core.evidence.Level`. A row whose label is not `KICAD-VERIFIED` or `CORPUS-VERIFIED` MUST name an `H-K-SEXPR-*` or `H-K-FMT-*` hypothesis. `src/fenolite/backends/kicad/PROVENANCE.md` MUST list every source consulted.

#### Scenario: Row without label
- **GIVEN** a fact row of `docs/formats/kicad/sexpr.md` whose label cell is empty
- **WHEN** `uv run pytest tests/unit/test_format_facts.py` runs
- **THEN** the test fails naming the page and the row

#### Scenario: Unverified row without hypothesis
- **GIVEN** a fact row labelled `INFERRED` with an empty hypothesis cell
- **WHEN** the same test runs
- **THEN** it fails naming the row
