## Decisions

1. A viewer-owned stdlib module composes status from scene metadata, resolved check stages and optional convert/export replies. It imports no checks/CLI/catalog layer. The CLI supplies parsed reports; existing geometry and markers remain authoritative.
2. Missing stages are not run; skipped/unknown stages, warnings, capped results, missing evidence and missing/mismatched input hashes are limited. Errors remain failed even when scope is limited. Aggregate categories cannot pass when only part of their declared stage set ran. Reading means the current scene was read, not electrical acceptance.
3. Preserve input path/hash, raw stage name/status/reason, evidence, limits and findings' original hint. A matched input hash binds only the named document; no claim of a locked multi-document snapshot. An unbound report is shown as historical information and cannot provide a current passed card.
4. `--report FILE` accepts complete convert/export JSON envelopes with result, issues and explicit boolean ok. Duplicate reports of the same command are refused so ordering cannot hide failures. Check reports keep the existing `--check` route. Missing or malformed files use existing FEN-3001/FEN-3004; no new code. Reporting is read-only; only existing HTML export plans writes.
5. Conversion is limited without equivalence, with losses/experimental scope or without a completed receipt. An export records generated artifacts; existing export replies do not attest successful readback, so it remains limited with an explicit reason rather than declaring fabrication readiness. No overall manufacture-ready badge.
6. The review entry sits in the existing project heading. A closable panel presents cards and stage details, then filtered findings. Locate reuses selectFinding, reveals its layer and closes the panel to show geometry; unplaced findings say so and keep their hint. Native controls provide keyboard operation and meaningful empty states. No auto-fix or local resolved flag changes verification results.
7. Report attachment happens after cached scene construction and is recomposed on live saves. Source hashes are compared with current scene hashes; the saved report is not rerun or silently updated. Offline HTML embeds the same payload.

## Verification

Authored reply fixtures prove state classification, warnings/caps/skips, partial coverage, revision mismatch, conversion/export limitations and preservation of metadata. CLI tests prove reports in JSON/offline/live paths, invalid/duplicate input refusal and staged replay. Chromium exercises actual status/finding controls, locate, filters, keyboard, narrow layouts and stale reloads. Run focused checks while iterating and one combined make check-fast; full CI is pending authorized publication.
