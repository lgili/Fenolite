## Decisions

1. Increment a navigation generation for every open request, including a repeated request for the same document. Check the captured generation after asynchronous work, including failure and empty-scene paths. Document identity alone is insufficient for A-to-B-to-A navigation.
2. Return a successful navigation token from openDoc so delayed cross-probe, marks, BOM selection and startup deep-link application can verify that their document still owns the view. A superseded operation returns no successful token.
3. Assign a monotonically increasing read generation per document. A completed decode or live read may populate the cache and remove its raw source only if it remains the newest request for that document. Invalidation also advances this generation, preventing an older in-flight response from refilling invalidated data.
4. Version polling captures the document and navigation before requesting. A per-document latest-poll sequence rejects replies arriving out of order. Navigation checks apply after both the version request and any triggered scene reload; a failed stale request must not change the current status.
5. Keep normal rendering and layout. On a new document request, show its existing document card with a reading message while its scene loads; keep the current scene during a background refresh. The loading card uses the current document identity, never a stale request's identity.
6. Browser tests control deferred promises rather than relying on response timing. Use the authored blink project and existing browser harness; no screenshot reference or private fixture changes. Cover success, rejection, empty scenes, A-to-B-to-A, stale polling and cache order. Run focused browser/unit proofs locally; the coordinator runs one combined check-fast after integration.
7. Revalidate on the first available version response, including when returning to a cached document. Do not adopt a version without loading its scene first. Skip new polls while the current scene is loading so slow initial reads or refreshes cannot be repeatedly superseded by polling. Failed reads retain their error and are retried by a later poll without adopting an unrendered version.
