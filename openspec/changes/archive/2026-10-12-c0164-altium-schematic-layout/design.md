## Context

The Altium reader preserves document bytes and computes schematic connectivity. The CLI already stages atomic writes and binds reviewed plans to inputs. Reuse those facilities rather than transform native presentation into a reduced placement model.

## Decisions

1. A build keeps its fresh SchDoc bytes in `.fenolite/altium-generated/`, independently of any replayed layout. The existing build receipt tracks both.
2. Sync captures the complete edited SchDoc bytes as base64 in a versioned JSON file next to the script. Each sheet binds to the SHA-256 of its fresh generated baseline. Filenames are single safe SchDoc names; no paths from the snapshot are followed.
3. Sync compares complete project netlists and stable component unit IDs, library references, pin designators/types and component parameters. Reader warnings, unresolved input and changed connectivity refuse the entire capture. Presentation changes are accepted and stored verbatim, including native embedded assets and unknown streams.
4. A build replays a sheet only when its freshly generated bytes match the bound baseline. Changed or removed saved sheets refuse the whole write transaction. Newly generated sheets without saved layout use their normal writer. Adding a component to a saved sheet is a conflict too; incremental merging is not part of this change.
5. The maintainer explicitly selected conflict refusal over regenerating a changed sheet. `--discard-layout` cannot bypass a saved source layout; the user must move or remove the source snapshot deliberately to regenerate it.
6. Staged sync and build plans bind all baseline, snapshot and edited-document inputs, including absence where applicable. `sync --check` reports whether the snapshot is current without writing.

## Verification

Authored ASCII and binary documents cover native edits and byte identity, changed nets and IDs, missing files, malformed snapshots, baseline tampering, stale reviewed plans, repeated sync/build, new sheets and conflicting edits. Full check is the final gate. A native Altium GUI run remains an external validation limit, not a claim made by these tests.
