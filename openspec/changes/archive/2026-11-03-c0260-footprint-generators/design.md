## Context

- **Source.** `docs/research/component-library.md`, section 4.2 ("Footprints and 3D from package
  families"), section 2 ("What the standards give us"), section 1 (licences) and change c0260 of
  section 5. Clean-room: only concepts are taken (per-family generators fed by parameter files; a land
  computed from toleranced package dimensions with toe, heel and side goals; a courtyard excess; the
  manufacturer's pattern winning; a body extruded from the same numbers). No IPC table, formula text,
  constant or naming pattern, no KiCad generator code, parameter file or footprint, and no vendor model
  is used.
- **What exists on `dev` (0.6.0).**
  - `fenolite.catalog` ships 100 footprints drawn by private helpers from tuples of manufacturer land
    numbers (`_NEW_TWO_TERMINAL_LANDS_UM`, `_SMALL_OUTLINE_LANDS_UM`, `_QFN_LANDS_UM`, `_DFN_LANDS_UM`,
    `_QFP_LANDS_UM`, `_DIP_BODIES_UM`). All are `INFERRED`, none has a body or a 3D model. Pad ids are
    `derived_id("pad", "fenolite.catalog", "<name>:<number>")`.
  - `FootprintDef` has `bodies: tuple[ComponentBody, ...]` and `models: tuple[str, ...]`.
    `ComponentBody(kind="extruded", height, standoff, outline, z_min, z_max, name, ...)` is a vertical
    prism over a polygon (`design-model`, "Component bodies"; `component-body-volumes`). A KiCad build keeps
    bodies in `.fenolite/` only; the Altium build writes extruded bodies with `--altium-bodies extruded`.
  - `fenolite export step` runs `kicad-cli pcb export step`, which reads `${KIPRJMOD}/<rel>` model paths
    from the board's folder (`docs/formats/kicad/libraries.md`, "3D models", `KICAD-VERIFIED`).
  - `fenolite.dsl.Footprint` builds a footprint from pads and graphics; `design.add_footprint()`
    registers it.
  - `fenolite library PATH --out LIB.pretty` derives a library from a board (c0223).
- **What this batch adds before it.**
  - c0246: exact intervals (`Range`, worst-case arithmetic); c0248 moves the exact unit parser to
    `fenolite.core.quantities`.
  - c0259: the record envelope of `fenolite.package.v0` (schema, name, version, stable id from
    `(kind, canonical name)`, `licence`, `sources`, `evidence`, `reviewed_by`), the data tree, where
    project package files are read, and the move of the catalog's tables to package records with
    byte-identical output.

## Goals / Non-Goals

**Goals**

- One public generator per package family, fed only by a package record, deterministic to the byte.
- A land from toleranced dimensions when the datasheet gives none, with constants Fenolite authored,
  versioned and documented; the manufacturer's land when it is given, recorded as evidence.
- Courtyard, pin-1, silkscreen and fabrication drawings by one versioned Fenolite convention.
- 3D bodies in the model and a STEP file, both from the same numbers, without a dependency.
- The 100 catalog footprints regenerated by the public generators with unchanged bytes.

**Non-Goals**

- See the proposal. In addition: no automatic choice of a package for a part (`fenolite-component-catalog`,
  "Generic symbols do not select a package"), no wave-solder variants, no rotated or bottom-side
  generation (a placed footprint is rotated by the board, as today).

## Today and proposed

    land.pad(str(i + 1), at=(mm(-2.7), mm(-1.905 + 1.27 * i)), size=(mm(1.55), mm(0.6)))

## Decisions

### 1. Where the code lives

- `fenolite.catalog.footprints` (new sub-package of `catalog`, which imports `model` and `core` only):
  `generate(package, *, density="nominal") -> Generated`, one module per family, `lands.py` (calculator
  and constants), `drawing.py` (conventions), `bodies.py` (bodies), `codes.py` (`package.*` codes).
- `fenolite.core.quantities.LengthRange` (decision 3), beside the parser that c0248 moves there and
  c0246 extends. If c0259 already defines a length range there, this change uses it.
- `fenolite.backends.step` (new top-level module of `backends`, which may import `model` and `geometry`):
  the STEP writer, a pure function of `ComponentBody` values. `lens` (the build) and `cli` may import
  `backends`, so no edge of `package-layering` changes. *Alternative:* `fenolite.geometry.step`; rejected
  because `lens` may not import `geometry`.

```python
@dataclass(frozen=True, slots=True)
class Generated:
    footprint: FootprintDef | None  # None on an error; bodies included
    land: LandReport  # source ("calculated" | "manufacturer"), Z/G/X, pad sizes, deltas
    stamp: str  # "gullwing/1 lands/1 drawing/1 nominal" or "gullwing/1 manufacturer drawing/1"
    issues: tuple[Issue, ...]  # package.* findings, sorted
```

`generate` is pure: no file, no clock, no environment. Errors (`severity == "error"`) give no footprint:
`Generated.footprint` is `None` and the issues say why.

### 2. Families and their keys

The envelope keys belong to c0259. This change defines the keys after `family`. Lengths are length
ranges (decision 3); counts are integers.

| family | packages | keys (required **bold**) |
|---|---|---|
| `chip` | two-terminal chips: R, C, L, bead | **`body`** (length, width, height), **`terminal`** (band length), `polarity` (`none` / `pad1`) |
| `molded` | SOD, SMA/SMB/SMC, molded tantalum, MELF | **`body`**, **`span`**, **`lead`** (length, width), `lead_style` (`flat` / `inward` / `cylinder`), `polarity` |
| `gullwing` | SOIC, SSOP, TSSOP, MSOP, QFP, SOT | **`pins`**, **`pitch`**, **`arrangement`** (`dual` / `quad` / `sides`), **`body`**, **`span`** (`span_x`, `span_y` for quad), **`lead`** (length, width, thickness), `[[side]]` (for `sides`: `edge`, `numbers`, `positions`), `tab` (number, width, length, edge) |
| `nolead` | QFN, DFN, SON | **`pins`**, **`pitch`**, **`arrangement`** (`dual` / `quad`), **`body`**, **`terminal`** (length, width), `pull_back`, `ep` (length, width), `ep_number` (default `EP`), `paste` |
| `grid` | BGA, LGA-style grids | **`rows`**, **`columns`**, **`pitch`** (or `pitch_x`, `pitch_y`), **`body`**, **`ball`** (diameter), `pad` (`nsmd` / `smd`), `depopulated` (names or `center = "RxC"`) |
| `to` | TO-220, TO-247, TO-92 (THT); DPAK-, D2PAK-style (SMD) | **`mount`** (`tht` / `smd`), **`leads`**, **`pitch`**, **`body`**, **`lead`** (width, thickness, length), `tab` (width, length, hole, number), `lead_rows` |
| `dip` | DIP, through-hole dual rows | **`pins`**, **`pitch`**, **`row_spacing`**, **`body`**, **`lead`** (width, thickness, length) |
| `header` | pin headers and sockets | **`rows`**, **`columns`**, **`pitch`**, **`mount`**, **`orientation`** (`vertical` / `horizontal`), **`pin`** (width, length_above, length_below), **`body`** (height), `numbering` (`rows-first` / `columns-first`) |
| `connector` | a connector series | **`series`**, **`positions`** (`"2..15"`), **`pitch`**, **`name_pattern`** (`"Conn_{series}_1x{n}_P{pitch}"`), **`body`** with `length = { per_position, extra }`, **`pin`**, `mount`, `orientation`, `[[mechanical]]` (pegs and retention pads), `[land]` per series |

- `[generate]` (all families): `lands` (constant table version; required when the calculator is used),
  `drawing` (convention version; required), `density` (default `nominal`, the only value shipped).
- `[land]` (all families, optional): the manufacturer's land (decision 7).
- A `connector` record expands to one package per position count; each expanded package has the name of
  `name_pattern`, its own stable id (c0259's rule on the expanded name) and the record's sources.
  `generate(package, positions=n)` draws one; `fenolite library generate` draws all.
- An unknown key, a missing required key or a wrong type is `FEN-3004` (c0259's parser error) naming the
  file and the key.

### 3. Length ranges

```python
@dataclass(frozen=True, slots=True)
class LengthRange:
    min: Nm | None
    nom: Nm | None
    max: Nm | None
```

- Text spellings: `"1.27mm"` (exact: min = nom = max), `"4.80mm..5.00mm"`, `"1.75mm max"`,
  `"0.10mm min"`, and the table `{ min = "...", nom = "...", max = "..." }`. Units: `mm`, `um`, `mil`
  (25 400 nm) and `in` (25 400 000 nm), parsed exactly; a value that is not a whole number of nm, or
  `min > nom`, `nom > max`, is `FEN-3004`.
- `nominal` is `nom` when given, else `(min + max) // 2` (floor to the nm), else `None`.
- These are c0246's intervals: exact bounds, worst-case arithmetic. They are integers in nm because
  every length of the model is (`docs/design-model.md`); c0246's electrical units are untouched.
- A calculator input that needs a missing bound gives the error `package.missing-bound` naming the key
  and the bound.

### 4. The land calculator (worst case, exact)

For two facing land rows (chip, molded, gullwing, nolead, SMD `to` leads) the inputs are the lead-tip
span `L` (for chip and nolead, the body length), the lead or terminal length `T` and the lead width `W`;
the goals `Jt` (toe), `Jh` (heel) and `Js` (side) come from the constant table (decision 5) for the land
class of the package. All arithmetic is on integer nm:

```
S_min = L.min - 2 * T.max          # smallest inner distance between lead heels
Z     = L.max + 2 * Jt             # outer extent of the two lands
G     = S_min - 2 * Jh             # inner gap between the two lands
X     = W.max + 2 * Js             # land width
Z, G, X rounded to the 10 µm grid: Z up, G down, X up
pad length = (Z - G) / 2           # exact: Z and G are multiples of 10 µm
row centre distance C = (Z + G) / 2
```

- Worst case, not root-sum-square: it is exact, needs no square root and no fabrication tolerance
  constant, and it is the arithmetic of c0246. *Alternative:* a statistical stack; rejected, it adds
  constants we would have to author without data and makes the land depend on a formula we cannot
  cite.
- **Pad gap.** When `pitch - X < pad_gap`, `X` becomes `pitch - pad_gap` floored to the grid, with the
  warning `package.pads-clipped` naming the lost side goal. When `G <= 0`, a pad length `<= 0`, or a
  clipped `X <= 0`, the error `package.land-impossible`.
- **Quad arrangements** compute each axis on its own (`span_x`, `span_y`); corner pads keep `pad_gap`
  between perpendicular rows or are shortened from the inner end (warning `package.pads-clipped`).
- **No-lead terminals** use `pull_back` (default 0) to shift `L`; the heel side is also bounded by the
  exposed pad (decision 8).
- **Grid arrays:** land diameter = ball nominal × `ball_ratio[pad]` (an exact fraction of the table),
  rounded to the grid.
- **Through-hole** (`dip`, THT `to`, `header`, `connector`): drill = `isqrt(w.max² + t.max²)` rounded up
  (a rectangular lead's diagonal; a round lead gives `w` only) plus `hole_clearance`, rounded up to the
  grid; pad diameter = drill + 2 × `annular_ring`; a pad wider than `pitch - pad_gap` becomes an oval of
  that width (warning `package.pads-clipped`). `math.isqrt` is exact on integers.

### 5. Constants: authored, versioned, calibrated from cited manufacturer patterns

- The table `lands/1` lives in `fenolite.catalog.footprints.lands.LANDS[1]` and in
  `docs/formats/library/lands.md`, labelled `INFERRED`, each row with how it was obtained. It holds,
  per land class (`chip`, `molded`, `gullwing`, `gullwing-fine` for pitch < 0.65 mm, `nolead`, `smd-tab`),
  `Jt`, `Jh`, `Js`; and globally `pad_gap`, `grid` (10 µm), `courtyard` (decision 10), `hole_clearance`,
  `annular_ring`, `ball_ratio` and the exposed-pad and paste values of decision 8.
- **Derivation.** `tools/calibrate_lands.py` reads every package record of a class that has both
  toleranced dimensions and a cited manufacturer `[land]`, back-solves the goals each pattern implies
  (`Jt = (Z_mfr - L.max) / 2`, `Jh = (S_min - G_mfr) / 2`, `Js = (X_mfr - W.max) / 2`), takes the lower
  median of each, rounds it to 10 µm, and writes the table with the list of records it used. CI runs it
  with `--check`. A class with fewer than three such records has no goals: the calculator gives the
  error `package.no-goals` and the package needs a `[land]`.
- The global constants that no manufacturer pattern can calibrate (`pad_gap`, `courtyard`, `grid`) are
  Fenolite's own choices, kept equal to what the 0.6 catalog already does (200 µm is the smallest pad
  gap among the 100 footprints; 500 µm is the courtyard excess of `_make_footprint`).
- **Versioning.** A table is never edited after release: a new calibration is `lands/2`. A package
  record names its version, so a Fenolite upgrade never moves a land silently. *Alternative:* default
  to the newest table; rejected, it breaks byte-identical rebuilds.
- **Never IPC.** No value is taken from IPC-7351 tables or its calculator, and `lands.md` says so. Some
  manufacturer documents present their patterns as following IPC; we use only their published numbers
  for their own package, as the 0.6 catalog does (open question 2).

### 6. Density

Only `nominal` is shipped (research, question 4). `density = "compact"` and `"robust"` are reserved:
they give `FEN-3004` with a message naming them as reserved. *Alternative:* three levels offset from
nominal by authored deltas; rejected for now, there is no data to calibrate them.

### 7. The manufacturer's land wins, and is evidence

- `[land]` keys: `source` (required, a registered source id with a location), and per family the pad
  size and placement (`pad`, `row_spacing` or `row_spacing_x/y`, `pads` for an explicit list, `ep`,
  `paste`, `drill`, `pad_diameter`). The generator uses these numbers unchanged and the conventions for
  everything else.
- The land source is recorded: the footprint description ends with
  `land: manufacturer <source>` or `land: calculated lands/1 nominal (INFERRED)`, and `Generated.land`
  holds the source and the numbers.
- When the class has goals, the calculator still runs and `Generated.land.deltas` holds the difference
  per number; the info `package.land-override` names the largest delta. c0262 turns large deltas into a
  library rule; c0264 compares imported lands with the same report.
- Evidence: a calculated land is `INFERRED` whatever the record says; a manufacturer land keeps the
  record's label (`fenolite-component-catalog`, "Source and evidence labels").

### 8. Exposed pad and paste grid

- The exposed pad land is the `ep` nominal size, numbered `ep_number` (default `EP`, as the 0.6 QFNs), on
  `F.Cu` and `F.Mask` without paste. When a signal land comes closer than `pad_gap`, the signal land is
  shortened from its inner end (warning `package.pads-clipped`); the exposed pad is never enlarged.
- Paste: an `n × m` grid of windows on `F.Paste` with `n = max(2, ceil(side_x / paste_cell))`, likewise
  `m`, each window `4/5` of its cell per axis (64 % coverage), as the 0.6 `_thermal_paste` does for
  `n = m = 2`. `paste_cell` is a constant of the table. `[land].paste = { grid = [4, 4], window = "1.06mm",
  pitch = "1.26mm" }` overrides it (the 0.6 QFN48).

### 9. Pin numbering and orientation

- Dual rows: pin 1 at the top of the left row (the most negative y of the Y-down library frame),
  counter-clockwise in the top view; quad likewise from the upper left. *Correction (2026-10-30):* the 0.6
  helpers `_row_pads` and `_quad_pads` put pin 1 at the most positive y, the bottom of the Y-down frame
  (`docs/formats/kicad/frame.md`), which is the mirror image of the top view; `drawing/0` keeps that
  placement for the catalog's bytes and `drawing >= 1` numbers correctly; `sides`: the `numbers` of each `[[side]]` at its `positions`
  on the pitch grid (SOT-23: left `[1, 2]` at positions `[0, 2]`, right `[3]` at `[1]`).
- Grid arrays: rows lettered `A`, `B`, ... skipping `I`, `O`, `Q`, `S`, `X`, `Z`, then `AA`, `AB`, ...;
  columns numbered from 1; `A1` at the top left in the top view. The skipped letters are a public
  convention cited in `naming.md`.
- Headers: `rows-first` (default for two rows: 1 and 2 across the first column) or `columns-first`.
- Two-terminal polarized parts: pad 1 is the cathode or the negative terminal, as the catalog's
  cathode-first lands ("Default pin-to-pad map of the cathode-first lands").

### 10. Courtyard

The courtyard is one rectangle: the bounding box of the nominal body and every pad, plus `courtyard`
(500 µm), rounded outward to the grid for `drawing >= 1` (`drawing/0` keeps the 0.6 rule without
rounding). A body offset from the pad centre (a right-angle connector) gives an offset rectangle, as
`_make_footprint(body_center_y=...)` does.

### 11. Drawing conventions, versioned

- `drawing/0` is the 0.6 catalog: a fabrication rectangle of the nominal body (100 µm), the courtyard, a
  pin-1 line across the fabrication corner (`_pin1_index`), a cathode line for polarized two-terminals,
  no silkscreen, rectangular pads, no 3D model. Its only users are the migrated catalog records.
- `drawing/1` (new packages), all constants in `lands.md` under "Drawing conventions":
  - fabrication: nominal body outline, 100 µm, with a chamfer at the pin-1 corner of `min(1 mm, short
    side / 4)`; a polarity bar at the pad-1 end of polarized two-terminals;
  - silkscreen: the body outline at 125 µm, cut wherever it would come within 175 µm of copper, pieces
    shorter than 250 µm dropped; a pin-1 dot (circle, radius 150 µm) outside the body beyond the outer
    end of pad 1; for no-lead and grid packages an L mark at the pin-1 corner instead; a polarity bar
    beside pad 1 outside the pads;
  - SMD pads `roundrect` with `corner_ratio` 200 000 (20 % of the shorter side), capped at a 100 µm
    radius; through-hole pad 1 square, other pads round;
  - the 3D model path `${KIPRJMOD}/lib/Fenolite.3dshapes/<name>.step` (decision 13).
- A convention is never changed after release; a new look is `drawing/2`. *Alternative:* change the
  catalog's look in place; rejected, it would change the bytes of every existing build.

### 12. Bodies in the model

- `bodies.py` gives every generated footprint whose record gives a body height (none otherwise)
  `ComponentBody(kind="extruded")` entries with signed
  bounds: `body` (nominal outline; `z_min` = standoff min, else 0; `z_max` = height max, else nominal);
  one `lead:<number>` per lead outside the body (gull-wing foot and shoulder as two prisms
  `lead:<n>:foot`, `lead:<n>:shoulder`); `tab`; and for through-hole packages one `pin:<number>` from
  `-length_below` to the seating plane (a negative `z_min`, allowed by `component-body-volumes`).
- A round outline (TO-92, a round body) is a 32-gon from an integer table of unit vectors in
  `bodies.py`, so no float or trigonometric function is evaluated at run time.
- Ids: `derived_id("bdy", "fenolite.catalog", "<lib id>:<body name>")`.
- A KiCad build keeps the bodies in `.fenolite/` (unchanged rule). *Effect:* designs that use migrated
  catalog footprints gain bodies in `.fenolite/board.json` once the records give heights, so their
  height checks start to work; their KiCad files keep their bytes. The CHANGELOG says so.

### 13. A STEP writer of our own

- `fenolite.backends.step.write_bodies(name: str, bodies: Sequence[ComponentBody], *, timestamp: str =
  "1970-01-01T00:00:00") -> bytes` writes one ISO 10303-21 file, schema `AUTOMOTIVE_DESIGN` (AP214),
  with one product named `name`, one `MANIFOLD_SOLID_BREP` per body (planar faces, `LINE` edges, a
  vertical prism over the body's outline from `z_min` to `z_max`) in an
  `ADVANCED_BREP_SHAPE_REPRESENTATION`, millimetre units, and a colour per body by name (`body` dark,
  `lead:*`, `pin:*`, `tab` light).
- Numbers are exact decimals printed from nm (`1270000` → `1.27`, `5000000` → `5.`); no float is
  formatted. Entity numbers follow a fixed traversal; vertices are shared by exact coordinates. Two
  calls with equal arguments give equal bytes; the header names `Fenolite` without a version.
- The STEP facts (entity names, the AP214 schema identifier, the header) are recorded in
  `docs/formats/step/part21.md` from public sources (the CAx-IF recommended practices, the published
  abstract of ISO 10303-21) with labels; the oracle is `kicad-cli pcb export step` (it uses the
  OpenCASCADE reader, run as a process), recorded as `H-K-STEP-MODELS`.
- Stdlib only, no extra. *Alternatives:* an optional extra over a CAD kernel (rejected: a large native
  dependency for prisms), VRML (rejected: no solid, and `--subst-models` already prefers STEP).
- **In a build.** For each used footprint whose `models` names `${KIPRJMOD}/lib/Fenolite.3dshapes/...`,
  `fenolite build` plans `lib/Fenolite.3dshapes/<name>.step` beside `lib/Fenolite.pretty/` (and a
  `Local.3dshapes` folder for a script's own generated footprints), so `fenolite export step` and the
  viewer find it. `drawing/0` footprints name no model, so existing builds keep their files.

### 14. Naming convention for packages authored by Fenolite

Recorded in `docs/formats/library/naming.md`; the generator refuses (`FEN-3004`) a generic package
whose name does not match the numbers of its record:

```
<FAMILY><pins>_B<L>x<W>[x<H>]_P<pitch>[_EP<x>x<y>][_<variant>]    generic, from a registered outline
<FAMILY><pins>_<Maker>_<drawing id>                                 the manufacturer's own drawing (0.6 style)
```

- `FAMILY` is upper case: `CHIP`, `SOD`, `SMA`, `SOIC`, `SSOP`, `TSSOP`, `MSOP`, `QFP`, `SOT`, `QFN`,
  `DFN`, `SON`, `BGA`, `TO`, `DIP`, `HDR`, `CONN`; `L` lies along the pin rows, `W` across them, in mm
  with trailing zeros removed and nominal values; `H` only when two packages differ by height only;
  `variant` for a tab, a pitch row pattern or an orientation (`RA` right angle, `SMD`).
- Examples: `SOIC8_B4.9x3.9_P1.27`, `QFN16_B3x3_P0.5_EP1.7x1.7`, `SOT5_B2.9x1.6_P0.95`,
  `HDR2x5_P2.54_RA`, `BGA64_B8x8_P0.8`, `CHIP0603_B1.6x0.8`.
- The 0.6 names (`SOIC14_TI_D0014A`, `Chip_0402`) stay; a name is never reused for other numbers (an
  interface change makes a new id, c0259).
- Not taken from IPC's naming pattern nor from KiCad's library conventions; it only has to be unique,
  readable and checkable against the record.

### 15. Determinism and the stamp

- Equal record bytes and equal Fenolite code give equal `FootprintDef`, `.kicad_mod` and `.step` bytes.
  Pads keep the 0.6 id rule; graphics and bodies use `derived_id` over the lib id and a role name;
  iteration orders are fixed (pads by numbering order, graphics by layer then role).
- The stamp (`gullwing/1 lands/1 drawing/1 nominal`, or `... manufacturer ...`) is the start of the
  description's second sentence and of `Generated.stamp`. c0249's lock and c0279's library items can record it;
  a change of stamp with the same name is a library change that c0262 reports.

### 16. Catalog migration

c0259 moves the catalog's tuples to package records (`drawing = 0`, a `[land]` per record carrying the
0.6 numbers). This change deletes the private helpers and draws those records with the public
generators. The proof is the golden list `tests/data/catalog/footprints.sha256` captured before the
change (SHA-256 of each written `.kicad_mod`, both KiCad writer targets): all 100 entries unchanged. The
irregular footprints (switches, LED module, electrolytics, mounting holes, test point, terminal blocks,
USB connector) stay explicit pad lists of c0259 and are not generated.

*Amended 2026-10-30, after c0259 merged:* c0259 moved all 100 footprints to explicit pad lists
(`generator = "explicit"`) with byte-identical output and deleted the private helpers itself, so nothing is
left to delete here. Re-expressing the family-shaped entries as family records needs keys the 0.6 tuples never
held (span, lead length and width, required by decision 2); they are not invented. This change proves instead
that `drawing/0` reproduces six representative entries equal to their records (`test_drawing.py`) and that
every catalog `.kicad_mod` keeps the bytes captured on `circuits-as-code` 52f32e8c
(`tests/data/catalog/footprints.sha256`, both targets). Moving a record to its family is a later record
version, made when its cited sources give the missing keys.

### 17. Command: `fenolite library generate`

- `fenolite library generate PACKAGE... --out DIR [--library NICK] [--positions N] [--no-step] [--no-pcblib]
  [--dry-run | --confirm --plan ID] [--timestamp T]` plans `DIR/<NICK>.pretty/<name>.kicad_mod` and
  `DIR/<NICK>.3dshapes/<name>.step` per package (and per position of a connector series), and one
  `DIR/<NICK>.PcbLib` holding them all (open question 3); `NICK` defaults to `Local`. It writes all files or none, through plan and confirm, with a receipt.
- **Verb dispatch.** `fenolite library` keeps its c0223 form: a first argument that is not a verb is a
  board path. The verbs are `generate` here and those later changes add (`check` c0262, `import` c0264,
  `propose` and `review` c0265, `seed` c0266, `audit`, `replay`, `release` and `gallery` c0279). A board path literally named `generate` is written
  `./generate`. *Alternative:* a new top-level command `fenolite package`; rejected, the batch groups
  library work under one command.
  *Amended 2026-10-30:* c0261 merged first and defined the action table of `fenolite library`
  (`symbol`, `check`, `review`, `import`, `propose`, `fetch`); `generate` joins that table, and a board folder
  named like any action is passed as `./<name>`.
- Result (`result.packages[]`): `name`, `family`, `id`, `stamp`, `land` (`source`, `z`, `g`, `x`, pad
  sizes, `deltas`), `courtyard`, `bodies` (count, top), `files`; `issues` holds the `package.*` findings.
  Exit 5 when a package has an error finding (nothing written), 3 for an unreadable record.

### 18. Codes

Registered in `fenolite.catalog.footprints.codes` and `explain.toml`:

| code | severity | when |
|---|---|---|
| `package.missing-bound` | error | the calculator needs a bound the record does not give |
| `package.dimensions-inconsistent` | error | span not larger than body width, `pitch × (n - 1)` beyond body length, a terminal longer than half the body, an exposed pad larger than the body, a depopulated ball outside the grid |
| `package.pin-count` | error | `pins` disagrees with the arrangement, the sides or the depopulation |
| `package.no-goals` | error | the land class has no calibrated goals and the record has no `[land]` |
| `package.land-impossible` | error | the calculated or given land has no positive gap or size |
| `package.pads-clipped` | warning | a land was narrowed or shortened to keep `pad_gap` |
| `package.land-override` | info | the manufacturer's land was used; names the largest delta from the calculation |
| `package.name-mismatch` | error | a generic name disagrees with the record's numbers |

No new `FEN-` code: unreadable records are c0259's `FEN-3004`/`FEN-3002`.

## Risks / Trade-offs

- **Calibration inherits IPC-shaped numbers** from manufacturer documents that follow IPC. Mitigation:
  only per-package published numbers are used, each cited; open question 2.
- **Too few calibration records** for some classes at first. Mitigation: `package.no-goals` refuses
  rather than guesses; the record gives a `[land]`.
- **Worst-case lands are larger** than statistical ones for long tolerance chains. Mitigation: the
  pad-gap clip and the manufacturer override; documented.
- **Simple 3D** (boxes, no bends) can surprise in a render. Mitigation: documented as volumes for
  clearance, not appearance.
- **Many lead bodies** on large QFPs make `.fenolite/board.json` and Altium body records larger.
  Mitigation: measured in the tests; open question 4.

   *Recommended:* yes, the numbers are the manufacturer's published facts for its package, cited one by
   one; never the standard's tables.
   Decided 2026-10-30: the recommended answer, yes, per package and cited, never the tables.
3. Should `fenolite library generate` also write the Altium `.PcbLib`? *Recommended:* later; the Altium
   build already lowers any `FootprintDef`, bodies included. **Answered (maintainer, 2026-10-30): yes.** `library generate` also
   plans `DIR/<NICK>.PcbLib` through `fenolite.backends.altium.pcblib.write_pcblib` (`--no-pcblib` leaves it
   out); tasks 3.7 and 6.2b.
4. One body per lead, or one merged lead body per side? *Recommended:* one per lead (exact volumes),
   revisit if files grow beyond 1 MB for a 208-pin QFP.
   Decided 2026-10-30: the recommended answer, one body per lead.
5. Is `Local` the right default library nickname for generated files outside the catalog?
   *Recommended:* yes, as `docs/dsl.md` already uses it for authored footprints.
   Decided 2026-10-30: the recommended answer, `Local`.
