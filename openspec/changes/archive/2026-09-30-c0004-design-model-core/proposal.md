## Why

Every backend, check and export in Fenolite reads and writes one neutral in-memory model. If that model is shaped by the first backend it meets, the second backend will not fit — the classic failure of single-tool toolkits. This change writes the one-page model specification (entities, units, ids, provenance, extensions, canonical serialisation, authority rules, backend "slots") and implements the `core` and `model` packages that everything else imports, before any KiCad or Altium code exists. The model is deliberately small; it grows per change, driven by real files, and freezes only after the second backend.

## What Changes

- `openspec/specs/design-model/spec.md` (one page, normative): common entity header `{id, native_ids, provenance, ext}`; integer nanometre lengths and integer microdegree angles; id derivation rules (`uuid5` for imported objects, seeded `uuid4` for created ones; never derived from a file hash); provenance record; per-backend extension bags with `min_version`; layout authority table; the "slots" mechanism backends must implement for lossless round-trip.
- `src/fenolite/core/`: `units.py` (parse/format lengths and angles; exact integer conversion to and from 1/10000 mil with documented rounding), `ids.py`, `provenance.py`, `evidence.py` (label vocabulary and the "lowest level wins" rule), `errors.py` (`FormatError(file, locator, offset)`, `ConsistencyError`, `Issue`), `io.py` (atomic write with `.bak`, SHA-256).
- `src/fenolite/model/`: `circuit.py`, `board.py`, `rules.py`, `manufacturing.py`, `findings.py`, `design.py` (container with indexes `by_id`, `by_ref`, `by_net`, `by_layer`), `canonical.py` (canonical JSON writer/reader), `schema.py` (schema ids `fenolite.<layer>.v0`).
- `schemas/fenolite.model.v0/*.json` generated by `tools/gen_schemas.py`, with a drift test.
- ADR-0001 "Neutral model: small now, frozen after the second backend; integer nm; uuid ids; ext bags".
- Property-based tests (`hypothesis`, dev extra) for units, ids and canonical idempotence.

## Capabilities

### New Capabilities
- `design-model`: the normative model specification (entities, units, ids, provenance, ext, authority, slots).
- `canonical-serialization`: deterministic JSON form of a design, ordering rules, idempotence, schema generation and drift control, the derived `.fenolite/` cache.
- `core-primitives`: units, ids, evidence labels, errors and atomic I/O exposed by `fenolite.core`.

### Modified Capabilities
- (none)

## Non-goals

- Presentation layer for schematics (`Sheet`, `SymbolInstance`, `Wire` … arrive with the schematic backend), `Bus`, `DifferentialPair`, `Variant`, full `Padstack`, 3D bodies (later changes).
- Any file format code, any query engine, transactions, undo, migrations (migrators start at schema 1.0).
- Floating-point anywhere in the model.

## Evidence level required

- Model behaviour is mechanical (unit and property tests). Format-derived constants used here — the 1/10000 mil unit of the second backend and the nanometre unit of the first — are recorded in `docs/evidence/sources.md` with their public documentation sources and labelled `INFERRED` until a corpus file confirms them (`docs/hypotheses.md` rows `H-K-UNIT`, `H-A-UNIT`).

## Impact

- `fenolite.core` and `fenolite.model` become the dependency root of every later package (see `package-layering`).
- `schemas/` gains the model schema files; `docs/adr/0001-neutral-model.md` is written.
