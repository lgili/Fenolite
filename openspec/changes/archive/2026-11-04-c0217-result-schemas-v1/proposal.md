## Why

The roadmap puts "per-command result schemas" in the v1.0 freeze (`docs/roadmap.md`, "Open decisions",
row 14: "result schemas with the v1.0 freeze"). Today two of the 46 visible commands have one:
`schemas/fenolite.equivalent.v0.json` and `schemas/fenolite.convert.v0.json`, written from the wire classes
of `fenolite.api.schema` and checked by the consistency suite. The other 44 commands return a `result` whose
shape exists only in their code and in prose in `docs/cli-contract.md`, so an agent parses it by example and
a renamed key passes every test. The same holds for the files Fenolite reads or writes beside a design: about
thirty ids of the form `fenolite.<name>.v0` are in the code (`review`, `requirements`, `drawing-spec`,
`placement-request`, `artifacts`, `export-preset`, `assembly-template`, `build-record`, the kit's files, the
viewer's documents), three of them with a schema file.

This is the second of the five changes of the freeze (c0216 to c0220). It depends on c0216's
`CONTRACT_VERSION`.

## What Changes

- **A result schema for every visible command**: `schemas/fenolite.<command>.<version>.json`, generated by
  `tools/gen_schemas.py` from wire classes, as `equivalent` and `convert` are. A command's result is
  described as it is today; a key that its schema exposes as inconsistent (one key with two types, a list
  that is sometimes a map) is fixed, each listed in the change.
- **The consistency suite** fails for a visible command without a result schema, and validates the result
  of every example against it, in a closed form (no key the schema does not name).
- **Published schemas are open**: an object allows keys it does not name, so a `1.x` addition does not
  break a consumer that validates with `1.0`'s schema; the closed form is for Fenolite's own tests.
- **File formats**: each format that a user writes or that an agent reads (inputs such as `requirements`,
  `drawing-spec`, `placement-request`, `export-preset`, `assembly-template`, `review`; outputs such as
  `artifacts`, `build-record`, the panel model and the kit's files) gets a schema file, and its readers
  accept `v0` and `v1`. Formats that only Fenolite writes and reads (the viewer's documents, the kit's form)
  are marked internal and keep no promise (the maintainer's answer of 2026-10-27).

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `cli-contract`: MODIFIED "Consistency test covers every command"; ADDED "Result schemas", "File format
  schemas".

## Non-goals

- The model's own layers (`schemas/fenolite.model.v0/`): c0218.
- No new content in any result.
- A schema of `--fields` projections: a projection is a subset of the result and is validated by nothing.

## Evidence level required

- Mechanical: every command's example result validates against its schema in the consistency suite, and the
  generator's drift check passes. No format claim.

## Impact

- New: one wire module per command family (`src/fenolite/cli/results/*.py`), about 44 result schema files
  and the schemas of the public file formats.
- Changed: `tools/gen_schemas.py`, `tests/consistency/test_cli_consistency.py`, the readers of the file
  formats, `docs/cli-contract.md` (each command names its schema), `schemas/README.md`.
- Size: about 8 days.
