## Why

The roadmap's v1.0 freeze asks for a "published conformance matrix (format × version × operation ×
evidence)" and "no `INFERRED` without a hypothesis, no `UNVERIFIED` outside `experimental`"
(`docs/roadmap.md`, "Phase 5: to 1.0"). Part of it exists: `docs/evidence/matrix.md` and
`capabilities`' `result.matrix` give, per backend and file kind, the label of `detect`, `read`, `write` and
the two round trips, and the matrix already requires an `UNVERIFIED` operation to be experimental. Two parts
do not:

- **No version axis.** A row says `KICAD-VERIFIED` without saying for which format versions (the KiCad board
  formats `20241229` of 9.0 and `20260206` of 10.0, `docs/formats/kicad/versions.md`), nor for which Altium
  Designer version a kit run settled it.
- **The rules hold for declarations, not for replies.** c0200 (archived on 2026-10-27) made every
  `Evidence(Level.INFERRED)` of the source name a hypothesis, through a source test; what a reply carries
  is still unchecked. Measured on 2026-10-28 over the example of every command: `view` answers `INFERRED`
  with no hypothesis, and `analyze` and `route` answer `UNVERIFIED` while their results make claims.
  `capabilities`, `doctor`, `edit`, `explain`, `fetch`, `guide`, `init`, `manifest`, `mcp`, `publish`,
  `restore` and `skill` answer `UNVERIFIED` as well; most of them claim nothing about a design, and no rule
  says so.

This is the fourth of the five changes of the freeze (c0216 to c0220).

## What Changes

- **Versions in the matrix**: each operation of a row gains the format versions it was verified on, each
  with its evidence (`{"version": "20260206", "tool": "kicad-cli 10.0.6", "level": "KICAD-VERIFIED"}`);
  an Altium cell names the kit run and the Altium Designer version that settled it.
- **Published**: `docs/evidence/conformance.md` and `docs/evidence/conformance.json`, generated by
  `tools/gen_evidence_matrix.py`, and the JSON attached to each GitHub release by `release.yml`.
- **Rules on every reply**: a reply whose `evidence.level` is `INFERRED` names at least one hypothesis,
  and a reply that is `UNVERIFIED` comes from a command that claims nothing (a closed list,
  `fenolite.cli.api.NO_CLAIM`) or names an experimental feature. The consistency suite checks every
  example, and the envelope writer refuses a reply that breaks a rule in tests (`FEN-1001` in a debug mode).
- **The gaps closed**: `view`, `analyze` and `route` give a level and hypotheses that their results
  support (`route` the Specctra rows it relies on), and the commands that claim nothing join the no-claim
  list (the maintainer's answers of 2026-10-27; open question 4 for the commands added since).

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `cli-contract`: MODIFIED "Evidence matrix in capabilities"; ADDED "Evidence of every reply".
- `verification-evidence`: ADDED "Published conformance matrix".

## Non-goals

- No new verification: a version is listed only where a test or a kit run already verified it.
- No level is raised by this change.
- Levels of analyses (their numbers against a standard) are the analyses' own (`board-analyses`).

## Evidence level required

- Mechanical: the generator, the consistency suite and the release workflow's test. A version listed in a
  cell is one that a test or a recorded kit run names; the generator refuses one that none names.

## Impact

- Changed: `backends/matrix.py` and the `claims` modules, `tools/gen_evidence_matrix.py`,
  `cli/api.py`, `cli/cmd_capabilities.py`, the five commands of the gaps,
  `tests/consistency/test_cli_consistency.py`, `.github/workflows/release.yml`.
- New: `docs/evidence/conformance.md`, `docs/evidence/conformance.json`.
- Size: about 4 days.
