## Decisions

1. Add `catalog view --out FILE` instead of another search mechanism: `list_entries` already provides stable offline case-insensitive filtering over ID, category and summary.
2. Compose the existing `fenolite.view_library.v0` scenes into a standalone page with `view.export.page`. Include virtual Symbols and Footprints documents only when they have matches. Use the existing browser item filter, measurement and selection tools; do not add another renderer.
3. Symbols use the authored in-memory KiCad symbol writer, parser and symbol scene builder. Footprints use the shared library-item builder with the KiCad board frame, which supplies pad primitives. This is internal geometry conversion, with no CAD executable or temporary CAD file.
4. Keep catalog metadata and scene evidence `INFERRED`; include exact lib IDs, category, description, public source IDs, pin roles and pad details. Generic symbol roles and land patterns do not establish device compatibility or manufacturing qualification.
5. Declare the command as potentially mutating, with an explicit mutation example, while list/show continue returning no writes and exit 0. Import preview code lazily only for view. `--out` on list/show, missing `--out` for view and a view positional ID are usage errors.
6. Empty view filters return `FEN-3001`, a hint to change the filters and no write. Empty list results keep their existing successful behavior.
7. Generate stable scene IDs and content hashes and avoid wall-clock data in the page. The dispatcher owns staging, byte replay, backups and receipts through one PlannedWrite.
8. Browser review showed that authored symbol properties at default coordinates obscure the drawing and inflate fitted bounds. Suppress those fields only for catalog scenes through an optional existing-renderer switch, keeping metadata in item properties and leaving definitions and ordinary library viewing unchanged. Show footprint fabrication and courtyard layers initially. Pad IDs remain available by selection; do not list every pad number in the initial properties panel.
9. Preserve package layering: the CLI resolves installed catalog IDs into immutable viewer-owned input records containing metadata and a `SymbolDef` or `FootprintDef`. The viewer consumes those model definitions without importing or querying the catalog. Its permitted dependencies stay model, backends and view; no layering exception is added. Preserve the existing generated bytes for identical inputs.

## Verification

The catalog metadata panel uses a native details/summary control, initially collapsed. This keeps the drawing unobstructed and gives keyboard activation without adding a second navigation system; existing file-backed library panels keep their current presentation.

Cover every installed definition, exact pad sizes/rotations and symbol pin counts, catalog metadata, deterministic bytes and filter selection. Exercise confirmation, dry-run, staged replay and unchanged targets on empty/invalid input. Block network and subprocess calls in a focused offline proof. The coordinator performs browser review after this implementation; only fast and focused checks run locally.
