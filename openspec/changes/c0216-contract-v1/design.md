## Context

- Commands are `fenolite.cli.cmd_*` modules, each with a `COMMAND` (`cli/api.py`, `Command`): 50 modules on
  2026-10-29, `_echo` hidden (`help=None`), 49 visible (`edit`, `mcp`, `publish`, `refs` and `snapshot` among
  them, from c0195, c0196 and c0201; `library`, `silk` and `tidy` from c0204 to c0229). Options come from each command's `register(parser)`.
- `Command.schema` returns `fenolite.<name>.v0` (`cli/api.py`); `schemas/fenolite.envelope.v0.json` and
  `schemas/fenolite.error.v0.json` are generated by `tools/gen_schemas.py`.
- Registries that the surface reads: `cli.errors.REGISTRY` (24 `FEN-` codes with their exit codes),
  `cli.explain.TABLES` (70 tables, 707 issue codes with severities), `capabilities`' `result.experimental`
  (features named by command and option).
- `tests/consistency/test_cli_consistency.py` runs every command's example and validates its envelope.
- Measured on 2026-10-28 over the examples of every command: every envelope says `fenolite.<name>.v0`.
- The MCP server (c0195) serves every public command as a tool built from the same parsers, so the
  surface is also the MCP server's tool list; c0195's tests of the tool list follow the surface.

## Goals / Non-Goals

**Goals:** a written surface; a test that tells a breaking change from an addition; `v1` envelope and
error schemas behind one constant; a deprecation path; the maintainer's pre-freeze review.

**Non-Goals:** result schemas (c0217), the model (c0218), the evidence rules (c0219).

## Decisions

1. **The surface is data, generated** (`docs/cli-surface.json`, sorted keys, LF): `{"contract": "v1",
   "commands": {name: {"mutates", "paged", "default_limit", "experimental", "deprecated", "exclusive",
   "options": {flag: {"type", "choices", "default", "required", "nargs", "experimental",
   "experimental_choices", "deprecated"}}}}, "exit_codes": {...}, "fen_codes": {code: exit}, "issue_codes":
   {code: {"severities", "experimental", "deprecated"}}, "library": {module: {name: {"kind", "parameters",
   "fields", "methods"}}}}`. Global options are one entry `"*"`; a positional is keyed `<dest>` with its
   `position`; `exclusive` lists the mutually exclusive groups; the mutation flags are options of each
   writing command. An issue code keeps every severity its tables give it (a few codes have two). Hidden commands are left out: they are not part of
   the contract. `library` holds every name of `fenolite.dsl.__all__` and `fenolite.api.__all__`: for a
   function its parameters with their kinds and defaults, for a class its public fields and methods
   (open question 1, decided).
2. **Experimental items are marked, not left out.** An option is experimental when `capabilities` names it
   in `result.experimental`; when the entry names one choice (`--target altium` of `build`), that choice
   goes to the option's `experimental_choices`, and the options of the same command whose flag starts with
   `--<choice>-` (`--altium-pour`) are experimental: they only act with that choice. An issue code is
   experimental when every table that holds it is a table of the Altium writers
   (`fenolite.cli.surface.EXPERIMENTAL_TABLES`: `fenolite.lens.altium*`). The judge lets them change.
   `capabilities` reads its entries from `cmd_capabilities.experimental_features()`, which the surface
   calls too, so both always agree.
3. **The judge** (`fenolite.cli.surface`):
   - `cli_surface(commands: Mapping[str, Command]) -> Surface` (a frozen dataclass with `to_json()`);
   - `surface_changes(before: Surface, after: Surface) -> tuple[SurfaceChange, ...]`, each
     `SurfaceChange(kind, path, before, after, breaking)` with `kind` in `added`, `removed`, `narrowed`,
     `default-changed`, `type-changed`, `required-added`, `severity-raised`, `severity-lowered`;
   - breaking: `removed`, `narrowed`, `default-changed`, `type-changed`, `required-added`,
     `severity-raised`, unless the item is experimental or `deprecated` before the change; for a library
     name, a removed name, a removed or renamed parameter, a parameter without a default added, a changed
     parameter kind or position, or a removed field or method (a changed default of a library parameter is
     reported, not breaking). Marking a stable item experimental is breaking: it would free it.
   The baseline is the surface of the last release tag (`git show <tag>:docs/cli-surface.json`); before
   1.0 the baseline is the committed file, so the test is a drift check until `1.0.0` is tagged.
4. **One constant** `fenolite.cli.api.CONTRACT_VERSION = "v0"`; `Command.schema` and the envelope's
   schema file follow it. The release change of `1.0.0` sets `"v1"`; tests run with both values
   (`monkeypatch`) so that the switch is one line. `gen_schemas.py` writes both envelope versions; the
   `v0` files stay byte for byte.
5. **Deprecation.** `Command` gains `deprecated: str | None` (the release that replaced it), and an option
   is deprecated through `fenolite.cli.api.deprecate(parser, flag, since=, use=)`. Using one gives one
   `cli.deprecated` (warning) naming the replacement; `capabilities` lists `result.deprecated`.
6. **The pre-freeze review** (`tools/gen_cli_surface.py --review --out FILE`): for each option, whether a
   test (a file of `tests/` that names the command and the flag), an example, the agent guide and
   `docs/cli-contract.md` (one paragraph naming both, or the command's section) name it; the flags that take
   another type or other choices on another command; the `--<choice>-` flags of an experimental choice on a
   command where they are not marked experimental; each hidden command; each issue code that no test names.
   The list goes to the maintainer; each renamed item keeps its old name as deprecated.

## Evidence level per behaviour (before merge)

| behaviour | level |
|---|---|
| surface generated from the code | mechanical (drift test) |
| breaking changes refused | mechanical (unit tests of each kind) |
| envelopes validate against `v1` with the constant set | mechanical (consistency suite) |

## Risks / Trade-offs

- A change that only alters behaviour (same flag, other meaning) is not seen by the judge; the stability
  text names it as breaking, and review catches it.
- Marking experimental items lets a writer change freely through 1.x; that is the intent of
  `experimental`, and `capabilities` says it.

## Open questions

The maintainer accepted every recommended answer below on 2026-10-27 (roadmap, "Open decisions", row 49).

1. Is the library API (`fenolite.api`, `fenolite.dsl`) frozen with the CLI? Recommended: `fenolite.dsl` and
   `fenolite.api` yes, listed in the surface as a second section; every other module stays internal. Decided by the maintainer on 2026-10-27: as recommended.
2. When do envelopes say `v1`? Recommended: in the release of `1.0.0` (one constant), so that `0.6.0`
   still says `v0` and no agent sees `v1` before the freeze holds. Decided by the maintainer on 2026-10-27: as recommended.
3. Hidden commands (`_echo`): out of the contract. Recommended: yes. Decided by the maintainer on 2026-10-27: as recommended.
