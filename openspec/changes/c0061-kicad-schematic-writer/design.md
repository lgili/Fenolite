## Context

- **Scope.** Plan D10, v0.2a: "a minimal `.kicad_sch`: one symbol per `Part` on a grid by module, a `global_label` per net, embedded `lib_symbols`, the `title_block` of the sheet spec, no pretty routing, positions fixable in `schematic-placements.toml`; enough for `sch erc`, `--schematic-parity` and `sch export netlist`", and "`fenolite.path` on the symbol too". The living `design-dsl` already announces it: no-connect marks are lowered "to KiCad's no-connect flags" by "the KiCad schematic writer of v0.2a", and symbol libraries "get the same rule" as vendored footprints "when built projects get schematics".
- **What exists.** `build_design` writes the triad, `fp-lib-table`, vendored footprints and `.fenolite/` (c0011, c0027); it resolves every symbol into a `SymbolDef` whose sub-symbols are slots (c0008); components carry `pin_pad_map` (c0056) and `Circuit.no_connects` (c0036); `Interface(kind="power")` marks supply nets (c0011). c0060 adds `SchematicSheet` and the reader. A built footprint has no `path` child today.
- **Measured at proposal time** (2026-10-04), with a sheet written by hand for the built blink (three parts, four nets, 29 unconnected pins of the IC), on `kicad-cli` 9.0.9 (pinned image, format `20250114`) and 10.0.6 (macOS, `20260306`):
  - **Loads.** Header, `uuid`, `paper`, `lib_symbols`, `symbol` instances (`lib_id`, `at`, `unit`, `exclude_from_sim`, `in_bom`, `on_board`, `dnp`, `uuid`, properties, one `pin` with a uuid per pin, `instances`), `global_label` (`shape`, `at`, `effects`, `uuid`), `no_connect` and `sheet_instances` load on both majors. A pin of a symbol at (x, y), not rotated, connects at (x + px, y − py): labels placed there connect every pin.
  - **ERC, labels only.** 37 violations on both: 29 `pin_not_connected`, 2 `pin_not_driven`, 2 `power_pin_not_driven` (errors), 3 `lib_symbol_issues` ("The current configuration does not include the symbol library …", warnings), and one warning for the label on the single-pin net (`isolated_pin_label` on 10.0.6, `global_label_dangling` on 9.0.9).
  - **ERC, complete.** With a no-connect flag on each unconnected pin, a power-flag symbol (one `power_out` pin, `(power)`) on each net of the power interface, and a project `sym-lib-table` naming libraries that hold the embedded symbols: 0 violations and exit 0 with `--exit-code-violations`, on both majors.
  - **Netlist.** `sch export netlist` names the nets after the label texts (`GND`, `LED_A`), takes the net class from the project (`PWR`), and names each pin on no net `unconnected-(U1-PA1-Pad2)`, or `unconnected-(U1-Pad16)` for a pin without a name; equal on both majors.
  - **Parity.** `pcb drc --schematic-parity` on the built board: 29 `net_conflict` warnings ("Pad missing net given by schematic (unconnected-(U1-PA1-Pad2))"). With those names written on the pads: 0 parity issues, on both majors.
  - **On 10.0.6 only:**
    - parity matches by reference: exchanging the `path` of two footprints, or giving one a path that names no symbol, changes nothing; a changed Value gives `footprint_symbol_mismatch`; a renamed reference gives `missing_footprint` and `extra_footprint`;
    - a multi-unit symbol names an unconnected named pin with the unit letter (`unconnected-(U2C-GND-Pad7)`) and an unnamed pin without it (`unconnected-(U2-Pad1)`); a `/` in a pin name becomes `{slash}`, a blank becomes `_`;
    - a global label `mod/LED_A` gives the net `mod{slash}LED_A`; parity then reports `net_conflict` against a pad stored as `mod/LED_A` and nothing against a pad stored as `mod{slash}LED_A`, which reports show as `mod/LED_A`; 20 other texts (blanks, brackets, braces, quotes, non-ASCII letters) are taken as they are;
    - two hidden `power_in` pins named `VSS`, labelled `GND` and `OTHER`, end on one net (`multiple_net_names` warning): hidden power inputs join a global net of the pin's name;
    - `sch upgrade --force` re-saves the sheet with the items sorted by kind, `body_style` and `in_pos_files` added to symbols, `show_name` and `do_not_autoplace` added to properties, `hide` moved out of `effects`, an `Intersheetrefs` property added to each global label, and `embedded_fonts` dropped; ERC still passes and a second re-save is byte-identical.
- **Constraints.** No runtime dependency; `build` needs no KiCad. Nothing from KiCad's libraries is committed: the power flag is authored for Fenolite.

## Goals / Non-Goals

**Goals:**
- A built project that KiCad's ERC and parity test accept without a finding, on 9.0 and 10.0, for the examples.
- One source of truth: the circuit. The schematic is regenerated by every build and is byte-identical for an unchanged design.
- A board that "Update PCB from Schematic" has nothing to change on.

**Non-Goals:**
- Everything under "Non-goals" in the proposal.
- A drawing a person would want to read. v0.2b does that.

## Decisions

1. **Probe first.** Task group 2 turns every measurement above into a probe on both majors before the generator is written: the pin frame for the four rotations and two mirrors, the names of unconnected pins, label texts, the power flag and hidden power pins, library rows, parity matching. A probe that contradicts a decision below changes the decision in this file first.

2. **The schematic is an output of `build`.** `build_design` gains the steps of Decision 12 and returns `<name>.kicad_sch`, `sym-lib-table` and `lib/<nickname>.kicad_sym` with the triad. `fenolite build --schematic write|skip` (default `write`); `skip` gives the v0.1 files and a board without the lowerings of Decisions 9 to 11.
   - Rejected: a separate `sch build` command (the plan's word). Board and schematic must agree on references, pad nets and symbol paths; two commands could build them from two states of the script.

3. **One flat sheet.** `<name>.kicad_sch` is the root and only sheet, page `1`. The paper is the smallest of A4, A3, A2, A1 and A0, landscape, that holds the layout of Decision 13; a design that does not fit A0 is refused (`build.schematic-too-large`) and names v0.2b's sheets per module.

4. **Symbols.** One `SymbolInstance` per unit of each component, body style 1, every unit of the symbol placed (ERC reports unplaced units). Its fields:
   - `ref`, `value`, `footprint` (the lib id of the placed footprint);
   - `properties`: the component's `properties` as the build writes them on the footprint (Reference, Value, Datasheet, Description, the user properties of c0027 and `fenolite.path`), plus `Footprint`. Reference and Value are visible, the others hidden. One set of fields for symbol and footprint keeps parity's field comparison quiet and lets `sch export bom` (c0064) see the user properties;
   - `dnp` from `Component.dnp`; `in_bom` false when the footprint has `exclude_from_bom`; `on_board` true;
   - one use: project `<name>`, path `/<root uuid>`, the reference and the unit.
   - A component without a resolved symbol (a board-only footprint kept by the lens) gets no symbol.

5. **Connections are global labels.** Each pin that a net lists gets one `NetLabel(kind="global")` at its connection point, with the net's stored name (Decision 9), shape `passive`, turned away from the body. No wire, no junction, no local label.
   - A pin that `Circuit.no_connects` marks gets a `NoConnectFlag` at its connection point. A pin that is on no net and not marked gets nothing: KiCad's ERC then reports it, which is the finding the user needs.
   - A net with one pin gets its label: KiCad warns (`isolated_pin_label`, `global_label_dangling`), as `model.single-pin-net` does.

6. **Pin frame.** The connection point of a pin at (px, py) in the library frame (Y up), for an instance at (x, y): first the mirror (`x`: py → −py; `y`: px → −px), then the rotation by the instance angle, then (x + px′, y − py′). The rotation sense and the order are settled by the probes `sch-pin-frame-*`; until a combination is proved, `schematic-placements.toml` may not ask for it (`build.symbol-placement-invalid`).

7. **Power flags.** For each net of an `Interface(kind="power")` that no `power_out` pin of a part that is not DNP drives, the sheet gets one flag: an instance of `fenolite:PWR_FLAG` (authored: a symbol flagged `power` with one `power_out` pin, reference `#FLG<nn>`, `in_bom` and `on_board` false) with the net's global label on its pin.
   - This is the rule of `erc.lite.power-undriven`, stated to KiCad. A net with power inputs, no power output and no power interface keeps KiCad's `power_pin_not_driven`.
   - The library nickname `fenolite` is reserved: a design that names a library `fenolite` is refused (`build.reserved-library`).

8. **Embedded symbols** (`symembed.py`). `lib_symbols` holds one definition per distinct symbol used, built from the resolved `SymbolDef` and its slots:
   - **Flattened.** A derived symbol takes the sub-symbols of its root parent, renamed to its own name, and its own properties over the parent's, as `sym.resolve_extends` does for the model.
   - **Pad numbers.** For a component with a `pin_pad_map`, the `number` of each mapped pin is replaced by its pad number, and the definition is embedded under `<name>_<8 hex digits of the SHA-256 of the sorted map>`. KiCad ties a symbol pin to the pad of the same number, so the netlist and parity then speak in pad numbers.
   - **Hidden power inputs shown.** A hidden pin of type `power_in` is embedded without its `hide`, because KiCad joins hidden power inputs of one name into one global net whatever label they carry. `kicad.sch.power-pin-shown` (info) names the symbol.
   - **Gated.** `versions.check_emittable` runs on each definition for the target with c0060's inventory rows. A token the target does not read is refused (`LossyWriteError`, `FEN-7001`) or, with `--allow-lossy`, dropped with a warning, as footprints are.
   - **Project libraries.** The same nodes, under their bare names, are written to `lib/<nickname>.kicad_sym`, one file per nickname, and `sym-lib-table` names each file. The embedded copy and the library copy are equal by construction, so ERC reports neither `lib_symbol_issues` nor `lib_symbol_mismatch`.
   - With `--vendor project`, symbols of rows that are not project rows are embedded but get no library file and no row (`build.global-library`, info), as footprints do. The `fenolite` library is always written.
   - Rejected: copying whole library files byte for byte, as footprints are. One official symbol file holds hundreds of symbols, and a derived symbol would still have to be flattened for the embedded copy.

9. **Net names in KiCad's stored form** (`netnames.py`). KiCad reserves `/` for sheet paths: a label text with a slash names the net with `{slash}`, and reports show it with the slash.
   - `stored_name(name)` replaces `/` by `{slash}`; `model_name(stored)` is its inverse.
   - The board writer writes a created net (no `kicad` native id) with `stored_name`; a net read from a file keeps its spelling. The board reader gives a net stored with `{slash}` the model name with the slash and keeps the spelling as its native id; if another net of the board already has that name, the stored spelling stays the name (`kicad.board.net-name-collision`, info).
   - Labels carry `stored_name(net.name)`. Every other character is written as it is (probe `sch-label-chars`).
   - A design net named `mod/LED_A` therefore reads back as `mod/LED_A`, and a v0.1 board that stored it raw is rewritten with the stored form on the next build.
   - Rejected: refusing `/` in net names. `docs/dsl.md` recommends `Net(f"{m.path}/FB")` for module nets.
   - Rejected: unescaping every net read from a board without keeping the spelling. A hierarchical net `/a/b` and a literal `{slash}a{slash}b` would be written back alike.

10. **Pads of unconnected pins take KiCad's names, in the written board only.** `netnames.unconnected_name` gives the name KiCad derives for a pin on no net: `unconnected-(<ref><unit letter>-<pin name>-Pad<number>)`, or `unconnected-(<ref>-Pad<number>)` for a pin without a name; the unit letter (`A` to `Z`) appears only for a named pin of a symbol with more than one unit; in the pin name a blank is `_` and `/` is `{slash}`.
    - `lens.build.lower_for_schematic(design, generated)` returns the design handed to `write_triad`: each pad whose pin is on no net and whose symbol is on the sheet gets a net of that name (id `derived_id("net", "fenolite", "unconnected:<component path>:<pad>")`, no class, no member).
    - The stored layout (`BuildOutput.layout`, `.fenolite/`) keeps those pads on no net: `merge_layout` takes pad nets from the built design, as today. `Design.validate()`, the no-connect marks and every model query are untouched.
    - `netlist.assignment_compare` then compares a model with pads on no net against a board with one single-pad net per such pad. Its partition rule changes: a pad on no net is a block of its own, not a member of one shared `NO_NET` block. Two pads on no net were never connected to each other, so the old rule only held while both sides spelled "no net" the same way.
    - A pin name outside the proved set (a probe gave `different`, or a character this change did not probe) leaves the pad on no net, with `kicad.sch.unconnected-name-unproven` (warning): parity may then report that pad.
    - Rejected: nets for unconnected pins in the circuit model. A marked pin would be "on a net" (`model.no-connect-on-net`), and every such net would be a `model.single-pin-net` warning.
    - Rejected: folding such nets to "no net" when a board is read. The export side of the assignment compare lists them as nets, and native boards compare equal today.

11. **Footprints carry the path of their symbol.** `Component.path` of the lowered design is `/<uuid of the instance of the lowest unit>`, which `write_board` already emits as `(path …)`. Parity ignores it (observed), but KiCad's update matches footprints to symbols by it, and would otherwise replace them. `sheetname` and `sheetfile` are not written.

12. **Build steps.** After the build checks and before `write_triad`:
    1. `schgen.generate_schematic(built, parts, name=…, target=…, placements=…, vendor=…)` returns the sheet, the library nodes per nickname, the table rows, the pad-net names and the symbol paths;
    2. `lower_for_schematic` applies Decisions 10 and 11;
    3. `write_triad` writes the lowered design; the readback and the layout follow as today;
    4. `sch.write_schematic(sheet, target=…)`, `symembed.write_symbol_library` per nickname and `libs.write_lib_table(LibTable("symbol", rows))` add their files; all are in `build.json`.
    - With an existing board, step 1 uses the merged layout's components, so a board-only footprint gets no symbol and KiCad's parity reports it unless it carries `board_only`.

13. **Layout** (`schlayout.py`; every number is a Fenolite choice).
    - Units are sorted by top-level module (parts outside a module first), then by natural order of the component path, then by unit. Each unit takes one cell.
    - A cell is the bounding box of the unit's pin connection points and body, grown on each side by the room for its labels (`CHAR_ROOM` 1.524 mm per character of the longest label on that side, plus 5.08 mm) and by `CELL_MARGIN` 5.08 mm, with 7.62 mm above for Reference and Value. Sizes are rounded up to 2.54 mm.
    - Cells fill rows from the left, inside a page margin of 12.7 mm and above a band of 40.64 mm kept for the title block. A new module starts a new row. Power flags take a last row.
    - Symbol origins lie on the 2.54 mm grid, so pins that the library puts on the 1.27 mm grid stay on it (KiCad's ERC warns about endpoints off that grid). A pin off the 1.27 mm grid in its library gives `kicad.sch.pin-off-grid` (info).
    - Rotation 0 and no mirror, unless Decision 14 says otherwise.

14. **`schematic-placements.toml`.** An optional file beside the design script, read with `tomllib` and `parse_float=Decimal`: one table per symbol, keyed by component path, or `<path>#<unit>` for a unit above 1; keys `x` and `y` in millimetres (the symbol origin; multiples of 1.27), `rotation` (0, 90, 180, 270) and `mirror` (`"x"`, `"y"`).
    - A placed unit keeps its position and leaves the automatic flow; the others are laid out around the cells of the placed ones as if those were absent, and two cells that overlap give `build.symbol-overlap` (warning), never an error: an overlap is ugly, and it is a short only when two connection points coincide, which is an error (`build.symbol-short`).
    - An unknown path gives `build.symbol-placement-unknown` (warning). A value off the grid, an unknown key or an unproved rotation gives `build.symbol-placement-invalid` (error).

15. **Writing per target.** `sch.write_schematic(sheet, *, target, allow_lossy=False) -> WriteResult` writes a created sheet: header `(version FORMAT_VERSIONS[SCHEMATIC][target])`, `(generator "fenolite")`, `(generator_version "<target>.0")`.
    - Target 10 follows what KiCad's own re-save keeps: items in the order `no_connect`, `global_label`, `symbol`, then `sheet_instances`; `body_style` and `in_pos_files` on symbols; `hide`, `show_name` and `do_not_autoplace` as children of a property; an `Intersheetrefs` property on each global label. Target 9 writes the set that 9.0.9 loaded: `hide` inside `effects`, no `body_style`, no `in_pos_files`, and `embedded_fonts no`.
    - The emit check runs on the final tree. A sheet read from a file is not written by this function: `rebuild_schematic` (c0060) keeps its version.
    - Identity with KiCad's printer is not a goal (plan D2); the probe `sch-gen-resave` records what a 10.0 re-save still changes.

16. **Uuids and determinism.** Created entities have ids derived from the design (`design-model`, "Identifiers of schematic entities"): symbol instance `<name>:<component path>#<unit>`, label `<name>:label:<component path>:<pin>`, flag `<name>:nc:<component path>:<pin>`, power flag `<name>:flag:<net name>`, and its label `<name>:label:flag:<net name>`. KiCad uuids come from c0017's `pcb.kicad_uuid`, pin uuids from the instance id and the pin number. No date and no path is written. Two builds give identical bytes.

17. **An edited schematic is replaced.** The sheet is a view. When `<name>.kicad_sch` exists and is neither the planned bytes nor the bytes of the last build, `cmd_build` reports `build.schematic-replaced` (warning) and the mutation protocol keeps a `.bak`. `sym-lib-table` and the symbol libraries follow "Edited outputs are not overwritten", as `fp-lib-table` does.
    - Rejected: refusing, as for vendored files. Opening and saving the sheet in KiCad changes its bytes without changing its content; a build that refuses after every look at the schematic would be unusable.
    - Rejected: adopting symbol positions from the edited file. That is the schematic lens (v0.5b); until then positions live in the placements file.

18. **Stand-in for "Update PCB from Schematic".** No headless command runs KiCad's update. `tests/_layout_edit.py` gains `update_from_schematic(board_text, schematic_text)`: it adds `sheetname` and `sheetfile` to each footprint, sets its `path` from the symbol and rewrites each footprint property from the symbol's field. A rebuild over that board must keep every position, every track and every pad net. What the real update writes is the maintainer's report (Open Questions).

19. **Evidence.** `schgen.EVIDENCE` starts `INFERRED` and is raised when `H-K-SCH-MINIMAL`, `H-K-SCH-UNCONNECTED` and `H-K-SCH-PARITY` are `KICAD-VERIFIED (9.0.x, 10.0.x)`. `BUILD_EVIDENCE` combines it when a schematic is written.

## Risks / Trade-offs

- [KiCad derives a name this change did not probe] → the pad stays on no net with a warning; parity reports it as a warning, and c0063's netlist comparison catches every such pin.
- [The copper guard sees pads of unconnected pins as nets] → the guard reads the planned board; task 9.2 runs it on both examples before and after and records any new finding with its cause.
- [The IPC-D-356 export labels a net by the last 14 characters of its name, and many `unconnected-(…)` names share a tail] → c0020 already reports the pads of colliding labels as `net-label-ambiguous` coverage, never as differences; the (`model`, `board`) pair still judges them.
- [A v0.1 board stored a slash net raw] → the next build rewrites the name; its tracks follow because nets are matched by model name; `result.preserved` counts them.
- [A symbol's pins lie off the 1.27 mm grid] → ERC warns; the issue names the symbol, and the library is the place to fix it.
- [Label texts overlap in a dense cell] → cosmetic; the room per character is a constant in one place.
- [c0058 landed on 2026-10-04 and writes `lib/<nickname>.kicad_sym` and `sym-lib-table` for the symbols a design authors] → its authored symbols are `SymbolDef`s like any other and enter Decision 8. The table and the library files are written once, by this change's step, which keeps every authored symbol of an authored nickname and gives each the node of `sym.write_symbol_library`, so a build with the schematic skipped writes what c0058 writes. c0058 added one requirement to `design-dsl` and changed none that this change modifies (checked on 2026-10-05). Its writer puts the version `20231120` into a target-9 library, where `FORMAT_VERSIONS[FileKind.SYMBOL_LIB][9]` is `20241209`; task 3.3 takes the header from the table in both writers, which changes that one line of an authored target-9 library and is said in the changelog.
- [The `kicad-9` image reports different ERC types] → the probes compare outcomes, not messages; the two label warnings already differ by major.

## Migration Plan

- `build` writes more files by default. A project built with v0.1 gets a schematic on its next build; `--schematic skip` keeps the old output.
- Pad nets of unconnected pins and the stored form of slash nets change the board text of every rebuilt project once; layouts are kept.
- The four MODIFIED requirements of `design-dsl` are written against the living text of 2026-10-04 (after c0056). If c0058 or another change modifies one of them first, task 1.1 re-bases the delta on the new text before any code is written.
- Rollback: `--schematic skip` as the default restores v0.1 output; the net spelling rule is independent and stays.

## Open Questions

- **A `sch-build` command that writes only the schematic.** Default: no (Decision 2).
- **The schematic's drawing sheet in the project file.** Default: not set; the living spec says `schematic.page_layout_descr_file` is not touched.
- **Adopting symbol positions from an edited schematic.** Default: no; v0.2b's `sync` may write `schematic-placements.toml`.
- **Maintainer:** will you run "Update PCB from Schematic" once on a built blink in KiCad 10.0.6 and report what changed on the board? Default: the stand-in alone, `H-K-SCH-UPDATE` stays `INFERRED`.
- **A power flag on a net that has a power output on a DNP part.** Default: the flag is written, because the DNP part does not drive the net.
