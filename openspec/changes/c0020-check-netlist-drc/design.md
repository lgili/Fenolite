1. **Probes first.** Task group 2 settles, on 9.0.9 and 10.0.6, the type names, the effect of project severities and the item uuids (`H-K-DRC-TYPES`, `H-K-PRO-SEV`, `H-K-DRC-UUID`) before `drc_json.py` is written; task 3.2 settles the export partition (`H-K-NET-IPC`) before `assignment_compare.py`. 2. **Two new oracle protocols.** `NetlistOracle` (`netlist(project, *, board) -> NetlistOutcome`) and `RoundTripOracle` (`rt2(project) -> Rt2Outcome`) are `@runtime_checkable` protocols in `backends.base`, beside c0013's `Oracle`, which is unchanged. `run_checks` keeps c0013's `oracle: Oracle | None` parameter and narrows it with `isinstance`; a stage whose oracle lacks the operation is skipped with `unsupported-oracle`. `KicadOracle` satisfies all three, which a typed function in `oracle.py` proves under pyright.
   - Rejected: adding `netlist` and `upgrade` to `Oracle`, as c0013's Open Questions suggested. It would MODIFY c0013's "Oracle protocol", and every drc-only fake of c0013 would stop satisfying it.
   - Rejected: an `upgrade` primitive with `checks` orchestrating the normalisation. Re-dump, re-save and staging are KiCad steps; `checks` only judges reports.

3. **The DRC stage judges violations: one MODIFIED delta.** `drc_stage(oracle, project, *, built, design=None)` maps every violation through `drc_json.finding_issues` whenever a report exists, and `violations_judged` becomes `true` then.
   - c0013's text cannot stay true: its scenarios assert exit 0 on the authored built project and on the native project, "four stages" and `violations_judged` `false` on the built blink, and the authored and blink boards are unrouted, so their `unconnected_items` now give error findings.

Two scenarios are added: "Findings mapped by the stage" and "No report, nothing judged". The rules verdict, copy skips and the no-report rule are kept word for word.
   - **Archive order.** `openspec validate --strict` accepts a MODIFIED delta of a requirement that only an active change ADDs (tested on 2026-10-02), but `openspec archive` fails unless the requirement already lives in `openspec/specs/verification-loop/spec.md`. c0013 therefore archives before this change, as the dependency already orders, and task 9.1 re-checks the living text before archive.

   - Rejected: warnings for KiCad errors to keep exit 0 before routing. The v0.1 loop checks after routing and fill; an unrouted board must not pass.

4. **Finding codes and severities.** `type_code(oracle, type)` gives `<oracle>.drc.<suffix>`: lower case; `_` and every other character outside `[a-z0-9-]` replaced by `-`; runs of `-` collapsed; leading and trailing `-` removed; `unknown` when empty. A suffix equal to c0013's `rules-not-loaded` or `rules-unchecked` becomes `type-<suffix>`. `summary.types` maps each emitted code to KiCad's raw type.
   - Severity: `excluded` → `info`; `error` → `error`; `warning` → `warning`; any other string → `error`, so a schema change fails loudly. Project severities reach the issue through the report (`H-K-PRO-SEV`).
   - `schematic_parity` entries are counted, not mapped: no parity check runs before v0.2a.
   - Rejected: one aggregate issue per type, which loses the location. Rejected: keeping KiCad's underscores, which `ISSUE_CODE` refuses. Rejected: dropping excluded violations, which hides the user's own decisions.

5. **Locations through native ids.** `item_locations(design, oracle)` indexes every entity of the board by `native_ids[oracle]`, so `checks` names no backend: KiCad's ids sit under `"kicad"`, which is `KicadOracle.name`.
   - A numbered pad gives `REF-PIN` (the component's `ref`, `-`, the pad number); a pad without number and a footprint give `REF`; tracks, arcs, vias, zones, keepouts, graphics and texts give their `provenance.locator`, the bare `kicad-sexpr` locator that `check.rt1-failed` also uses.
   - A uuid that names no entity, or several (pads repeat a uuid in 2 demo boards, `H-K-PCB-UUID`), and every item when the board read was refused, give `@<x>,<y>`: the report position in millimetres as an exact decimal (`12500000` nm gives `12.5`). A guess is never made, so a wrong `REF-PIN` cannot appear.
   - `where` joins the item locations in report order with `, `.
   - Rejected: KiCad's item description as location (prose, and not `REF-PIN`). Rejected: matching items by position first (several items share a position).

6. **Messages hold no temporary path.** A message is `<type>: <description>`. `report.source` is the board path as KiCad saw it, inside the runner's temporary folder, so its parent folder is replaced by `<tmp>` and the home directory by `~`, as c0009's runner does for stdout. c0013's determinism rule forbids temporary and absolute paths in the output.
   - Rejected: changing c0017's `KicadCli.drc` to rewrite reports (a living requirement). Rejected: dropping descriptions; they carry what the report gives about measured values (`H-K-DRC-MEASURED`).

7. **Assignment compare as partitions.** Sources: `board` (every numbered pad of the re-read board, labelled by `net_id`, `NO_NET` for none), `model` (built input: every `PinRef` of a net labelled by the net id, every other pin `NO_NET`) and `export` (`KicadOracle.netlist`). Elements are `REF-PIN` strings.
   - Pairs: (`model`, `board`) on built input, and (`board`, `export`) always. The board is the hub, so a reassigned pad is reported once. Native input has no independent model (c0009 synthesises its circuit from the board), so only (`board`, `export`) runs; built input with an unreadable `.fenolite/` does the same, after c0013's `check.cache-unreadable`.
   - Partition rule: over the elements both sides cover, two elements are together when they share a label; `NO_NET` is one class, as in c0009's verified comparison. An element with two labels on one side (pads of one number on two nets) is a difference.
   - `min_pins=1` keeps single-pin nets (818 in the demos); `min_pins=2` would drop them, counted as `below-min-pins`. The scope is global: elements span the whole board, with no per-sheet scope in v0.1.
   - Coverage: elements that only one side covers are `netlist.uncovered` infos per side and reason, never differences. A reason is the source's own (`not-exported`, `unmatched-record`, `net-label-ambiguous`), `below-min-pins`, or `not-in-<source>` for an element the other source does not name (`not-in-board`, `not-in-model`, `not-in-export`).
   - Rejected: comparing names (the export keeps 14 characters). Rejected: pads on no net as singletons, which departs from c0009's verified comparison and lets a single-pin net whose pad lost its net pass unseen. Rejected: three pairs, which report a reassigned pad twice.

8. **Locating the moved pad.** For each block of either side, when one block of the other side holds more of its elements than every other block, the elements outside that block are flagged; ties flag nothing. If the relations differ and nothing was flagged, every element of a block without an equal block on the other side is flagged, so `differences == ()` exactly when the partitions are equal.
   - Worked case: `R1-2` moved from `LED_A` {`R1-2`, `D1-2`} to `GND` {`D1-1`, `U1-9`}. From the model side, `LED_A` splits 1 to 1 (tie, nothing). From the board side, `GND` {`D1-1`, `U1-9`, `R1-2`} maps mostly to the model's `GND`, so `R1-2` is flagged, and only it.
   - Rejected: block-level reports without a pad. Rejected: flagging every member of a changed block (noise grows with net size).

    - Rejected for that run: a bench without custom rules, whose `clearance` violation would come from a net class. An `absent` there could also mean an unread project, which `rule_severities` lives in, so it proves no more. Rejected: a second canary of another type in the ignored run (a change of c0018's canary that the living rule fixes to `canary.kicad_dru`).
