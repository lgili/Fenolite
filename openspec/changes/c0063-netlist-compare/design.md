## Context

- **Scope.** Plan D10: "`fenolite netlist` on a KiCad project = wrapper of `kicad-cli sch export netlist` (`KICAD-VERIFIED`); an own extractor (`backends/kicad/sch_netlist.py`) only for schematics generated by Fenolite (restricted grammar, 100 % parity required)". Plan D9, stage 4: "with a schematic, (d) `kicad-cli sch export netlist --format kicadsexpr`" as a further source of the assignment compare. Plan v0.2a acceptance: "`sch_netlist` == `kicad-cli sch export netlist` on 100 % of the schematics generated by Fenolite (not of the demos)".
- **What exists.**
  - `checks.assignment_compare`: partitions of `REF-PIN` elements, the pairs (`model`, `board`) on built input and (`board`, `export`) on every input, the export being KiCad's IPC-D-356 (c0020). c0061 makes a pad on no net a block of its own.
  - `model_netlist` names an element by the symbol pin number of a net member, and `board_netlist` by pad number. For a component with a `pin_pad_map` (c0056) the two differ, so its mapped pins are only "uncovered" today.
  - c0060: `KicadCli.export_netlist`, `read_schematic`, a test helper that reads the components of an export. c0061: generated sheets (symbols, global labels on pin points, no-connect flags, power flags), `netnames.unconnected_name`, `schlayout.pin_point`.
- **Observed at proposal time** (2026-10-04) on the hand-made blink sheet, 9.0.9 and 10.0.6:
  - The export is one list `(export (version "E") …)` with the children `design`, `components`, `libparts`, `libraries` and `nets`; 10.0.6 adds `groups` and `variants`.
  - A `comp` holds `ref`, `value`, `footprint`, `description`, `fields`, `libsource`, `property` entries, `sheetpath` and `tstamps` (the symbol's uuid); 10.0.6 also lists `units`.
  - A `net` holds `code`, `name`, `class` and one `node` per pin with `ref`, `pin`, `pintype` and, for a named pin, `pinfunction`. `pinfunction` is the pin name on 9.0.9 and `<name>_<number>` on 10.0.6. The `pintype` of a pin under a no-connect flag ends with `+no_connect`.
  - Net names and node sets are equal on both majors (33 nets for the blink: 4 named, 29 `unconnected-(…)`). The power flags (`#FLG…`) are neither components nor nodes.
  - `design` holds the export date and the absolute path of the schematic, and `libraries` the absolute path of each library: with the runner's copy, paths under a temporary folder.
  - A schematic that does not load gives exit 3 and no file (10.0.6).
- **Constraints.** `checks` stays backend-free; `build` needs no KiCad; stdlib only.

## Goals / Non-Goals

**Goals:**
- KiCad's reading of the schematic as a source of `check`.
- A tool-free proof, at build time, that the generated sheet means the circuit.
- The plan's acceptance as a test: the own netlist equals KiCad's, names included, on every generated schematic of the test set, on both majors.
- A command that answers "what is connected to what" for a KiCad project.

**Non-Goals:**
- Everything under "Non-goals" in the proposal.
- Any reading of wires. A sheet with a wire is outside the grammar, and the own netlist refuses it.

## Decisions

1. **Probe first.** Task group 2 pins on both majors the shape of the export, the absence of `#` references, the `pintype` strings and the suffix under a flag, before the reader and the extractor are final.

2. **One netlist type for both readings.** `backends/kicad/netlist.py`: `KicadNetlist(components, nets)`, `NetComponent(ref, value, footprint, properties)`, `NetlistNet(name, netclass, nodes)`, `NetNode(ref, pin, pintype)`; components sorted by natural order of the reference, nets by name, nodes by reference then pin.
   - `read_netlist(text, *, file="") -> KicadNetlist` reads `components` and `nets` of an `(export …)` list with c0006's parser. It ignores `design`, `libparts`, `libraries`, `groups`, `variants`, `code`, `pinfunction`, `sheetpath`, `tstamps` and `units`: they carry dates, paths, numbering or per-major spelling.
   - `properties` holds the `fields` of a component by name.
   - A root other than `export`, or a missing `components` or `nets`, raises `FormatError`.
   - `differences(a, b, *, pintypes=True, netclasses=False) -> tuple[str, ...]` lists what differs, sorted: a component on one side only, a value or footprint that differs, a net on one side only, a node on one side only, a `pintype` that differs.

3. **Own netlist** (`sch_netlist.py`). `own_netlist(sheet, *, project) -> KicadNetlist` for a sheet inside the grammar of Decision 4:
   - every pin of every symbol instance whose reference does not start with `#` is a node at `schlayout.pin_point`, with the pin number of its embedded symbol;
   - the labels at that point give the net name, the label text as written (the stored form, `netnames`); every node under one name is one net, wherever it lies on the sheet;
   - a node without a label is a net of its own, named by `netnames.unconnected_name`, whether or not a no-connect flag marks it;
   - `pintype` is the pin's electrical type, with `+no_connect` under a flag;
   - components come from `sch.components` with their properties; `netclass` is empty.
   - Pins of `#` references are not nodes: a power flag contributes nothing to the netlist.
   - Rejected: reading the nets back from the circuit model. The point is to read the sheet as KiCad reads it.

4. **Grammar check.** `sch_netlist.grammar_issues(sheet) -> tuple[Issue, ...]` gives one `kicad.sch.netlist-unsupported` (error) per reason, and `own_netlist` raises `NetlistUnsupportedError` with them when any exists:

   | reason | when |
   |---|---|
   | `wire` | the sheet holds a `wire`, `junction`, `bus`, `bus_entry` or `bus_alias` (seen as opaque slots of the root) |
   | `label-kind` | a label that is not global |
   | `sheet` | a sheet reference, or a symbol with more than one use |
   | `label-off-pin` | a label at a point where no pin connects |
   | `two-names` | labels of different names on one point |
   | `shared-point` | pins of two units on one point |
   | `frame` | a symbol whose rotation and mirror are not in `schlayout.PROVED_FRAMES` |
   | `hidden-power` | a hidden pin of type `power_in`, or a symbol flagged `power` other than `fenolite:PWR_FLAG` |

   A generated sheet never gives one of them; a sheet edited in KiCad usually does. The check is what keeps the own netlist from claiming more than it reads.

5. **Build guard.** After `generate_schematic`, `build_design` computes `own_netlist(sheet)` and compares it with the circuit: each net of the circuit under its stored name with its members named by pad number, and each pin of `pad_nets` under its name. A difference, or a grammar issue, gives `build.schematic-netlist-differs` (error) naming the first net and pin, and the build returns no file.
   - The guard runs without any tool, on every build with a schematic.
   - It catches what c0061's layout checks cannot see as a whole: a label at the wrong pin after a pin-pad map, a variant embedded for the wrong component, two nets under one stored name.
   - Rejected: only a test. A generator defect would then reach users who do not have KiCad to run `check`.

6. **The `schematic` source in `check`.** `backends.base.SchematicNetlistOracle` (`@runtime_checkable`): `schematic_netlist(project) -> NetlistOutcome`, the `PadNetList` (source `schematic`) of KiCad's export of `<stem>.kicad_sch`, one `PadAssignment(f"{ref}-{pin}", <net name>)` per node. `KicadOracle` implements it with `KicadCli.export_netlist` and `read_netlist`.
   - Pairs of `netlist.assignment_compare`: built input compares (`model`, `board`), (`model`, `schematic`) and (`board`, `export`); native input compares (`schematic`, `board`) and (`board`, `export`). The model stays the hub on built input and the board on native input, so one wrong pad or pin is reported once.
   - The `schematic` pair is left out when the project set has no `<stem>.kicad_sch` or the oracle does not export schematic netlists. When the schematic is there and the export fails, the stage reports `check.oracle-failed` and compares the other pairs.
   - **Elements by pad number.** `model_netlist` names a net member by its pad: the pin number mapped through the component's `pin_pad_map`. Board, export and schematic already speak in pad numbers.

7. **`fenolite netlist PATH`** (`cli/cmd_netlist.py`, `mutates=False`, `example_tools=("kicad-cli",)`). Flags: `--source kicad|fenolite` (default `kicad`), `--min-pins N` (default 1), `--kicad-cli`, `--timeout`.
   - `PATH` is a project folder, a `.kicad_pro`, a `.kicad_pcb` or a `.kicad_sch`; the schematic is the `.kicad_sch` itself, or `<stem>.kicad_sch` of the resolved board. No schematic exits 3 (`FEN-3001`).
   - `kicad`: `sch export netlist` on the copy set; exit 6 without the tool; a schematic the tool cannot load exits 3 with the tool's line.
   - `fenolite`: `own_netlist` of the root sheet, no tool; a sheet outside the grammar exits 7 (`FEN-7001`) with the grammar issues.
   - `result`: `schematic`, `source`, `components` (`ref`, `value`, `footprint`, `properties`), `nets` (`name`, `class`, `unconnected`, `pins` as `{ref, pin, type}`) and `counts` (`components`, `nets`, `pins`, `unconnected`). `unconnected` marks a single-pin net that KiCad named `unconnected-(…)`. `--min-pins` leaves out smaller nets and counts them in `counts.below_min_pins`.
   - No date, no temporary path, no absolute path; two runs give equal output apart from `elapsed_ms`.
   - Rejected: writing KiCad's netlist file. It holds the paths of the runner's temporary copy; an agent that needs KiCad's file runs `kicad-cli` itself.

8. **Acceptance test.** `tests/kicad/schematic/test_own_netlist.py`, on both majors: for the blink, c0061's units design, every KiCad example under `examples/`, and 25 designs that `tests/_gendesigns.py` generates from a fixed seed over the Mini library (one to twelve parts, units, pin-pad maps, marks, power interfaces, slash names), each built for the running major, `differences(own_netlist(sheet), read_netlist(<export>))` is empty.
   - If `pintype` strings differ on a major (probe `netlist-pintype`), that major compares with `pintypes=False`, and the row says so.

9. **Evidence.** `netlist.EVIDENCE` and `sch_netlist.EVIDENCE` start `INFERRED`. The first is raised with `H-K-NETLIST-SHAPE`, the second with `H-K-NETLIST-OWN`, on both majors.

## Risks / Trade-offs

- [The own netlist agrees with KiCad only because both come from one generator] → it reads the written sheet, not the circuit; the acceptance set holds designs with units, maps, marks and slash names, and the guard compares against the circuit, a third source.
- [A sheet edited in KiCad] → outside the grammar: `netlist --source fenolite` refuses it and `check` uses KiCad's export only.
- [The export of a large hierarchy is slow] → one run per check, under the command's timeout.
- [One pin reported in two pairs] → the hub rule of Decision 6; unit tests pin one report per defect.
- [A pin name outside the proved characters] → the own netlist uses the same function as KiCad's name by rule, and the acceptance test compares names; a difference shrinks `PROVED_PIN_CHARS` (c0061).

## Migration Plan

- Additive, except the element naming of `model_netlist`: a built project with a `pin_pad_map` gets real comparisons for its mapped pins instead of coverage infos.
- The MODIFIED "Assignment compare stage" is written against c0061's text (a pad on no net is a block of its own). Archive order: c0061, then this change.
- Rollback: remove the command, the guard and the `schematic` source; the reader and the own netlist can stay unused.

## Open Questions

- **Should `fenolite netlist` also write a file?** Default: no; c0065's manifest may list a JSON netlist if a user asks.
- **Net classes in the comparison.** Default: not compared; the own netlist does not read the project file.
- **Should the guard be skippable (`--no-netlist-guard`)?** Default: no. It costs milliseconds and refuses only a sheet that contradicts the circuit.

## Implementation notes (2026-10-05)

What the working tree held when the implementation started, and what was changed in this change's text
because of it.

- **c0061 is implemented and not archived.** The living "Assignment compare stage" is still the text
  before c0061. The MODIFIED delta of this change is therefore c0061's delta text with exact
  replacements (the sentence about the schematic source, the pairs, the label of a `schematic` net in a
  message, and five scenarios). Archive order: c0061 first, then this change; in the other order
  c0061's delta would remove the schematic source again. c0061 was archived on 2026-10-06, before the
  last rebase of this change: the delta was generated again from the living text and came out the
  same, so the ordering question is closed.
- **Pad numbers in `model_netlist` are c0061's.** c0061 already names a model element by its pad, with
  the scenario "Mapped pins are named by their pads". This change keeps that sentence and scenario as
  they are and adds no second scenario for it; the work "pad numbers in `model_netlist`" of the budget
  was not needed.
- **The copy set holds no schematic.** `projectset.project_set` never lists `.kicad_sch` (living
  "Check project copy set"), and c0062, a sibling change, is the one that adds the schematic files to
  it. So the stage cannot ask `project.files` alone. It asks whether the project has a schematic:
  `<board stem>.kicad_sch` is one of `project.files`, or a file beside the board under `project.root`.
  `KicadOracle.schematic_netlist` copies the project's files and, when the set does not hold them, the
  root schematic and the sheet files that `sch.sheet_files` lists inside the root. Once c0062 is merged
  the files come from the set and this addition does nothing. `projectset.py` is not touched here.
- **`KicadCli.export_netlist` returns the run**, not a text: the netlist is `run.outputs[NETLIST]`.
  `tests/_fakecli.py` already takes a `netlist` argument (c0060), and `tests/_erc.py::netlist` reads
  the nets of an export for tests (c0061).
- **(`schematic`, `board`) when the model is missing.** Built input whose `.fenolite/` model could not be
  loaded has no model to be the hub, so the schematic is compared with the board there, as on native
  input.
- **Scenario "Schematic export fails"** was added: the requirement asks for `check.oracle-failed` and
  the other pairs, and no scenario pinned it.
- **The grammar issue is not a code of the reader.** The living "Schematic read issue codes" pins
  `sch.ISSUE_CODES` as a closed set, and `read_schematic` never gives `kicad.sch.netlist-unsupported`.
  The code lives in `sch_netlist.ISSUE_CODES` instead of joining `sch.ISSUE_CODES`.
- **A ninth reason, `undefined-symbol`.** The table had no reason for an instance whose definition the
  sheet does not embed (the reader only warns, `kicad.sch.symbol-undefined`), and the pins of such an
  instance are not known. It is refused under its own reason. `label-off-pin` is not reported beside
  it, since the labels of the unknown pins would all be named.
- **`shared-point` also covers stacked pins without a label.** Several pins of one instance at one
  point are one net for KiCad. With a label at that point they are the net of the label, which the own
  netlist reads; without one KiCad names the net after one of the pins, by a rule that was not
  measured, so the sheet is refused.
- **`frame` cannot occur today.** `schlayout.PROVED_FRAMES` holds the twelve pairs the model allows; the
  reason stays for the day a pair leaves that set, and its test shrinks the set.
- **The guard compares what the sheet draws.** The design a rebuild hands to the generator can hold
  footprints kept from the board, which have no part and get no symbol, and their pads are members of
  nets. The guard therefore compares the members whose component has a symbol (`generated.paths`),
  and takes the list of the other pins from the sheet: each must be alone on its net. Two tests of
  c0019 (`test_net_alias.py`, `test_preserve_readback.py`) fail without this.
- **Two nets under one stored name** (`a/b` and `a{slash}b`) are a difference of their own in the
  guard: element by element the sheet agrees with each, and KiCad reads them as one net.
- **`fenolite netlist` on a schematic alone.** A `.kicad_sch` without a board has no copy set, so the
  run gets the schematic, the sheets it names (`oracle.with_sheets`) and the project file of its stem.
  The pre-flight without a board is `_kicadtool.supported_tool`, which `preflight` now calls first.
- **A timeout of `fenolite netlist`** exits 6 with `FEN-6001` and `retryable: true`: the tool is there
  and did not answer, and no other registered code says that.
- **Example fakes.** A fake `kicad-cli` refuses a schematic unless it is given a netlist (c0060's
  tests rely on that), so the two example suites pass `EXAMPLE_NETLIST`, the authored 10.0 export.
- **Fields of a component.** KiCad lists `Footprint`, `Datasheet`, `Description` and the user fields
  under `fields`, each as `(field (name "N") "text")` with no text atom for an empty field. `Reference`
  and `Value` are not fields there, so `own_netlist` leaves them out of `properties` too.

### What the own netlist does not measure

- **A pin common to several units** (unit 0) is listed once, with the unit of its first instance on the
  sheet in the name of its unconnected net, as `schgen` names the pad. The mini library has no such
  pin, so the acceptance set does not hold one.
- **A symbol with `(on_board no)` that is not a power flag** is listed as a component by
  `sch.components`, and KiCad lists none for it. `build` never writes one; a sheet edited to hold one
  and nothing else outside the grammar would differ from KiCad's export by that component.
- **Pin types of a pin with an alternate function chosen on the instance** are those of the definition.

The acceptance holds for what `build` writes, which is what `H-K-NETLIST-OWN` states.

### Results (2026-10-05)

No probe outcome differs from "Context". No difference was found by the acceptance test on either
major, pin types included, so no fallback of Decision 8 was applied and nothing was cut from the cut
order. The 9.0.9 image runs Python 3.11, which refused an unhashable dataclass default that Python 3.13
accepts; `NetComponent.properties` takes its empty mapping from a factory.
