## Context

- **What exists** on `dev` at `5191911` (0.6.0 prepared), with the page moved to modules by c0272
  (`viewer-build`, which this change follows):
  - The page's sources are TypeScript modules in `viewer/src/` (`core/`, `board/`, `measure/`, `three/`,
    `sch/`, `panels/`, `dialogs/`, `table/`, `library/`, `export/`), linked by `viewer/build.mjs` in the order
    `viewer/src/main.ts` imports them; the markup shell is `viewer/src/page.html` and the stylesheet
    `viewer/src/styles/` (`index.css` imports ten files in cascade order; `base.css` holds the seven colour
    variables of `:root`). The build writes `src/fenolite/view/static/` (`page.html`, `viewer.js`,
    `viewer.css`, `manifest.json`), committed; `fenolite.view.export.template()` inlines the bundles into
    the shell, `page()` embeds a tree and its scenes, `server.py` serves it for `--serve`.
  - Preact (bundled, global `preact`) renders the Changes, Messages, Findings and Navigator panels
    (`viewer/src/panels/*.tsx`); the tree (`panels/tree.ts`), the review panels (`panels/review.ts`), the
    marks (`panels/marks.ts`), the project review (`panels/project-review.ts`) and the catalog dialog
    (`dialogs/catalog-selection.ts`) build their DOM by hand.
  - The toolbar `#top` holds, in one row: `bSidebar`, `fname`, `b3d`, `bFit`, `bFlip`, `bMeasure`, `bUnit`,
    `bEdge`, `bMark`, `bLink`, the select `printScale` (whose first option reads "Fit"), `bPrint`, `bSvg`,
    `variantSel`, `search`, `bClear` and the "Other side" range `opac`. The filter panel has its own
    `bQClear` ("Clear").
  - The side bar `#side` holds the tree, then `#panels` with plain `h3` headings: library, navigator,
    filter, Components, Nets, Changes, Messages, Marks, Findings (`.fg.zero` rows at half opacity) and
    Notes. `bProjectReview` is an underlined "Review" in the Projects heading.
  - The status bar `#status` holds `coord`, `zoomv`, `cur`, `gen` (written in three places as
    `SHA-256 <12 hex>`) and `live`.
  - One `keydown` listener on `window` (`viewer/src/core/input.ts`) runs the shortcuts and ignores events with
    Ctrl, Meta or Alt, in form controls, during composition or after `preventDefault` ("Context-aware viewer
    shortcuts", c0235). The toolbar's buttons are wired in `core/input.ts`, `core/units.ts`,
    `core/links.ts`, `export/svg.ts`, `measure/edge-tool.ts` and `panels/marks.ts`.
  - Tests: `tests/unit/view/test_page.py` (static checks of the template, Node runs of page functions as in
    `test_filter.py` and `test_scene_v1.py`), and `tests/visual` (Chromium of Playwright 1.63.0 through
    `tests/visual/harness.js`; eight screenshot references in `tests/visual/refs`, 0.1 % tolerance,
    regenerated by `tools/update_view_refs.py`), run by the `viewer` job of `.github/workflows/ci.yml`.
- **Constraints.** No runtime dependency, no CDN, no external URL (`test_template_is_self_contained`), the
  page works from `file://` as an exported page. Palettes and icons are Fenolite's own (clean-room). Ids that
  the visual tests read (`info`, `fname`, `search`, `status`, `tree`, `cv`, `gl`) stay. No framework beyond
  the Preact of c0272, for UI only; the canvas and WebGL renderers never go through it. A module's top-level
  names stay page globals (the visual tests read them), and every change of `viewer/` is committed with its
  rebuilt bundle (`make viewer`; `make viewer-check` in the `viewer` job).

## Goals / Non-goals

- **Goals:** a shell that reads as a professional tool at 1440 × 900 and still works at 390 px; every
  command reachable from the keyboard; no duplicate or ambiguous control; developer detail out of sight but
  one click away.
- **Non-goals:** the proposal's. The drawing code (`draw`, `paintCache`, the 3D renderer) is not touched.

## Decisions

### 0. Where each part goes (the module structure of c0272)

| part | module | form |
|---|---|---|
| tokens and themes | `viewer/src/styles/tokens.css` (imported first by `index.css`), theme choice in `core/theme.ts` | CSS, TS |
| command registry | `viewer/src/core/commands.ts` (`COMMANDS`, `runCommand`, `commandForKey`); `core/input.ts` looks shortcuts up in it | TS |
| toolbar, menus, tooltip | `viewer/src/panels/toolbar.tsx`, `ui/menu.tsx`, `ui/tooltip.tsx`, icons as Preact components in `ui/icons.tsx` | Preact |
| command palette | `viewer/src/dialogs/palette.tsx`; the pure matcher in `core/palette-match.ts` between `// ---- palette (c0268)` and `// ---- end palette`, run under Node by the unit test as `test_filter.py` runs the query functions | Preact, TS |
| side bar sections | `viewer/src/ui/section.tsx` (disclosure with count); the tree, review lists, marks and library list become Preact components in their `panels/` modules | Preact |
| status bar, About | `viewer/src/panels/status-bar.tsx`, `dialogs/about.tsx` | Preact |
| loading, empty, error | `viewer/src/ui/states.tsx`; the reading card stays in `core/documents.ts` | Preact |

Hand-written DOM converted to Preact keeps the ids, classes and the `.onclick()` the visual tests rely on, or
the change updates those tests with it (the Marks rows: `test_navigation.py` calls `.onclick()` of a row).
Each task's proof includes `uv run python tools/build_viewer.py --check`.

### 1. Tokens in `:root`, a light theme by attribute

All colours, spacing, radii and type sizes of the chrome become custom properties: `--space-1..6` (4, 8, 12,
16, 24, 32 px), `--text-xs..lg` (11, 12, 13, 15, 17 px), `--radius-s/m` (4, 6 px), `--surface-0..3`,
`--text-1..3`, `--border`, `--accent`, `--accent-text`, `--focus`, `--ok`, `--warn`, `--err`, `--info`.
Hard-coded colours in the chrome rules (`#2e323b`, `#1f4e7a`, `#cfd3da`, `#ffffff0d` and the like) are
replaced by tokens. `html[data-theme="light"]` redefines the surface and text tokens; without the attribute,
`@media (prefers-color-scheme: light)` applies the light values. The user's choice is kept in
`localStorage` under `fenolite.view.theme` (`system`, `dark`, `light`), read in `try` as the highlight mode
is. The canvas background and every layer colour stay those of the scene's theme (`S.theme`), so a KiCad
board stays navy in the light shell. Values are chosen for Fenolite; each text token pair meets a contrast
of 4.5:1 on its surface, which a unit test computes from the parsed tokens.

### 2. One command registry

`export const COMMANDS = [{id, title, group, icon, keys, when, run, pressed}]` in `core/commands.ts` declares
every action of the shell once: `when()` says whether it applies to the current scene kind (board, sheet, library, table, 3D),
`pressed()` gives a toggle's state. The toolbar is built from it (buttons with `aria-label`,
`aria-keyshortcuts`, `aria-pressed`), the palette lists it, the shortcut sheet prints it, and the existing
`keydown` listener looks shortcuts up in it instead of its chain of `if`s, with the same context rule.
Later changes (c0269 to c0271) add their commands to the registry.

### 3. Toolbar layout

`#top` becomes: side bar toggle, document title with an "About this document" button, then three groups
separated by a divider: **View** (2D/3D segmented control `D`, Fit `F`, Top/Bottom `B` with the other-side
opacity in its popover), **Tools** (Measure `M` with a menu for Point and Edge gap `Shift+M`, Mark `N`,
mm/mil `Q`), **Share** (Copy link, Export menu: Save SVG, Print with Fit, 1:1, 2:1, 5:1, 10:1). At the right:
the variant selector when the project has variants, and the search field, which shows "Search or run…
Ctrl K" and opens the palette. `bClear` and the print-scale select leave the toolbar; the filter's clear
becomes an icon button inside the filter field labelled "Clear filter". "Edge" reads "Edge gap" and "Link"
reads "Copy link". Icons are inline `<svg>` elements rendered by Preact components (`ui/icons.tsx`), 16 px strokes in
`currentColor`, drawn for Fenolite. Tooltips are one positioned element showing the title and the shortcut in `<kbd>`, opened on
hover and on keyboard focus after 400 ms. At 760 px and below the groups collapse to icons and the Share
group to an overflow menu; the existing narrow layout requirement is kept.

### 4. Command palette

A `<dialog id="palette">` with a text field and a `role="listbox"` result list. Sources: commands of the
registry whose `when()` holds, parts (`S.comps`: reference, value, footprint), nets (`S.nets`), documents of
the tree, and on sheets the sheet's parts and nets. Matching is case-insensitive subsequence matching with
a score (prefix and word starts first), at most 50 results grouped by source. `Enter` runs or jumps (the
existing `selectCompAt`, `selectNetAt`, document open with its navigation guard), arrows move, `Esc` closes
and returns focus. A leading `>` limits to commands, `@` to parts, `#` to nets. The matcher is one pure
function, `paletteMatch(query, items)`, run under Node by a unit test.

### 5. Side bar sections

Every panel heading becomes `<details class="sect"><summary>Title <span class="count">n</span></summary>`;
open states are kept in `localStorage` (`fenolite.view.sections`). Components sort by reference (natural
order: R2 before R10), value or footprint; Nets by name, pads or routed length; the sort is a small control
in the summary. In Findings, groups with a count of 0 are listed under one line "n groups with no findings",
collapsed: each zero stays a result, as "Review findings" requires, one click away. The project review
entry is a button at the head of the side bar that shows its state counts (for example "1 failed · 7 not
run").

### 6. Status bar and "About this document"

`#status` shows, left to right: cursor position in the page unit, grid pitch when a grid is drawn, unit,
zoom, current layer, selection (part, net or count of filtered items) and live state ("Live · updated
12:03", "Building…", the read error). `gen` is removed. The "About this document" popover lists the file
name and path, size (from the tree's `size`), SHA-256 in full with a copy button, backend, evidence level of
the read, scene version (live) and the counts of notes; nothing in it is new data, so the scene does not
change.

### 7. Loading, empty and error states

Loading keeps the reading card of "Current browser navigation owns the view" and adds an indeterminate
progress bar under the toolbar. A list with nothing to show says why ("No components on this board", "No
nets match 'x'"). A failed read shows its error with a Retry button that asks for the scene again under the
current navigation generation. A project with no viewable document shows a card that says so and lists the
document kinds that can be opened.

### 8. Tests

- `tests/unit/view/test_page.py` (on the assembled `template()`): tokens declared for both themes; no colour literal left in chrome rules
  outside the token block (an allow-list of drawing constants); every registry command has a title, an icon
  that exists in the sprite and a unique shortcut; no two toolbar controls share a label; contrast of each
  text/surface pair at least 4.5:1; `paletteMatch` under Node.
- `tests/visual/test_shell.py` (new): toolbar groups and labels at 1440 × 900; palette opens with `Ctrl+K`
  in a text field and with `Cmd+K`, jumps to a part and to a net, runs Fit; `?` opens the shortcut sheet;
  sections collapse and keep their state across a reload; zero groups fold; theme switch persists; About
  popover copies the hash; the existing narrow-window tests still pass.
- Screenshot references: the eight existing references are regenerated with `tools/update_view_refs.py`
  in the `viewer` job's environment (Linux, the pinned Chromium, `tests/visual/fonts.conf`); a new
  reference `kicad_board_light.png` covers the light shell.

## Risks / Trade-offs

- **Every screenshot reference changes.** The chrome is part of each screenshot, so the eight references
  are regenerated in one task and reviewed as images by the maintainer; a local macOS run differs by fonts
  (as recorded in c0239) and is not the reference.
- **Page size.** Tokens, the icons and the palette add an estimated 15 to 25 KB to `viewer.js` and
  `viewer.css` (Preact itself is already in the bundle, about 11 KB); the export is gzip-friendly and the scene, not the page, dominates large exports.
- **Ctrl+K in browsers.** Some browsers bind `Ctrl+K` to their search bar; the page takes it only while it
  has focus, and the search field remains a mouse entry to the palette.

## Open Questions

- Should the light theme be the default when the system asks for it (as designed), or should dark stay the
  default with light opt-in?
- Is `?` acceptable for the shortcut sheet, given that it is `Shift+/` on most layouts?
- Should the side bar get a resize handle now, or stay 260 px (the narrow-window requirement fixes 260 px
  at 1100 px)?

Decided on 2026-10-29, as recommended: the interface follows the system's light or dark preference until the
user chooses a theme; `?` opens the shortcut sheet (`Shift+/` where the layout needs it, matched on the key,
not the code); the side bar stays 260 px, without a resize handle.
